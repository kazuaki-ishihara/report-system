この順に進めてください。各手順の □ に印を付けながら進め、終わったら「8. 開発担当への連絡」の内容を返してください。

0. 【至急】今すぐ行うこと
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
いま、次の URL から DB ファイルがだれでもダウンロードできます（2026-11-15 に確認）。
  https://toyama-mai.sakura.ne.jp/report-system/data/reports.sqlite

□ ~/www/report-system/data/reports.sqlite を自分の PC にダウンロードして保管する
   （旧システム「レポート管理システム」のデータです。新システムへ移す場合に使うので、消す前に必ず控えを取る）
□ サーバーの ~/www/report-system/data/ を消す
□ ブラウザーで上の URL を開き、「Not Found」になることを確かめる


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 事前の確認
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
初期設定（手順 4）は、サーバーでコマンドを実行しないとできません（画面からはできません）。

□ サーバーにコマンドを打てるか確かめる
   - さくらのコントロールパネルの「SSH」、または Windows の「ターミナル」で ssh <アカウント名>@<アカウント名>.sakura.ne.jp
   - つながったら、 php -v と打って、PHP の版（7.4 以上）が表示されることを確かめる
□ コマンドが打てない場合は、ここで止めて開発担当に連絡する（別の方法を用意します）

□ ファイルを上げる道具で「.」で始まるファイル（.htaccess）が見えるようにする
   - FileZilla の場合: メニュー「サーバー」→「隠しファイルを強制表示」
   - コントロールパネルのファイルマネージャーの場合: 隠しファイルを表示する設定を有効にする


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 古いものを片付ける
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
今の本番には、開発用のアカウント・開発用の暗号の鍵、旧システム、設計書や開発の道具が混ざっています。
いったん空にして、作り直します（今の本番のデータはテストデータだけなので、消して問題ありません）。

□ 手順 0 の控え（旧システムの DB）を取ってあることを確かめる
□ ~/www/report-system/ の中身をすべて消す（.htaccess などの隠しファイルも含む）
□ ~/www/report-system/ が空であることを確かめる


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 新しいものを上げる
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
開発担当から「反映用の一式」を受け取ります（フォルダー名: <日時>_<コミット>）。中身は次の 3 つです。
  report-system/       ← これを上げる
  report-system.zip    ← 上と同じもの（サーバーで zip を展開できるときに使う）
  反映手順.txt         ← 上げない

□ report-system フォルダーの「中身」を、サーバーの ~/www/report-system/ に上げる
   （~/www/report-system/report-system/ にならないよう注意。~/www/report-system/login.php になれば正しい）
□ 次の 2 つのファイルがサーバーにあることを、必ず目で確かめる
     ~/www/report-system/.htaccess
     ~/www/report-system/app/.htaccess
   ※ この 2 つが無いと、設定や DB が Web から見えてしまいます
□ 一式に無いもの（docs、tools、public、data、config.local.php など）を上げていないことを確かめる


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 初期設定（サーバーでコマンドを実行）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SSH でつないで、次を 1 行ずつ実行します。

  cd ~/www/report-system

□ DB と暗号化の鍵を作る
    php app/bin/migrate.php
   → 「暗号化の鍵: …/app/keys/field_v1.key」と表示されれば成功

□ 報告の共通の項目を登録する
    php app/bin/seed_template.php

□ 最初の管理者（課長ご自身）を作る
    php app/bin/create_user.php --login=<ログインID> --name=<表示名> --admin
   - ログイン ID は英小文字・数字・. _ - の 3〜32 文字（メールアドレスは使えません）
   → 仮のパスワードが 1 回だけ表示されるので、その場で控える

□ DB と鍵を本人だけが読めるようにする
    chmod 700 app/data app/keys
    chmod 600 app/data/reports.sqlite app/keys/field_v1.key

□ 暗号化の鍵の控えを取る
   app/keys/field_v1.key を自分の PC にダウンロードし、サーバーとは別の安全な場所に保管する
   ※ この鍵をなくすと「限定」の項目が読めなくなります。DB と同じ場所には置かないでください。

【やってはいけないこと】
  - 開発用の DB・鍵をサーバーに持ち込む
  - tools/test/dev_seed.php を実行する、開発用のアカウント（admin01、kacho_a など）を使う
  - app/config/config.local.php を置く

5. 最初のログインと利用者の登録
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ https://toyama-mai.sakura.ne.jp/report-system/login.php を開き、手順 4 のログイン ID と仮のパスワードでログインする
□ 画面の案内に従って、2 段階認証を設定する
   （スマートフォンで開いて「認証アプリに登録する」を押す。PC で開いているときは、
     認証アプリで「セットアップキーを入力」を選び、画面に出た文字を入れる。表示された 6 桁の数字を画面に入れる）
□ 表示された予備のコード（8 個）を紙に書いて保管する（この画面を離れると二度と表示されません）
□ パスワードを自分のものに変える
□ 管理の「組織・ユーザー」で、課と利用者を登録する
   （各利用者には仮のパスワードを伝え、初回ログインで本人に 2 段階認証を設定してもらう）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. 定期実行（cron）の登録
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
さくらのコントロールパネルの「CRON 設定」で、次の 2 つを登録します。
（<アカウント名> はさくらのアカウント名。php の場所はコントロールパネルの説明に合わせる）

□ DB のバックアップ（毎日。例: 3:00）
    cd /home/<アカウント名>/www/report-system && php app/bin/backup.php
□ 組織の改訂の予約の反映（毎日。日付が変わったあと。例: 0:10）
    cd /home/<アカウント名>/www/report-system && php app/bin/run_schedules.php

□ 翌日、管理のトップの「最後のバックアップ」に日時が出ていることを確かめる

7. 旧システムのデータを移す場合（必要なときだけ）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
旧システム（手順 0 で控えた DB）の利用者・報告・コメントを新システムへ移す道具があります。
移すかどうか、いつ移すかは、開発担当と相談してから行ってください（手順はそのときに別途用意します）。

8. 開発担当への連絡
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
終わったら、次を開発担当に伝えてください。開発担当が外から確認します（画面を見るだけで、データは変えません）。

  - 手順 0〜6 のうち、終わったもの・できなかったもの
