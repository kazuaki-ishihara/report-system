# 組織の改訂の手順

| 項目 | 内容 |
|---|---|
| いつ | 毎年の組織改訂のとき。年の途中で役職者が退職・異動したとき |
| だれが | 管理者（システムの管理担当。システム 2 部システム 2 課） |
| 画面 | 組織・ユーザー（G-14）。作りは `docs/detailed_design/G14_org_users.md` §6.6 |

## 1. 考え方

- 報告は、**作ったときの課**に結び付く。人が課を移っても、課を作り直しても、過去の報告の課は変わらない。
- 新しい課の確認者・課長が、改訂の前の課の過去の報告（前月との比べ・検索を含む）を見る必要があるときは、新しい課に「**引き継ぐ課**」を設定する。
- 課の名前を変えるだけなら、課を作り直さずに名前を変える（課の ID が同じなので、引き継ぎの設定はいらない）。
- 管理者でも、確認者でない課の報告の中身は見られない（基本設計書 §8）。改訂の作業で報告の中身を開く必要はない。

## 2. 毎年の改訂

改訂の効力が始まる月の報告を作り始める前（月の初め）に行う。作り始めた報告は、作ったときの課のまま。報告は人について回るので、課・班を移った人の過去の報告は、今の課・班の確認者も見られる。

1. **新しい課を作る**（課の名前には部を含める。例: 「1部 システム1課」）。名前を変えるだけの課は、作らずに名前を変える。新しい課の**課長**を「課長」の節で決める（管理の仕方・締め日・課代・リーダー・班は、その課の課長が「課の管理」（G-23）で決める）。
2. **新しい人を登録する**（「ユーザーを追加」。仮のパスワードを本人に渡す）。
3. **人の所属・班・役割をまとめて入れる**（タブ「一括（CSV）」。G-14 §6.8）。
   1. 「今の組織を CSV に出力」する。
   2. 変わる人の行だけを直す（所属の課・班・役割・担当の班・項目管理者・有効）。動かない人はそのまま。辞めた人は「有効」を 0 にする。
   3. 取り込んで、変わる内容を確かめ、「すぐに反映する」を押す。誤りがあれば直して取り込み直す。
   4. **事前に予告がある改訂**は、「予約して反映する日」を選んで「この日に反映するよう予約する」（G-14 §6.10）。その日の最初の画面の表示（または定期の処理 `php app/bin/run_schedules.php`）で、その時点の組織に対してもう一度確かめてから反映する。誤りがあれば反映せず、管理のトップに「反映できなかった予約」と出るので、取り込み直す。予約は一括（CSV）のタブで取り消せる。
   - 1 人だけ変えるときは、画面でもよい（所属の課はユーザーの編集。課代・リーダー・班は、その課の課長が「課の管理」で決める）。
4. **課長がいない課を確かめる**（課の一覧と、管理者のホームに出る）。
5. **引き継ぐ課を設定する**（新しい課の編集の「引き継ぐ課（組織の改訂の前の課）」）。
   - まとめたとき: 新しい課で、まとめた前の課をすべて選ぶ。
   - 分けたとき: 分けた先のそれぞれの課で、前の課を選ぶ（どちらの課の確認者も、前の課の全員の過去の報告を見られる点に注意）。
6. **管理担当の課を確かめる**（システム 2 部システム 2 課の編集で「この課をシステムの管理担当にする」。この課の課長が画面の文言を変えられる）。
7. **課別項目・課ごとの選択肢・コメントの定型文**を、必要なら新しい課で作り直す（課の項目は課ごとなので、新しい課には引き継がれない）。
8. **前の課を無効にする**（所属する人がいなくなってから）。報告は残り、引き継いだ課の確認者が見られる。
9. **確かめる**: 課の一覧で、課長がいない課・引き継ぎを確かめる。新しい課の課長に、前の課の報告が開けるかを見てもらう。

## 3. 年の途中で役職者が辞めたとき

1. 辞めた人を**無効にする**（ユーザーの編集で「有効」を外す）。確認者・課長・項目管理者の役割は自動で外れ、外した役割が画面に出る。チェック・コメントの記録は残る。
2. 課長が辞めたときは、課の一覧に「課長がいません（確認を完了にできません）」と出るので、**新しい課長**を設定する。
3. 回答待ちのまま残ったコメントは、新しい課長が「解決」にできる。

## 4. 役を降りるだけのとき（辞めない）

課長は、管理者が課の編集の「課長」の節で外す（新しい課長を選ぶ）。課代・リーダー・項目管理者は、その課の課長が「課の管理」（G-23）の「確認者と課員」で外す（利用者は有効のまま）。
