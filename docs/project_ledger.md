# 案件台帳（客先名・案件名と案件コードの対応）

| 項目 | 内容 |
|---|---|
| 道具 | `tools/lib/project_ledger.py`（Python 3.8 以上の標準ライブラリだけ。Windows・Ubuntu で動く） |
| 使う人 | 案件を管理する人（管理者） |
| 台帳の置き場所 | 手元の PC の、リポジトリの外（例: `~/report-ledger/project_ledger.sqlite`）。システム（サーバー）には置かない |
| 検証 | `tools/test/smoke_project_ledger.py`（自動検証に組み込み） |

## 1. 目的

月次報告システムは、客先名・案件名を持たない（漏れたときに客先が分からないように）。報告には案件コード（P-0001 …）と社内向けの呼び名だけを使う。

コードと実際の客先・案件の対応は、システムの外で管理する必要がある。表計算などで人が手で管理すると、次のような食い違いが起きる。

- システムで作った案件が、台帳に書かれていない。
- 台帳では終わった案件が、システムでは有効のまま（報告で選べてしまう）。
- 同じ案件に、別のコードを 2 つ作ってしまう。
- システムの呼び名に、うっかり客先名を書いてしまう。

この道具で台帳を管理し、システムから出力した案件の一覧と突き合わせて、食い違いを見つける。台帳の変更はこの道具のコマンドからだけ行い、入力の形を確かめ、変更の履歴を残す。

## 2. 使い方

台帳の場所は毎回 `--ledger` で指定するか、環境変数 `PROJECT_LEDGER_PATH` に入れておく。

```bash
export PROJECT_LEDGER_PATH=~/report-ledger/project_ledger.sqlite   # Windows の PowerShell: $env:PROJECT_LEDGER_PATH = "…"
python3 tools/lib/project_ledger.py init                            # 最初の 1 回だけ。台帳を作る
```

月に 1 回（報告の締めのあとなど）:

1. システムの「案件の管理」（G-13）で「案件の一覧を CSV に出力」を押し、CSV を手元に保存する。
2. 取り込む。システムで新しく作られた案件は、台帳に足される。

   ```bash
   python3 tools/lib/project_ledger.py import-system projects_20261113-1000.csv
   ```

3. 足された案件に、客先名・案件名・期間を入れる。

   ```bash
   python3 tools/lib/project_ledger.py set P-0013 --customer "（客先名）" --project-name "在庫管理の改修" --start 2026-11-01
   ```

4. 食い違いを確かめる。出てきたものを直す（システム側は G-13 で、台帳側は `set`・`end` で）。

   ```bash
   python3 tools/lib/project_ledger.py check
   ```

5. 取り込んだ CSV は消す（台帳に写したので不要。社外秘）。

案件が終わったとき:

```bash
python3 tools/lib/project_ledger.py end P-0007 --end 2026-12-31
```

そのあと、システムの G-13 でも案件を終了にする（`check` で食い違いとして知らせる）。

## 3. コマンド

| コマンド | 内容 |
|---|---|
| `init` | 台帳を作る（あれば誤り） |
| `import-system <CSV>` | G-13 の案件の一覧を取り込む。システムの状態（呼び名・課・有効／終了・最後に使われた月）を写し、台帳にないコードは台帳に足す（客先名などは空） |
| `set <コード> [--customer …] [--project-name …] [--start YYYY-MM-DD] [--end YYYY-MM-DD] [--note …]` | 台帳の情報を変える。台帳にないコードは `--create` を付けたときだけ作る |
| `end <コード> --end YYYY-MM-DD` | 終了日を入れる |
| `list` | 台帳の一覧（システムの状態・呼び名と並べる） |
| `check` | 食い違いの一覧。あれば終了コード 1（ほかの道具から使える） |
| `history <コード>` | 変更の履歴（いつ・だれが・どの項目を・何から何へ） |
| `export-csv <ファイル>` | 台帳を CSV に書き出す（見るためだけ。直すときは `set`）。リポジトリの外にだけ書ける |

誤り（形の違う日付、開始日 > 終了日、台帳がない、リポジトリの中の置き場所など）は終了コード 2 で止め、何も変えない。

## 4. 見つける食い違い（`check`）

| 種類 | 内容 | 直し方 |
|---|---|---|
| 取り込み | まだ取り込んでいない／最後の取り込みが 31 日より前 | 新しい一覧を `import-system` |
| 台帳にない | システムにあるが台帳にない | `import-system` で足す |
| システムにない | 台帳にあるが、システムの一覧にない | コードの書き間違いなら台帳を直す |
| 台帳の入力漏れ | 客先名か案件名が空 | `set` |
| 終了の食い違い | 台帳では終了日を過ぎたがシステムでは有効／システムでは終了だが台帳に終了日がない | G-13 で終了にする／`end` |
| 使われていない | 開始日の月を過ぎたが、まだ報告で使われていない | 参画の状況を確かめる |
| 呼び名に客先の情報 | システムの呼び名に、台帳の客先名か案件名が入っている（全角・半角、大文字・小文字、空白の違いはならして比べる） | G-13 で呼び名を直す |
| 重複 | 同じ客先名・案件名に、複数のコードがある | 片方のコードを G-13 で終了にし、台帳に備考を書く |

## 5. 台帳の中身

SQLite のファイル 1 つ。POSIX（Ubuntu など）では、作るときに本人だけが読める権限（600）にする。

| テーブル | 内容 |
|---|---|
| `ledger_projects` | 案件コード、客先名、案件名、開始日、終了日、備考、作成・更新日時 |
| `system_projects` | 最後に取り込んだシステムの一覧（そのまま写したもの） |
| `ledger_history` | 変更の履歴（コード、項目、変更前、変更後、OS の利用者名、日時） |
| `ledger_state` | 最後に取り込んだ日時とファイル名 |

## 6. 守ること

- 台帳と、`export-csv` で書き出したファイルは社外秘（客先名を含む）。リポジトリ・システムのサーバー・共有の場所に置かない（道具も、リポジトリの中には作らない・書き出さない）。
- 台帳の控えは、暗号化した場所に取る。
- システムの呼び名には、客先が分かる言葉を入れない（`check` の「呼び名に客先の情報」で見つける）。
