# G-12 項目マスタ

| 項目 | 内容 |
|---|---|
| URL | `/admin/fields.php?dept=<課ID または common>`（GET: 一覧）、`/admin/field_edit.php?id=`（GET: 作成・編集、POST: 保存・並べ替え・有効/無効） |
| 利用者 | 管理者（共通項目・全課の課別項目）、課の管理者・課長（自分の課の課別項目） |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-04 |

---

## 1. 目的

報告の項目を、画面から追加・変更・並べ替え・無効化する。課ごとの補足情報を、課長が自分で設定できるようにする。

## 2. 表示の条件と権限

| 対象 | 管理者 | 課の管理者・課長 | それ以外 |
|---|---|---|---|
| 共通項目 | 編集できる | 見るだけ | 開けない |
| 自分の課の課別項目 | 編集できる | 編集できる | 開けない |
| 別の課の課別項目 | 編集できる | 開けない | 開けない |

機密区分を「限定」にする・外すのは、管理者だけ。

## 3. 画面の配置

**一覧**

```text
項目マスタ   対象 [A課の様式 ▼]（共通項目＋A課）  [ ＋ 項目を足す ] [ プレビュー ]
報告全体
  ≡ 前月からの変更    チェック  共通  通常           [編集]
  ≡ 問題・悩み事      複数行    A課   社外秘          [編集] [無効にする]
案件ブロック
  ≡ 案件              案件      共通  通常   必須     [編集]
  ≡ 担当内容          複数行    共通  社外秘 引継ぎ   [編集]
  ≡ 業務システムの種類 プルダウン A課  通常   引継ぎ   [編集] [無効にする]
  ...
無効の項目（3）▶
```

`≡` をつかんで並べ替える（JavaScript）。JavaScript が使えないときは、編集画面の「並び順」の数字で変える。

**編集**

```text
表示名      [業務システムの種類]
コード      [system_type]（作成後は変更できません）
適用        A課（変更できません）
区分        (○報告全体 ●案件ブロック)
入力部品    [プルダウン ▼]
選択肢      コード    表示名        並び  有効
            inventory 在庫管理       1    ☑
            sales     販売管理       2    ☑
            [＋ 選択肢を足す]
必須        ☐   前月から引き継ぐ ☑
機密区分    [通常 ▼]
説明文      [__________________]
入力例      [__________________]
表示の条件  [なし ▼]（例: 進捗 が 遅延あり のとき）
一覧に表示 ☑  検索の対象 ☐  出力する ☑
[ プレビュー ] [ 保存 ]
```

## 4. 表示項目

- 一覧は「共通項目＋選んだ課の課別項目」を、区分（報告全体・案件ブロック）ごとに、実際の様式と同じ順で出す。
- 各項目に、種類・適用（共通／課）・機密区分・必須・引き継ぎ・**使用中か**（値の件数）を出す。
- プレビュー: G-04 と同じ部品で、入力画面の見た目を出す（保存はしない）。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 表示名 | 必須、1〜60 文字、制御文字なし |
| コード | 作成時のみ。`^[a-z][a-z0-9_]{2,39}$`、全体で一意 |
| 区分 | `report`／`project`。作成後はデータがあれば変えられない |
| 入力部品 | §6.2 の決まり |
| 選択肢 | コード `^[a-z0-9_]{1,40}$`（項目の中で一意、作成後は変更不可）、表示名 1〜60 文字。`select`・`radio`・`multi_check` は有効な選択肢が 1 つ以上 |
| 機密区分 | `normal`／`internal`／`restricted`（`restricted` の付け外しは管理者のみ） |
| 設定 | 最大文字数 1〜10,000、数値の範囲（最小 ≦ 最大）、小数の桁 0〜4、表の行数 1〜50、表の列の定義（列は 1〜10、列の種類は `single_text`・`multi_text`・`number`・`date`・`select`） |
| 表示の条件 | 同じ様式の、選択式の項目と、その選択肢 |
| 説明文・入力例 | 0〜300・0〜100 文字 |

すべての文字は表示のときにエスケープする（HTML は書けない）。

## 6. 操作と処理

### 6.1 保存

1. CSRF → 送信の番号 → 権限（対象の課）→ 入力の確認 → §6.2 の変更の決まり。
2. 1 つのトランザクションで `report_fields`・`report_field_options` を保存。
3. 記録 `admin field:<id>:create|update`。
4. 既にある報告には影響しない（報告は作成時の定義を持つ。G-04 §4.1）。**新しく作る報告と、まだ作っていない月から**反映される。

### 6.2 変更の決まり（基本設計書 §9.4）

「データがある」は、`report_field_values` か `adhoc_request_fields.source_field_id` に使われていること。

| 変更 | データがない | データがある |
|---|---|---|
| 表示名・説明文・入力例・並び順・必須・引き継ぎ・一覧/検索/出力 | 可 | 可 |
| 入力部品 | 可 | `single_text`→`multi_text`、`select`⇔`radio` だけ可 |
| 区分・適用（共通⇔課） | 可 | 不可 |
| 機密区分 | 可 | 可。ただし「限定」との付け外しは管理者のみ。付け外すと、既存の値を暗号化・復号し直す処理を同じトランザクションで行う（自由記述は常に暗号化のため、対象は選択式などの値） |
| 選択肢の追加・表示名の変更・並び | 可 | 可 |
| 選択肢の削除 | 不可（無効化） | 不可（無効化） |
| 項目の削除 | 不可（無効化） | 不可（無効化） |

`field_type = 'project'`（案件）の項目は、無効にも、種類の変更もできない。

### 6.3 並べ替え・有効/無効

- 並べ替え: 区分ごとに、送られた順に `sort_order` を 10, 20, 30… で振り直す。
- 無効にする: 確認の表示（「新しい報告に出なくなります。過去の報告には残ります」）のあと `is_active = 0`。
- 有効に戻す: `is_active = 1`。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 保存 | 保存しました。これから作る報告に反映されます |
| 使用中で変えられない | この項目には入力済みのデータがあるため、入力部品をこの種類には変えられません |
| コードの重複 | 同じコードの項目があります |
| 権限 | この項目を変更する権限がありません |

## 8. 記録

`admin field:<id>:create|update|deactivate|activate|reorder|confidentiality`。

## 9. 検証の観点

- 課長が別の課・共通項目を変える POST が断られる。課長が「限定」を付け外す POST が断られる。
- データがある項目の入力部品を、互換のない種類に変えられない。
- 項目・選択肢を物理削除できない（DB のトリガーでも止まる）。
- 項目を変えたあと、既にある報告の表示が変わらない。新しい報告には反映される。
- 表示名に `<script>` を入れても、すべての画面で文字として出る。
- 「限定」に変えた項目の既存の値が暗号化される。
