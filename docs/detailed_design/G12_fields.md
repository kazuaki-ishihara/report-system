# G-12 項目マスタ

| 項目 | 内容 |
|---|---|
| URL | `/admin/fields.php?dept=<課ID または common>`（GET: 一覧。POST: 並べ替え・有効/無効）、`/admin/field_edit.php?id=<項目ID>`／`?dept=<課ID または common>`（GET: 編集・作成。POST: 保存）、`/admin/field_edit.php?preview=<課ID>`（GET: プレビュー）、`/admin/field_edit.php?dept=<課ID>&from_q=<質問ID>`（GET: 臨時の調査の質問を写して作成） |
| ファイル | `app/pages/admin_fields.php`・`admin_field_edit.php`、`app/views/admin_fields.php`・`admin_field_edit.php`・`admin_field_preview.php` |
| 利用者 | 管理者（共通項目・全課の課別項目）、課の項目管理者・課長（自分の課の課別項目） |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-04 |

`fields.php` の POST の `action`: `move_up`・`move_down`・`deactivate`・`activate`（`field_id` で項目を指定）。

---

## 1. 目的

報告の項目を、画面から追加・変更・並べ替え・無効化する。課ごとの補足情報を、課長が自分で設定できるようにする。

## 2. 表示の条件と権限

| 対象 | 管理者 | 課の項目管理者・課長 | それ以外 |
|---|---|---|---|
| 共通項目 | 編集できる | 見るだけ（一覧に「見るだけ」と出す） | 開けない |
| 自分の課の課別項目 | 編集できる | 編集できる | 開けない |
| 別の課の課別項目 | 編集できる | 開けない（403） | 開けない |

- 一覧を開けるのは、管理者か、どこかの課の項目管理者・課長。それ以外は 403。
- 機密区分を「限定」にする・外すのは、管理者だけ。

## 3. 画面の配置

**一覧**

```text
項目マスタ
様式 [A課の様式（共通＋A課） ▼] [表示] [ ＋ 項目を足す ] [ プレビュー ]
報告全体
┌────────────────┬────────┬────┬──────┬──────────┬────┬──────────────┐
│項目             │入力部品 │適用 │区分   │設定        │使用 │操作           │
├────────────────┼────────┼────┼──────┼──────────┼────┼──────────────┤
│前月からの変更     │チェック │共通 │通常   │           │12  │見るだけ        │
│ change_flag     │        │    │      │           │    │               │
│問題・悩み事       │複数行   │A課  │社外秘 │一覧        │3   │[↑][↓] 編集 [無効にする]│
└────────────────┴────────┴────┴──────┴──────────┴────┴──────────────┘
案件ブロック
  （同じ形）
▸ 無効の項目
```

- 様式の選択肢は、管理者だけ「共通項目のみ」が出る。ほかは「<課>の様式（共通＋<課>）」を管理できる課の分だけ出す。
- 「プレビュー」は課を選んだときだけ出す。
- 並べ替えは各行の「↑」「↓」ボタン（POST）。同じ区分・同じ適用（共通か、その課か）の中で隣と入れ替える。ドラッグや並び順の数字の入力はない。
- 無効の項目は、折りたたみの「無効の項目」に入れる。

**編集**

```text
項目の編集（A課）
← 項目マスタ
表示名      [業務システムの種類]
コード      system_type（変更できません）
区分        (○報告全体 ●案件ブロック（案件ごとに繰り返す）)
入力部品    [プルダウン ▼]
┌ 選択肢（プルダウン・ラジオ・チェックボックス）──────  ← 選択式のときだけ出す
│ 表示名        コード（任意）  有効
│ [在庫管理]     inventory      ☑
│ [販売管理]     sales          ☑
│ [________]    [自動  ]       ☑   ← 空の行を 3 つ足して出す
│ [＋ 選択肢の行を足す]
└────────────────────────────────────────
┌ 入力の制限 ──────────────────────────────  ← 入力部品に関係する欄だけ出す
│ 1 行・複数行: 最大文字数 [__]
│ 数値: 最小 [__]  最大 [__]  小数の桁 [__]
│ 表: 行数の上限 [__]  表の列（1 行に 1 列。キー|表示名|種類|選択肢）
│ それ以外: 「この入力部品には、入力の制限はありません。」
└────────────────────────────────────────
☐ 必須   ☑ 前月から引き継ぐ
機密区分    [社外秘 ▼]
説明文      [__________________]
入力例      [__________________]
┌ 表示の条件（任意）───────────────────────
│ この項目が [進捗（案件ブロック）▼]   ← 同じ区分の項目だけ選べる
│ 進捗 が次のどれかのとき: ☑遅延あり ☐問題なく進行 ☑その他
└────────────────────────────────────────
☐ 横並び表示に出す  ☐ 検索の対象にする（G-20 のキーワードで探す）  ☑ 出力する
[ 保存 ]
```

- 適用（共通／課）は欄にせず、見出しに「（A課）」のように出す。
- 既存の選択肢のコードは文字として出し、変えられない。選択肢の並びの列はない（行の順が並びになる）。
- 表の列は文字で入れる（画面で組み立てる部品は作らない）。
- 項目のコード・選択肢のコードは空でよい。空なら保存のときに自動で付ける（項目は `item_<番号>`、選択肢は `o1`・`o2`…でその項目の中で使われていない番号）。決めたいときだけ入れる。
- JavaScript が動くときは、入力部品に関係する「入力の制限」の欄と選択肢の欄だけを出す（隠した欄の値は残す。サーバーは入力部品に関係する設定だけを読む）。「＋ 選択肢の行を足す」で行を足せる。
- 表示の条件は、項目を選び、その項目の選択肢にチェックを付ける。選べる項目は、同じ様式の有効な選択式の項目のうち、今の区分（案件の項目は案件ブロック）と同じもの。選んだ項目の値の欄だけを出し、ほかの値の欄は送らない。JavaScript が動かないときはすべての値の欄を出す（違う項目の値を選ぶと、保存のときに誤りを出す）。
- データがある項目には、「この項目には入力済みのデータがあります。入力部品は互換のある種類（1 行→複数行、プルダウン⇔ラジオ）にだけ変えられます。区分は変えられません。」と出す。
- 編集の画面にプレビューのボタンはない（一覧から開く）。

## 4. 表示項目

- 一覧は「共通項目＋選んだ課の課別項目」を、区分（報告全体・案件ブロック）ごとに、共通項目が先、そのあと `sort_order` の順で出す。
- 各項目に、表示名とコード・入力部品・適用（共通／課）・機密区分・設定（必須／引継ぎ／一覧）・使用（`report_field_values` の件数）を出す。
- プレビュー: 課の様式（有効な項目）を、G-04 と同じ部品で「案件 1」（案件ブロックの項目。案件の項目は除く）、「報告全体」の順に出す。保存はしない。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 表示名 | 必須、1〜60 文字、制御文字なし |
| コード | 作成時のみ。空なら `item_<番号>`（番号は最大の ID + 1 から、使われていないもの）。入れたときは `^[a-z][a-z0-9_]{2,39}$`、全体で一意 |
| 区分 | `report`／`project`。種類が `project` のときは `project` に固定する |
| 入力部品 | `FIELD_TYPES` のどれか。変更は §6.2 の決まり |
| 案件の項目 | 種類 `project` の項目は全体で 1 つだけ |
| 選択肢 | コード `^[a-z0-9_]{1,40}$`（項目の中で重複なし、既存のコードは変更不可・削除不可。空で表示名がある行は `o<番号>` を自動で付ける）、表示名 1〜60 文字。コードと表示名がどちらも空の行は捨てる。選択肢を持つのは `select`・`radio`・`multi_check` で、有効な選択肢が 1 つ以上 |
| 機密区分 | `normal`／`internal`／`restricted`（`restricted` の付け外しは管理者のみ。課長には「限定」の選択肢を選べない形で出す） |
| 最大文字数 | `single_text`・`multi_text` のとき 1〜10,000（空なら既定: 1 行は 200、複数行は 2,000） |
| 数値 | 最小・最大は `^-?\d{1,12}(\.\d+)?$`、最小 ≦ 最大。小数の桁 0〜4 |
| 表 | 行数の上限 1〜50（空なら 20）。列は 1 行に 1 列、`キー|表示名|種類|選択肢（カンマ区切り）`。キーは `^[a-z][a-z0-9_]{0,29}$`、種類は `single_text`・`multi_text`・`number`・`date`・`select`。列は 1〜10 |
| 表示の条件 | 項目のコード（`show_when_field`）と、値（チェックボックスの `show_when_value[]`、またはカンマ区切りの `show_when_values`。1 つ以上）。コードは、同じ様式の項目（課の項目なら共通の項目かその課の項目、共通の項目なら共通の項目だけ）で、有効、区分が同じ、種類が `select`・`radio`・`checkbox`、自分以外のもの。値は、その項目の有効な選択肢のコード（`checkbox` は `1`）だけ |
| 説明文・入力例 | 0〜300・0〜100 文字 |

すべての文字は表示のときにエスケープする（HTML は書けない）。

## 6. 操作と処理

### 6.1 保存

1. 権限（対象の課）→ 送信の番号 → 入力の確認 → §6.2 の変更の決まり（共通編 §3）。
2. 1 つのトランザクションで `report_fields`・`report_field_options` を保存する。
   - 新しい項目の `sort_order` は、同じ区分・同じ適用の最大＋10。
   - 選択肢の `sort_order` は、送った行の順に 10, 20… を振る。
3. 記録 `admin field:<id>:create|update`。
4. 既にある報告の様式は変わらない（報告は作成時の定義を持つ。G-04 §4.1）。**新しく作る報告と、まだ作っていない月から**反映される。ただし「限定」の付け外しは、既存の報告の定義（`report_record_fields.confidentiality`）にも反映する。

臨時の調査の質問から作るとき（`from_q`）は、質問の表示名・種類・機密区分・説明・選択肢を初期値にする（区分は報告全体、引き継ぎと出力は有効）。依頼の課と `dept` が同じときだけ写す。

### 6.2 変更の決まり（基本設計書 §9.4）

「データがある」は、`report_field_values` か `adhoc_request_fields.source_field_id` に使われていること。

| 変更 | データがない | データがある |
|---|---|---|
| 表示名・説明文・入力例・必須・引き継ぎ・一覧/検索/出力 | 可 | 可 |
| 入力部品 | 可（`project` との変更は不可） | `single_text`→`multi_text`、`select`⇔`radio` だけ可 |
| 区分 | 可 | 不可 |
| 適用（共通⇔課） | 不可（作成後は変えない） | 不可 |
| 機密区分 | 可 | 可。ただし「限定」との付け外しは管理者のみ。付け外すと、既存の値を暗号化・復号し直す処理を同じトランザクションで行う（自由記述は常に暗号化のため、対象は選択式などの値。変更履歴は暗号化し直さない） |
| 選択肢の追加・表示名の変更・有効/無効 | 可 | 可 |
| 選択肢の並び | 行の順のまま（画面で変える手段はない） | 同左 |
| 選択肢の削除 | 可（行の「削除」にチェック。その選択肢が報告で使われていなければ消す） | 使われている選択肢は不可（無効化）。使われていない選択肢は可 |
| 項目の削除 | 不可（無効化） | 不可（無効化） |

`field_type = 'project'`（案件）の項目は、無効にも、種類の変更もできない。

### 6.3 並べ替え・有効/無効

- 並べ替え: 「↑」「↓」で隣と入れ替えたあと、同じ区分・同じ適用の項目（無効も含む）を 10, 20, 30… で振り直す（1 つのトランザクション）。端の項目では何もしない。
- 無効にする: 確認の表示（「新しい報告に出なくなります。過去の報告には残ります。無効にしますか？」）のあと `is_active = 0`。
- 有効に戻す: `is_active = 1`。

### 6.4 選択肢の削除

- 項目の編集で、既存の選択肢の行の「削除」にチェックを付けて保存すると、その選択肢が報告で使われていなければ消す（`form_option_is_used()`。1 つ選ぶ項目は値が同じコード、複数選ぶ項目は JSON の配列の中にそのコードがあるもの。「限定」の項目は値が暗号化されていて照合できないので、値が 1 つでもあれば使われているとみなす）。
- 使われていれば保存せずに「報告で使われている選択肢は削除できません（無効にしてください）: （コード）」を出す。
- 「削除」にチェックがないのに既存の選択肢の行が送られなかったとき（古い画面など）は、消さずに「選択肢は削除できません（無効にしてください）: （コード）」を出す。
- DB でも、使われている選択肢の削除はトリガーで止める（DB 編 `tr_report_field_options_no_delete_used`）。

### 6.5 共通の項目の、課ごとの選択肢

報告する人は主に IT 系（インフラ・SE・PG など）で、共通の項目（作業フェーズなど）の選択肢も IT 向けになっている。IT 系でない課のために、課長が共通の項目の選択肢を、自分の課でだけ変えられるようにする。ほかの課と、共通の選択肢そのものは変わらない。

| 項目 | 内容 |
|---|---|
| URL | `/admin/field_options.php?field=<共通の項目 ID>&dept=<課 ID>`（GET: 画面。POST: `action` = `save`・`delete_added`）。`app/pages/admin_field_options.php` |
| 開ける人 | その課の項目を管理できる人（課長・項目管理者・管理者。`can_manage_fields_of()`）。それ以外は 403 |
| 対象 | 有効な共通の項目のうち、選択式（`select`・`radio`・`multi_check`）。ほかは 404 |
| 入口 | 項目マスタの一覧で課の様式を見ているとき、共通の選択式の項目の行に「この課の選択肢」 |
| 共通の選択肢 | 1 つずつ「この課での表示名」（空なら共通のまま。60 文字まで）と「この課で出す」 |
| 足した選択肢 | 表示名（必須、60 文字まで）と「この課で出す」。報告で使われていなければ「削除」できる（確認の表示のあと。使われていれば「この選択肢は報告で使われているため削除できません（「出す」を外してください）」） |
| 足す | 空の欄 3 つに表示名を入れると足す。コードは `d<課 ID>_o<番号>`（共通の選択肢・この課で足した選択肢と重ならない番号） |
| 確かめ | この課で出す選択肢が 0 になる保存はしない（「この課で出す選択肢を 1 つ以上にしてください」）。100 件まで |
| 保存 | 1 つのトランザクションで、その課・その項目の `department_field_options` を入れ替える（表示名を変えた・出さない共通の選択肢と、足した選択肢だけを持つ）。「この課の選択肢を保存しました。これから作る報告に反映されます」 |
| 反映 | 課の様式を組み立てるとき（`form_template_fields()`）に、共通の有効な選択肢から「出さない」を除き、表示名を置き換え、足した有効な選択肢をうしろに並べる（`form_department_options()`）。報告を作るときに定義を写す（`report_record_fields`）ので、作った報告は作ったときの選択肢のまま |
| 記録 | `admin field_options:<項目 ID>:<課 ID>:update`・`delete` |

課ごとの選択肢は、報告の作成・表示・前月からの引き継ぎ・写す機能（いずれも報告ごとの定義を使う）に反映される。検索（G-20）の選択式の条件は共通の選択肢だけを出す（課で足した選択肢では探せない）。

## 8. 記録

`admin field:<id>:create|update|deactivate|activate|reorder`。「限定」の付け外しは `update` として残す。

## 9. 検証の観点

- 課長が別の課・共通項目を変える POST が断られる。課長が「限定」を付け外す POST は、入力の誤りとして画面にメッセージが出る。
- データがある項目の入力部品を、互換のない種類に変えられない。
- 項目・選択肢を物理削除できない（DB のトリガーでも止まる）。
- 項目を変えたあと、既にある報告の表示が変わらない。新しい報告には反映される。
- 表示名に `<script>` を入れても、すべての画面で文字として出る。
- 「限定」に変えた項目の既存の値が暗号化され、既存の報告の定義も「限定」になる。
