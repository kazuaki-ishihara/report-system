# G-05 報告の詳細

| 項目 | 内容 |
|---|---|
| URL | `/reports/view.php?id=<報告ID>`（GET。`&seq=1` で「未チェックを順に見る」）、`/reports/act.php`（POST: コメント・返信・解決・回答待ちに戻す・削除、チェック、確認完了・取り消し） |
| 利用者 | 本人、確認者、課長、管理者 |
| 主な端末 | スマートフォン |
| 段階 | 1（コメント）、2（チェック・確認完了・変更履歴） |
| 関連する機能 | F-06、F-07、F-11、F-12 |

---

## 1. 目的

報告を作成時の定義で表示し、項目ごとにコメントでやり取りする。確認者はチェックし、課長は確認を完了にする。**誰がチェック済みで、誰が未チェックか**を見せる。

## 2. 表示の条件と権限

- 見られる人は共通編 §10.2。見られない人には 404。未ログインはログイン画面へ転送する。
- 下書きの報告は本人と管理者だけが見られる（確認者には見せない）。下書きへの POST（`act.php`）は、だれでも 404。
- 「限定」の項目は、本人・課長・管理者だけに中身を出す（確認者には「（限定のため表示しません）」）。確認者には、その項目のコメントと変更履歴も出さない。「限定」の項目にコメントを出そうとすると 400、そのコメントへの返信・解決は 404。

| 操作 | 本人 | 確認者 | 課長 | 管理者 |
|---|---|---|---|---|
| コメントを出す（最初のコメント） | × | ○ | ○ | ○ |
| 返信する | ○ | ○ | ○ | ○ |
| 解決にする・回答待ちに戻す | × | 自分が出したもの | ○ | ○ |
| コメントを消す | 自分のもの | 自分のもの | 自分のもの | ○（すべて） |
| チェック済みにする | × | ○ | ○ | 確認者のときだけ |
| 確認完了にする・戻す | × | × | ○（自分の報告は不可） | ○ |

コメントを直す操作はない。

## 4. 表示項目

| 欄 | 内容 |
|---|---|
| 見出し | 「（表示名）さん YYYY年M月」、状態の札、「移行データ」「先月から変更なし」の札、「提出 YYYY-MM-DD HH:MM:SS」。「編集する」は、本人で、確認完了でなく、移行データでもないときに出す |
| チェック状況 | 下書きでないときだけ。報告の課の確認者（本人を除く）を、課長（`is_final`）が先、そのあと `sort_order` の順に。課長には「課長」の札。状態は「未チェック」「チェック済 MM-DD」「更新あり（再確認待ち）」 |
| 値 | `report_record_fields` の定義で表示。選択式は `options_json` の表示名。自由記述は復号して、改行を保って表示。空は「—」、復号できない値は「この内容は表示できません」 |
| 変わった値の印 | 見ている人が最後にチェックしたあとに変わった値（`report_value_history.revision > checked_revision`）に「更新あり」の札。一度もチェックしていなければ付けない |
| 客先名らしい言葉の印 | `has_warning = 1` の欄に、本人以外へ「注意: 客先名の可能性」。「限定」で隠した欄には出さない |
| コメント | 項目ごと・案件ブロックごと・報告全体に、最初のコメントと返信をまとめて出す。種類の札（追加情報の依頼／認識の確認／連絡）と状態の札（回答待ち／回答あり／解決）。削除されたものは、返信の有無に関係なく「（削除されました）」として残す |
| 変更履歴 | 提出後の変更を新しい順に（項目：変更前 → 変更後（長いものは 40 文字で省略）、変更した人、日時）。折りたたんで出す |
| 保管期限で消した自由記述 | 「（保管期限を過ぎたため削除しました）」 |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| コメントの種類 | `request`／`confirm`／`note`（最初のコメントのみ。返信は種類なしで `note`、状態は NULL） |
| コメントの本文 | 必須。1〜1,000 文字。制御文字は改行のみ。誤りは「コメントは 1〜1000 文字で入れてください」を出して G-05 に戻す。客先名らしい言葉の注意は画面だけで出す（止めない。保存はしない） |
| 対象 | `field_id` は報告の `report_record_fields` にあるもの（0 は報告全体）、`report_project_id` は報告の案件ブロック、または 0 |

## 6. 操作と処理

すべて `/reports/act.php` に POST。共通: CSRF（共通編 §3）→ 報告を見られるか（下書きは 404）→ 送信の番号（控えは `report.act.<action>`）→ 権限 → 状態 → 更新 → G-05 へ転送（該当のコメントへ移動）。`comment`・`reply`・`confirm`・`unconfirm` は 1 つのトランザクションで行う。

| 操作（`action`） | 処理 |
|---|---|
| `comment` | `report_field_comments` を作る。`request`・`confirm` は `thread_status = 'open'`、`note` は NULL。本文は暗号化（付加データにコメントの ID を入れるため、行を作ってから本文を入れる） |
| `reply` | 返信を作る（`parent_id`、`note`）。返信したのが報告の本人で、最初のコメントが `open` なら `answered` にする |
| `resolve` | 最初のコメントを `resolved`、`resolved_by`、`resolved_at`。出した人・課長・管理者だけ。状態のないコメント（`note`）は 400 |
| `reopen` | `open` に戻し、`resolved_by`・`resolved_at` を空にする。条件は `resolve` と同じ |
| `comment_delete` | 確認の表示のあと `deleted_at`。本文は暗号化のまま残し（30 日間は管理者が戻せる。G-15）、「（削除されました）」と出す |
| `check` | `report_reviews` に `(報告, 自分, 今の revision)` を入れる（あれば更新）。その課の確認者（本人を除く）だけ。ボタンは「チェック済みにする」、済みなら「チェック済み（もう一度付ける）」 |
| `confirm` | 課長・管理者（自分の報告は、管理者でない課長はできない）。提出済みのときだけ。確認の表示「確認を完了にします。完了すると本人は変更できなくなります。よろしいですか？」のあと `status = 'confirmed'`、`confirmed_by`、`confirmed_at`、状態の履歴。回答待ちのコメントがあっても完了できる（基本設計書 §4.1）。操作した人が本人でなければ、その人のチェックも同時に付ける |
| `unconfirm` | 課長・管理者。確認完了のときだけ。確認の表示「確認完了を取り消して提出済みに戻します。よろしいですか？」のあと、`status = 'submitted'`、`confirmed_by`・`confirmed_at` を空にし、状態の履歴を残す |

「未チェックを順に見る」（G-08 から `?seq=1` で開く）のときは、チェックの POST に `seq=1` を付ける。チェック済みにしたあと、同じ課・同じ月の次の未チェックの報告（`submitted_at`、`id` の順）へ `?seq=1` で転送する。最後なら「未チェックの報告はもうありません」を出して G-08 へ。

## 8. 記録

- 本人以外が開いたとき `view report:<id>`。
- 他人のコメントを消したとき `admin comment:<id>:delete`。

## 9. 検証の観点

- 別の課の確認者、確認者でない部下が開くと 404（存在を分からせない）。下書きは確認者にも 404。未ログインはログイン画面へ転送。
- 確認者に「限定」の値・コメント・変更履歴が出ない（HTML の中にも含まれない）。
- 部下は最初のコメントを出せない。他人のコメントを消せない。
- 本人の返信で `open` が `answered` になる。確認者の返信では変わらない。依頼した人が解決にできる。
- 提出後に本人が修正すると、チェック済みの確認者が「更新あり」になり、変わった値に印が付く。
- 回答待ちがあっても確認完了にできる。確認者は確認完了にできない。課長は確認完了にできる。
- 同じ送信の番号でコメントを 2 回送っても 1 件。
- 自分の報告に自分のチェック欄が出ない。

自動の検証でまだ試していないもの: コメントの二重送信、自分のチェック欄、回答待ちがあるままの確認完了、他人のコメントの削除。
