# G-05 報告の詳細

| 項目 | 内容 |
|---|---|
| URL | `/reports/view.php?id=<報告ID>`（GET）、`/reports/act.php`（POST: コメント・返信・解決・削除、チェック、確認完了） |
| 利用者 | 本人、確認者、課長、管理者 |
| 主な端末 | スマートフォン |
| 段階 | 1（コメント）、2（チェック・確認完了・変更履歴） |
| 関連する機能 | F-06、F-07、F-11、F-12 |

---

## 1. 目的

報告を作成時の定義で表示し、項目ごとにコメントでやり取りする。確認者はチェックし、課長は確認を完了にする。**誰がチェック済みで、誰が未チェックか**を見せる。

## 2. 表示の条件と権限

- 見られる人は共通編 §10.2。見られない人には 404。
- 下書きの報告は本人だけが見られる（確認者には見せない）。
- 「限定」の項目は、本人・課長・管理者だけに中身を出す（確認者には「（限定のため表示しません）」）。

| 操作 | 本人 | 確認者 | 課長 | 管理者 |
|---|---|---|---|---|
| コメントを出す（最初のコメント） | × | ○ | ○ | ○ |
| 返信する | ○ | ○ | ○ | ○ |
| 解決にする | × | 自分が出したもの | ○ | ○ |
| 自分のコメントを直す・消す | ○（返信） | ○ | ○ | ○（すべて） |
| チェック済みにする | × | ○ | ○ | － |
| 確認完了にする・戻す | × | × | ○ | ○ |

## 4. 表示項目

| 欄 | 内容 |
|---|---|
| 見出し | 作成者の表示名、対象月、状態、提出日時、「先月から変更なし」で提出したなら印 |
| チェック状況 | 報告の課の確認者を `sort_order` 順に。状態は未チェック／チェック済（日付）／更新あり（共通編・DB 編の判定）。本人の報告が確認者自身のものなら、その人は除く |
| 値 | `report_record_fields` の定義で表示。選択式は `options_json` の表示名。自由記述は復号して、改行を保って表示 |
| 変わった値の印 | 見ている確認者が最後にチェックしたあとに変わった値（`report_value_history.revision > checked_revision`）に印 |
| 客先名らしい言葉の印 | `has_warning = 1` の欄に「注意: 客先名の可能性」（確認者・課長・管理者に出す） |
| コメント | 項目ごと・案件ブロックごとに、最初のコメントと返信をまとめて出す。種類と状態の札。削除されたものは「（削除されました）」 |
| 変更履歴 | 提出後の変更を新しい順に（項目、変更前→変更後、変更した人、日時）。折りたたんで出す |
| 保管期限で消した自由記述 | 「（保管期限を過ぎたため削除しました）」 |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| コメントの種類 | `request`／`confirm`／`note`（最初のコメントのみ） |
| コメントの本文 | 必須。1〜1,000 文字。制御文字は改行のみ。客先名らしい言葉は注意（止めない） |
| 対象 | `field_id` は報告の `report_record_fields` にあるもの、`report_project_id` は報告の案件ブロック、または 0 |

## 6. 操作と処理

すべて `/reports/act.php` に POST。共通: CSRF → 送信の番号 → 権限 → 状態 → 1 つのトランザクション → G-05 へ転送（該当箇所へ移動）。

| 操作（`action`） | 処理 |
|---|---|
| `comment` | `report_field_comments` を作る。`request`・`confirm` は `thread_status = 'open'`、`note` は NULL。本文は暗号化 |
| `reply` | 返信を作る（`parent_id`）。返信したのが報告の本人で、最初のコメントが `open` なら `answered` にする |
| `resolve` | 最初のコメントを `resolved`、`resolved_by`、`resolved_at` |
| `reopen` | `resolved` を `open` に戻す（解決にした人・課長・管理者） |
| `comment_edit` | 自分のコメントの本文を直す（`updated_at`） |
| `comment_delete` | 確認の表示のあと `deleted_at`。返信があれば本文だけ消して「（削除されました）」として残す |
| `check` | `report_reviews` に `(報告, 自分, 今の revision)` を入れる（あれば更新）。報告が提出済みか確認完了のときだけ |
| `confirm` | 課長・管理者。確認の表示のあと `status = 'confirmed'`、`confirmed_by`、`confirmed_at`、状態の履歴。回答待ちのコメントがあっても完了できる（基本設計書 §4.1）。課長のチェックも同時に付ける |
| `unconfirm` | 課長・管理者。確認完了を提出済みに戻す（間違えたとき） |

「未チェックを順に見る」（G-03 から）のときは、チェック済みにしたあと、同じ課・同じ月の次の未チェックの報告へ転送する。最後なら G-08 へ。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| コメント | コメントしました |
| 解決 | 解決にしました |
| チェック | チェック済みにしました（次の報告へ進みます） |
| 確認完了 | 確認を完了しました |
| 回答待ちがある状態で確認完了 | 確認の表示に「回答待ちのコメントが n 件あります。このまま完了しますか？」 |
| 下書き・削除済みへの操作 | 対象のデータが見つかりません |

## 8. 記録

- 本人以外が開いたとき `view report:<id>`。
- 管理者が他人のコメントを消したとき `admin comment:<id>:delete`。

## 9. 検証の観点

- 別の課の確認者、確認者でない部下、未ログインで開くと 404（存在を分からせない）。下書きは確認者にも 404。
- 確認者に「限定」の値が出ない（HTML の中にも含まれない）。
- 部下は最初のコメントを出せない。他人のコメントを直せない・消せない。
- 本人の返信で `open` が `answered` になる。確認者の返信では変わらない。
- 提出後に本人が修正すると、チェック済みの確認者が「更新あり」になり、変わった値に印が付く。
- 回答待ちがあっても確認完了にできる。確認者は確認完了にできない。
- 同じ送信の番号でコメントを 2 回送っても 1 件。
- 自分の報告に自分のチェック欄が出ない。
