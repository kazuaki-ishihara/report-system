# G-02 パスワードの再設定

| 項目 | 内容 |
|---|---|
| URL | `/password_reset.php`（GET: 画面、POST: 再設定） |
| 利用者 | 全員（未ログイン） |
| 主な端末 | スマートフォン |
| 段階 | 1 |
| 関連する機能 | F-01 |

---

## 1. 目的

パスワードを忘れた人が、管理者に頼らずに自分で再設定する（基本設計書 §4.3）。本人確認には 2 段階認証のコード（または予備のコード）を使う。

## 2. 表示の条件と権限

- ログインしていない人が使う。
- 2 段階認証を設定していない人は、この画面では再設定できない（管理者に依頼する。G-14）。

## 3. 画面の配置

```text
┌──────────────────────────┐
│ パスワードの再設定          │
├──────────────────────────┤
│ ログイン ID                │
│ [________________]        │
│ 認証アプリの 6 桁のコード    │
│ （または予備のコード）       │
│ [__________]              │
│ 新しいパスワード（10 文字以上）│
│ [________________] [表示] │
│ 新しいパスワード（確認）     │
│ [________________]        │
│                          │
│ [       再設定する      ]   │
│                          │
│ 認証アプリも使えないときは、  │
│ 管理者に連絡してください     │
└──────────────────────────┘
```

## 4. 表示項目

- パスワードの決まり: 「10 文字以上。文の形（例: 好きな言葉をつなげたもの）にすると覚えやすくなります」。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| ログイン ID | G-01 と同じ |
| コード | G-01 と同じ（TOTP 6 桁、または予備のコード） |
| 新しいパスワード | 10 文字以上、72 バイト以下。ログイン ID と同じものは不可 |
| 確認 | 新しいパスワードと一致 |

## 6. 操作と処理

1. CSRF の確認。送信の番号の確認。
2. ログイン ID で `users` を探す。ない・無効・2 段階認証が未設定・ロック中のときは、すべて同じ「ログイン ID かコードが違います」にする。
3. コードを G-01 §6.2 と同じ方法で確かめる。失敗はログインの失敗と同じ回数に数え、ロックの対象にする。
4. 新しいパスワードを確かめる。
5. 1 つのトランザクションで、`password_hash` を更新、`password_changed_at`、`failed_count = 0`、`session_version + 1`（ほかの端末をログアウトさせる）、`must_change_password = 0`。
6. 記録 `auth password:reset`。
7. ログイン画面へ転送し、成功のメッセージを出す。そのままではログインさせない（G-01 から入り直す）。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 成功 | パスワードを再設定しました。新しいパスワードでログインしてください |
| ID かコードが違う | ログイン ID かコードが違います |
| パスワードが短い | パスワードは 10 文字以上にしてください |
| 確認が一致しない | 確認のパスワードが一致しません |
| ロック中 | G-01 と同じ |

## 8. 記録

`auth` に `password:reset`、`password:reset_fail`。

## 9. 検証の観点

- 存在しない ID、2 段階認証が未設定の ID、コード違いで、表示と時間が同じ。
- 失敗はログインの失敗と合わせて数えられ、ロックされる。
- 再設定のあと、ほかの端末のセッションが無効になる。
- 予備のコードで再設定すると、そのコードは使用済みになる。
