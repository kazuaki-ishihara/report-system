# G-22 要望・依頼（課長・確認者 → システム管理者）

| 項目 | 内容 |
|---|---|
| URL | `/requests/index.php`（GET・POST。一覧と新しく出す）、`/requests/view.php?id=<ID>`（GET・POST。詳細とやり取り） |
| ファイル | `app/pages/support_request_list.php`、`app/pages/support_request_view.php`、`app/views/support_request_list.php`、`app/views/support_request_view.php`、`app/lib/support_request.php`、`app/views/layout.php`（各画面のリンク） |
| 利用者 | 出す人: 課長・確認者（課代・リーダー）。受ける人: システム管理者・システム管理者補佐（代行） |
| 主な端末 | PC・スマートフォン |
| 段階 | 3 |

---

## 1. 目的

課長・確認者が、システムへの改善要望・対応依頼・不具合・質問を、システム管理者へ画面から出せるようにする。システム管理者側は、対応した内容や検討の結果を、出した人へ返信する。口頭やメールのやり取りで抜け漏れが出ないよう、要望と返信と状態をシステムの中に残す。

## 2. 表示の条件と権限

| 人 | できること |
|---|---|
| 課長・確認者（`support_request_can_submit()`: 確認者の課が 1 つ以上ある人） | 新しく出す。自分が出したものの一覧・詳細・返信。受付待ちのうちは取り下げ |
| システム管理者・補佐（`support_request_is_staff()` = `can_manage_system()`） | すべての要望・依頼の一覧・詳細。返信と状態の変更 |
| 部下 | 使えない（403）。部下の要望は課長を通して出す |

- 詳細は、出した本人と管理者・補佐だけが開ける（ほかの人は 403）。
- 管理者・補佐が確認者でもあるときは、自分でも出せる（一覧にタブ「すべての要望・依頼」「自分が出したもの」）。
- メニュー: 管理者・補佐は見出し「管理」、課長・確認者は見出し「確認」に「要望・依頼」。管理のトップ（G-21）にカード。
- 課長・確認者には、各画面（`SUPPORT_REQUEST_SCREEN_CODE_BY_TEMPLATE` に載っている画面）の下に「この画面について要望・依頼を出す」を出す。押すと、その画面の番号と開いていた画面（`from`）を付けて一覧を開き、新しく出す欄を開いて画面のボタンを選んでおく（§6.1）。

## 3. 画面の配置

**一覧（`/requests/index.php`）**

1. 「← ホーム」、見出し「要望・依頼」、説明。
2. 管理者・補佐: 「未受付 n ／ 返信待ち（出した人が返信） n」。
3. 課長・確認者: 「＋ 新しく出す」（開くと入力欄。`id="new"`）。関係する画面は丸いボタン（「全体的な要望（システム全体）」・画面ごと・そのほか）を押して選ぶ。画面のリンクから来たときは、開いていた画面を出し、端末の種類と一緒に送ると知らせる。
4. 絞り込み: 状態（続いているもの〈既定〉／すべて／各状態）、種類。
5. 一覧（最大 300 件）: 「#番号 件名」（押すと詳細）、種類と関係する画面、（管理者・補佐の全員分では）出した人と課、最後のやり取りの日時、状態の札、「急ぎ」、出した人の一覧では「回答あり」、管理者側の一覧では「返信あり」（受付後の続いているもので、最後が出した人の返信）。並びは未受付 → 続いているもの → 閉じたもの、急ぎを先、新しい順。

**詳細（`/requests/view.php?id=<ID>`）**

1. 「← 要望・依頼の一覧」、見出し「#番号 件名」、状態・種類・急ぎの札。
2. 出した人（課）、関係する画面、開いていた画面（リンク）、端末、出した日時、閉じた日時。管理者・補佐には、客先名らしい言葉があれば注意を出す。
3. 内容。
4. やり取り: 管理者側の返信は「システム管理者（名前）」で色を付けて出す。状態を変えた返信には「→ 完了」などの札。
5. 管理者・補佐: 「出した人への返信（対応した内容・検討の結果）」の欄と、状態のボタン（未受付・対応検討中・対応中・検証中・リリース待ち・リリース済み・完了・見送り。今の状態のボタンは押せない）、「返信だけ送る（状態は変えない）」。
6. 出した人（続いている間）: 「返信（補足・追加の情報）」。閉じたものには「この要望・依頼は閉じています。続きがあるときは、新しく出してください。」
7. 出した人（未受付のとき）: 「取り下げる」（理由は任意。確認の表示のあと）。

## 4. 表示項目

| 項目 | 値 |
|---|---|
| 種類 | 改善要望（`improvement`）／対応依頼（`task`）／不具合（`bug`）／質問（`question`） |
| 状態 | 未受付（`open`）／対応検討中（`reviewing`）／対応中（`in_progress`）／検証中（`testing`）／リリース待ち（`release_waiting`）／リリース済み（`released`）／完了（`done`。リリースのない質問・依頼）／見送り（`declined`）／取り下げ（`withdrawn`）。続いているのは未受付〜リリース待ち（`SUPPORT_REQUEST_ACTIVE_STATUSES`） |
| 急ぎ | 通常（`normal`）／急ぎ（`urgent`） |
| 関係する画面 | 指定しない／全体的な要望（システム全体。`system`）／G-02〜G-22 の画面／そのほか（`SUPPORT_REQUEST_SCREEN_LABELS`） |
| 開いていた画面 | 画面のリンクから出したときの URL。同じサイトのパスと、決まった問い合わせの項目（`id`・`period`・`dept`・`tab`・`scope`・`edit`・`field`・`status`・`filter`・`preview`・`seq`。英数字 20 文字まで）だけを残す。検索のキーワードなど自由な文字は残さない（`support_request_clean_source_path()`。200 文字まで） |
| 端末 | 出したときの PC／スマートフォンと、ブラウザー・OS の名前（`support_request_client_text()`。版は残さない） |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 種類・急ぎ・関係する画面 | 決まった値のどれか |
| 件名 | 必須、60 文字まで、改行と制御文字なし |
| 内容・返信 | 必須（管理者側の返信は §6.4）、2,000 文字まで、改行可 |
| 続いている数 | 1 人で続いているもの（受付待ち・対応中）が 30 件あれば、新しく出せない |

件名・内容は注意の言葉（客先名らしい言葉）で確かめ、当たれば `has_warning = 1`（保存はする。管理者側の詳細に注意を出す）。

## 6. 操作と処理

### 6.1 新しく出す

`support_requests` に 1 行（状態 `open`、出した人の今の課、開いていた画面、端末）。件名と内容は行の ID を含む文脈で暗号化する（`sreq_title:<ID>`・`sreq_body:<ID>`）。記録 `admin support_request:<ID>:create`。詳細へ移り「要望・依頼を出しました。システム管理者から返信があると、ホームに出ます」。

### 6.2 出した人の返信

続いている間だけ。`support_request_messages` に 1 行（`is_staff = 0`。本文は `sreq_msg:<要望ID>:<返信ID>` で暗号化）。閉じたものは「閉じた要望・依頼には返信できません。新しく出してください」。

### 6.3 管理者側の返信と状態の変更

- 状態のボタンを押すと、状態を変えて返信する。返信の欄が空なら、状態ごとの定型の返信を送る（G-17 で文言を変えられる）。「返信だけ送る」は状態を変えない。返信も状態もなければ「返信を入れるか、状態のボタンを押してください」。
- 見送りにするときは、検討の結果の返信が必須（「見送りにするときは、検討の結果を返信に書いてください」）。
- リリース済み・完了・見送りにすると閉じた日時を残す。続いている状態に戻すと閉じた日時を消す。

| 状態のボタン | 返信が空のときの定型の返信 |
|---|---|
| 未受付 | 受付前の状態に戻しました。 |
| 対応検討中 | ご要望を受け付けました。対応するかどうかを検討しています。 |
| 対応中 | 対応を始めました。 |
| 検証中 | 対応が終わり、検証しています。 |
| リリース待ち | 検証が終わりました。リリースを待っています。 |
| リリース済み | リリースしました。画面で確かめてください。 |
| 完了 | 対応が終わりました。 |
| 見送り | （なし。返信が必須） |
- 取り下げられたものは変えられない。
- `support_request_messages` に 1 行（`is_staff = 1`、状態を変えたときは `status_change`）。記録 `admin support_request:<ID>:reply|status_<状態>`（補佐は `acted_as_deputy = 1`）。

### 6.4 取り下げ

出した人が、未受付のときだけ。理由は任意。状態 `withdrawn`。記録 `admin support_request:<ID>:withdraw`。

### 6.5 知らせ（メールなどは使わない）

| 相手 | 出す所 | 条件 |
|---|---|---|
| 出した人 | ホーム「要望・依頼にシステム管理者から回答があります（n 件）」、一覧の「回答あり」 | 管理者側の返信で、番号が `requester_seen_message_id` より大きいものがある。出した人が詳細を開く・返信する・取り下げると、今あるやり取りの最後の番号にする |
| 管理者・補佐 | ホーム「要望・依頼: 未受付 n 件、返信待ち n 件」、管理のトップのカード（未受付があれば目立つ札） | 未受付の数。受付後の続いているもので、最後のやり取りが出した人の返信の数 |

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 出した | 要望・依頼を出しました。システム管理者から返信があると、ホームに出ます |
| 返信 | 返信しました ／ 返信し、状態を「（状態）」にしました ／ 定型の返信（§6.3） |
| 取り下げ | 取り下げました ／ 未受付のときだけ取り下げられます |
| 誤り | 種類を選んでください ／ 急ぎかどうかを選んでください ／ 関係する画面が正しくありません ／ 件名を入れてください ／ 内容を入れてください ／ 続いている要望・依頼が 30 件あります。終わったものが閉じられてから出してください ／ 閉じた要望・依頼には返信できません。新しく出してください ／ 取り下げられた要望・依頼は変えられません |

## 8. 記録

- `admin support_request:<ID>:create|reply|status_<状態のコード>|withdraw`。
- 本文は記録しない。

## 9. 検証の観点

`tools/test/smoke_requests.py`（`verify_all.py` の工程 requests）。

- 課長・確認者が出せる。部下は 403。ほかの人の要望・依頼は 403。
- 件名・本文・返信が暗号化されている（`check_db_secrets.py` でも確かめる）。
- 管理者のホームと管理のトップに受付待ち・返信待ちの数。補佐も一覧を開き、対応できる。
- 各画面の「この画面について要望・依頼を出す」で、画面のボタンが選ばれ、開いていた画面は決まった項目だけが残る。部下の画面には出さない。端末を残す。
- 状態のボタンだけで定型の返信を送れる。対応検討中 → 対応中 → 検証中 → リリース待ち → リリース済みと進められる。見送りは返信が必須。リリース済みにすると閉じ、出した人のホームに「回答あり」が出て、開くと消える。
- 閉じたものには返信できない。取り下げは受付待ちのときだけ。取り下げたものは管理者側も変えられない。

## 10. 便利機能（B・C・D・E）

| 機能 | 内容 |
|---|---|
| B 返信の定型文 | 管理者側の一覧の下の「返信の定型文」で、要望の種類（改善要望・対応依頼・不具合・質問、または「すべての種類」）を選んで足す・消す（500 文字・30 件まで。`support_reply_templates.kind`）。詳細の返信の欄の上には、その要望の種類と「すべての種類」の定型文だけを出し、選ぶと返信の欄に足す（K-047 決定） |
| C 重複をまとめる | 詳細（管理者側。続いている要望）の「同じ内容の要望の番号」で、この要望をまとめる先にまとめて閉じる（状態は完了、`merged_into_id`）。まとめる先にほかの要望にまとめられたものや自分自身は選べない。まとめる先に管理者側が返信・状態を変えると、まとめた要望にも「（同じ内容の要望 #番号 での返信）」として同じ返信が届く（出した人どうしはお互いの要望を見られないため）。記録 `admin support_request:<ID>:merge:<先>`。取り消しは作らない（省いた） |
| D 対応の予定 | 詳細（管理者側）の「対応の予定」（40 文字。例: 2026年12月にリリース予定）。出した人の詳細と一覧に出す。空で消す。記録 `admin support_request:<ID>:plan` |
| E CSV の出力 | 管理者側の全員分の一覧（PC）で「この条件で CSV に出力（件名と状態）」「内容も含めて CSV に出力」。今の絞り込みのまま。列は 番号・種類・件名・状態・急ぎ・関係する画面・課・出した人・出した日時・最後のやり取り・閉じた日時・対応の予定・まとめた先（・内容）。G-10 と同じ形式。記録 `export export:support_requests;body=0|1` |
| A・J へ | 「リリース済み」「完了」の詳細から更新のお知らせ（G-24）、「質問」で閉じた詳細からよくある質問（G-25）へ移れる |
