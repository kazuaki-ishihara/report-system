公開側の入り口のファイルは、次の 2 行と、その画面の処理を呼ぶだけにする。

```php
<?php
declare(strict_types=1);
require __DIR__ . '/../../report-system-app/app/bootstrap.php';   // 位置は config で調整
```

開発用 PC のローカル検証環境では、`public/` と `app/` を同じリポジトリの中に置き、`bootstrap.php` の場所だけを変える。

## 2. URL の決まり

| 決まり | 内容 |
|---|---|
| 画面 | GET で開く。画面を開くだけでデータは変えない |
| 更新 | POST だけで受ける。処理のあとは結果の画面へ転送する（PRG） |
| ID の受け取り | `filter_input(..., FILTER_VALIDATE_INT)` で受け、1 以上でなければ 400 |
| 対象月 | `YYYY-MM`。正規表現 `^\d{4}-(0[1-9]|1[0-2])$` で確かめる |
| 転送先 | 自分のサイトの中の相対パスだけ（外のサイトへの転送はしない） |
| 未ログイン | どの階層の画面からでも、`/report-system/login.php?next=<元の画面>` へ転送する（`next` は自サイトのパスだけ受け付ける） |

## 3. すべての要求で行う共通処理

`bootstrap.php` が、画面ごとの処理の前に次を順に行う（基本設計書 §15.1）。

| 順 | 処理 | 失敗したとき |
|---|---|---|
| 1 | 設定の読み込み、エラーの扱いの設定（画面に詳細を出さない） | 500「ただいま利用できません」 |
| 2 | 共通のヘッダーを付ける（§4） | — |
| 3 | DB に接続し、`PRAGMA foreign_keys = ON`、`PRAGMA busy_timeout = 5000` | 503 |
| 4 | セッションの開始。自動ログアウトの確認（§5） | ログイン画面へ |
| 5 | ログインの確認（ログイン画面・再設定画面・稼働の確認を除く） | ログイン画面へ |
| 6 | 2 段階認証が済んでいるかの確認 | G-01 のコード入力へ |
| 7 | 2 段階認証の設定が済んでいるかの確認（未設定なら G-16 の設定だけ使える） | G-16 へ |
| 8 | POST なら CSRF の確認（§6） | 403 |
| 9 | POST なら送信の番号の確認（§7） | 1 回目の結果を返す／処理中の案内 |
| 10 | 画面ごとの権限の確認（§10） | 403 |
| 11 | 画面ごとの処理（入力の確認 → 状態の確認 → 1 つのトランザクションで更新 → 記録） | 入力エラーは同じ画面に戻す |

## 4. 共通のヘッダー

| ヘッダー | 値 | 目的 |
|---|---|---|
| `Cache-Control` | `no-store` | 画面の内容を端末に残さない |
| `X-Frame-Options` | `DENY` | 他のサイトへの埋め込みを防ぐ |
| `X-Content-Type-Options` | `nosniff` | |
| `Referrer-Policy` | `same-origin` | |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; form-action 'self'; frame-ancestors 'none'` | 外部の読み込みと埋め込みのスクリプトを禁止する |
| `Strict-Transport-Security` | `max-age=31536000` | HTTPS だけで接続させる（HTTPS の動作を確認してから付ける） |

HTTP で来た要求は HTTPS へ転送する（`.htaccess`）。

## 5. セッションと自動ログアウト

| 項目 | 値 |
|---|---|
| Cookie | `Secure`、`HttpOnly`、`SameSite=Lax`、パスは `/report-system/` |
| ID の作り直し | ログイン成功時、2 段階認証の成功時、パスワード変更時に `session_regenerate_id(true)` |
| 操作がないときのログアウト | 30 分 |
| ログインの最長 | 12 時間 |
| すべての端末からログアウト | `users.session_version` を 1 増やす。セッションに持つ版と違えばログアウトさせる |
| ログアウト | セッションを破棄し、Cookie を消す。端末の記憶は残す（G-16 で消せる） |

## 6. CSRF

- セッションごとに 32 バイトの乱数のトークンを作り、すべてのフォームに隠し項目 `csrf_token` で入れる。
- POST を受けたら `hash_equals()` で比べる。違えば 403「画面を開き直してから、もう一度お試しください」。
- 自動保存などの JavaScript からの送信も、同じトークンを付ける。

## 7. 送信の番号（二重登録の防止）

基本設計書 §15.3。

| 項目 | 内容 |
|---|---|
| 番号の作成 | 画面を作るときに、更新のフォームごとに 32 文字の乱数を隠し項目 `request_key` で入れる |
| やり直し | 通信が切れて同じフォームを送り直すときは、同じ番号を使う（JavaScript が番号を変えずに送る） |
| サーバーの処理 | `request_keys` に番号を登録してから処理する。登録済みで `done` なら、処理せずに 1 回目の結果（転送先）を返す。`processing` なら「前の送信をまだ処理しています」 |
| 別の人・別の操作 | 同じ番号でも利用者か操作が違えば 400 |
| 入力エラー | 控えを消し、直して送り直せば処理する |
| 控えの期間 | 1 日。それより古いものは、ログイン時の後片付けで消す |

## 8. 暗号化

基本設計書 §8.1、§11.1。

### 8.1 対象

| 対象 | 暗号化する |
|---|---|
| 自由記述の値（`single_text`、`multi_text`、`table` の文字の列） | 常に |
| 機密区分が「限定」の項目の値（種類を問わない） | 常に |
| コメントの本文 | 常に |
| 変更履歴の変更前・変更後（対象の項目が暗号化の対象なら） | 常に |
| 臨時の調査の回答（上と同じ決まり） | 常に |
| 2 段階認証の秘密の値 | 常に |
| 選択式の値、数値、日付、年月、案件コード（通常・社外秘） | しない |

### 8.2 方式

| 項目 | 内容 |
|---|---|
| 方式 | AES-256-GCM（PHP の OpenSSL 機能。PHP 7.4 で使える） |
| 鍵 | 32 バイトの乱数。`keys/field.key` に Base64 で保存（権限 600）。DB・公開ディレクトリとは別の場所 |
| 保存の形 | `v1:` ＋ Base64（IV 12 バイト ＋ 認証タグ 16 バイト ＋ 暗号文）。`v1` は鍵の版 |
| 付加データ | テーブル名と行の識別（例: `rfv:<report_id>:<field_id>:<block>`）を付加データにする。暗号文を別の行に移し替えても復号できない |
| 鍵の入れ替え | 新しい鍵を `v2` として追加し、全件を復号して新しい鍵で暗号化し直す処理を用意する。古い鍵は入れ替えが終わるまで残す |
| 復号の失敗 | 画面には「この内容は表示できません」と出し、ログに記録する |

### 8.3 検索

自由記述は DB では検索できないため、検索の条件（対象月・課・選択式の値）で絞った報告を、見る権限のある範囲だけ復号して、アプリの中で文字列を探す。1 回の検索で復号する件数の上限を 2,000 件とし、超えるときは条件を足すよう案内する。

## 9. 入力の確認

### 9.1 3 段階（基本設計書 §15.2）

| 段階 | 場所 | 内容 |
|---|---|---|
| 1 | 画面 | HTML の `required`、`maxlength`、`type`、`min`/`max`。補助であり、頼らない |
| 2 | サーバー | 項目マスタの設定に従い、すべてを確認し直す（§9.2） |
| 3 | サーバー（DB を見る） | 重複、存在、状態（例: 確認完了の報告は変更できない） |

### 9.2 入力部品ごとの確認

| 種類 | 確認 | 保存の形 |
|---|---|---|
| `single_text` | 改行なし。制御文字なし。UTF-8 として正しい。最大文字数（設定。既定 200 文字） | 文字列（暗号化） |
| `multi_text` | 制御文字は改行・タブのみ可。最大文字数（設定。既定 2,000 文字） | 文字列（暗号化） |
| `date` | `YYYY-MM-DD` で、実在する日付 | 文字列 |
| `month` | `YYYY-MM` | 文字列 |
| `number` | 数字。最小・最大・小数の桁数（設定） | 数字の文字列 |
| `select`・`radio` | 選択肢のコードのどれか（有効なもの） | 選択肢のコード |
| `checkbox` | `0` か `1` | `0`／`1` |
| `multi_check` | 選択肢のコードの集合。重複なし | JSON の配列 |
| `table` | 行数の上限（設定。既定 20 行）。各列を上の決まりで確認 | JSON の配列（文字の列があれば全体を暗号化） |

- 文字数は `mb_strlen()` で数える（`mbstring` がない環境では `preg_match_all('/./us')` で数える）。
- 前後の空白は取り除いてから確認する。
- 必須の確認は「提出」のときだけ行う。下書きの保存では行わない。

### 9.3 客先名らしい言葉の注意

- 自由記述の値に、`warning_words` の言葉が含まれるかを、画面（入力中）とサーバー（保存時）の両方で調べる。
- 含まれても保存は止めない。サーバーは、含まれた欄を `report_field_values.has_warning = 1` にする（確認者の画面の印に使う）。
- 調べるときは、全角・半角と大文字・小文字をそろえてから比べる。

## 10. 権限の判定

`perm.php` にまとめ、画面ごとの処理は必ずここを通す。

### 10.1 役割の判定

| 役割 | 判定 |
|---|---|
| 管理者 | `users.is_admin = 1` |
| 課長（その課の最終確認者） | `department_reviewers` に `(課, 本人, is_final = 1)` がある |
| 確認者（その課） | `department_reviewers` に `(課, 本人)` がある（課長を含む） |
| 課別項目の管理者 | `department_admins` に `(課, 本人)` がある、またはその課の課長 |
| 部下 | 上のどれでもない、ログインしている利用者 |

役割は課ごとに決まる。同じ人が、ある課の確認者で、別の課では部下ということもありうる。

### 10.2 報告を見られるか

```text
本人の報告                         → 見られる
管理者                             → 見られる
報告の課（作成時の課）の確認者      → 見られる（ただし「限定」の項目は課長と管理者だけ）
それ以外                           → 見られない（存在しない報告と同じ 404 を返す）
```

### 10.3 機密区分による表示

| 区分 | 本人 | 確認者 | 課長 | 管理者 |
|---|---|---|---|---|
| 通常・社外秘 | ○ | ○ | ○ | ○ |
| 限定 | ○ | 「（限定のため表示しません）」 | ○ | ○ |

## 11. メッセージと画面の共通部品

### 11.1 メッセージの出し方

| 種類 | 出し方 |
|---|---|
| 成功 | 画面の上に重ねて出し、4 秒で消える |
| 入力エラー | 画面の上にまとめて出し、該当する欄の下にも出す。消えない（閉じるボタン） |
| 注意（客先名らしい言葉など） | 該当する欄の下に黄色で出す |
| エラー（権限・障害） | 専用の画面。英語や内部の情報は出さない |

### 11.2 共通のエラー画面

| 状態 | 文言 |
|---|---|
| 400 | 要求の内容が正しくありません。画面を開き直してください |
| 403 | この操作を行う権限がありません |
| 403（CSRF） | 画面を開き直してから、もう一度お試しください |
| 404 | 対象のデータが見つかりません |
| 500・503 | ただいま利用できません。時間をおいてもう一度お試しください |

### 11.3 通信が切れたとき（JavaScript）

| 状況 | 動き |
|---|---|
| 保存・提出の応答が 30 秒ない、または通信のエラー | 「通信が途中で切れたため、保存されたか確かめられません。画面を読み直したので確かめてください。保存されていなければ、そのままもう一度押してください（二重には登録されません）」と出し、入力を残したまま最新の状態を読み直す |
| 送り直し | 同じ送信の番号で送る |

### 11.4 確認の表示

提出、取り下げ、削除、確認完了、項目の無効化、すべての端末からのログアウトの前に「はい／いいえ」を出す。「いいえ」と Esc では何も送らず、入力もそのまま残す。

### 11.5 画面の共通の配置（スマートフォン）

```text
┌──────────────────────────┐
│ 月次報告      [≡ メニュー] │ ← ヘッダー（ホームへ戻る）
├──────────────────────────┤
│ （メッセージ）              │
│                          │
│ 本文（1 列）               │
│                          │
├──────────────────────────┤
│ [ 主な操作のボタン ]        │ ← 画面の下に固定
└──────────────────────────┘
```

- 幅 360px で横にスクロールしない。ボタンの高さは 44px 以上。
- 機密区分の印: 社外秘は「社外秘」、限定は「限定」の小さな札を項目名の横に出す。
- メニューに出すのは、その人の役割で使える画面だけ。

## 13. 記録（access_logs）

| 操作 | `action` | `target` の例 |
|---|---|---|
| 報告を開いた（本人以外） | `view` | `report:123` |
| 臨時の調査の回答を開いた | `view` | `survey:5:responses` |
| 出力した | `export` | `export:report;period=2026-11;dept=2;format=xlsx` |

- 中身（報告の値、コメント、パスワード、コード）は記録しない。
- 本人が自分の報告を開いたときは記録しない（件数を抑えるため）。

## 14. 稼働の確認（health.php）

- ログイン不要。DB に `SELECT 1` を流し、成功なら `200 OK` と本文 `ok`、失敗なら `503` と本文 `ng` だけを返す。
- バージョン、件数、エラーの詳細は返さない。
