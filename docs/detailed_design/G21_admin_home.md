# G-21 管理のトップと管理画面の道しるべ

| 項目 | 内容 |
|---|---|
| URL | `/admin/index.php`（GET） |
| ファイル | `app/pages/admin_home.php`、`app/views/admin_home.php`、`app/views/layout.php`（道しるべ）、`app/lib/html.php`（`ADMIN_SECTION_PATH_BY_TEMPLATE`） |
| 利用者 | 管理の画面（メニューの見出し「管理」）を 1 つ以上使える人（管理者・課長・項目管理者・確認者） |
| 主な端末 | PC |
| 段階 | 3 |

---

## 1. 目的

管理画面を、画面の並びと入力の流れから見直す。管理の仕事を 1 か所から始められ、どの管理画面にいるかが分かり、管理画面どうしを行き来しやすくする。

## 2. 表示の条件と権限

- 開けるのは、メニューの見出し「管理」の画面を 1 つ以上使える人。ない人は 403。カードには、その人が使える管理の画面だけを出す。
- 報告の中身は出さない（件数だけ）。

## 3. 管理のトップ

管理の画面ごとにカードを並べる。押すとその画面へ。カードには説明と、今の状態の札を出す。対応が要るものは目立つ札にする。

| カード | 説明 | 状態の札 |
|---|---|---|
| 項目マスタ | 報告の様式（共通の項目・課の項目・選択肢・課ごとの選択肢） | 有効な項目の数 |
| コメントの定型文 | コメントで選んで使う定型文 | 自分の定型文の数 |
| メッセージ | 画面に出す文言（全体で 1 つ） | 変えた文言の数 |
| 要望・依頼 | 課長・確認者からの改善要望・対応依頼・不具合・質問（G-22） | 未受付の数（あれば目立つ札）、返信待ちの数（目立つ札） |
| 案件の管理 | 案件コードと社内向けの呼び名。案件台帳との突き合わせ用の CSV | 有効な案件の数 |
| 組織・ユーザー | 課・班・ユーザー・確認者・組織の一括の入れ替え（CSV） | 有効な課・ユーザーの数。目立つ札: 課長がいない課、2 段階認証が未設定の人、ロック中の人 |
| 記録・削除データ | 閲覧・出力・管理の操作の記録と、削除データ | 今日の記録の数（補佐はログインと管理の操作の数）、戻せる削除データの数。目立つ札: ログインの失敗（直近 24 時間）の数、管理者には補佐の操作（直近 7 日）の数 |
| 課の管理 | 自分の課の締め日・管理の仕方・確認者・チェックする人・項目管理者・班（課長だけ。G-23） | 管理する課の数 |

メニューの見出し「管理」の先頭に「管理のトップ」を出す。

## 4. 管理画面の道しるべ（すべての管理画面）

管理画面（項目マスタ・課ごとの選択肢・項目の編集・プレビュー・コメントの定型文・メッセージ・案件の管理・組織・ユーザー・ユーザーの編集・記録・削除データ・管理のトップ）の上に、共通の道しるべを出す（`layout.php`。テンプレートの名前から区分を決める `ADMIN_SECTION_PATH_BY_TEMPLATE`）。

| 部品 | 内容 |
|---|---|
| パンくず | 「管理 › （区分） › （この画面の題名）」。区分の画面では題名を省く |
| 管理画面の切り替え | メニューの「管理」の画面を丸い札で並べ、今の区分を目立たせる |
| 幅 | 管理画面は本文の幅を広げる（PC で表が見やすいように） |

## 5. ページの中のタブ

長い画面は節に分け、JavaScript が動くときはページの中のタブで 1 つずつ出す（`.tabbed-sections` の中の `section[data-tab-title]`）。JavaScript が動かないときは全部を並べる。

- 最初に出す節: URL の `#節の id`、なければ入力の誤りがある節、なければ最初の節。タブを押すと URL の `#` を変える（再読み込みしても同じ節）。
- 保存のあとは、その節の `#` 付きの URL に戻す。
- 使っている画面: 組織・ユーザーの課の編集（基本・確認者・班・引き継ぎ。G-14）。

## 6. 検証の観点

- 管理者・課長は管理のトップを開け、使える管理の画面のカードだけが出る。部下は 403。メニューの先頭に「管理のトップ」（`smoke_features.py`）。
- 管理画面に道しるべと切り替えが出る（`smoke_features.py`・`ui_check.py`）。
- 課の編集は節のタブに分かれ、押すとその節が出る（`ui_check.py`）。

## 7. システムの状態（便利機能 F・H。管理者・補佐）

管理のトップのカードの上に「システムの状態」を出す。

| 項目 | 内容 |
|---|---|
| DB の大きさ | DB のファイル（と `-wal`）の大きさ |
| 最後のバックアップ | 設定 `backup_dir` の `*.sqlite` のうち一番新しいものの日時と個数。`backup_warn_days`（7 日）より古いか無ければ目立つ札と「`php app/bin/backup.php` を動かして作る」案内 |
| バックアップの道具 | `php app/bin/backup.php`: `VACUUM INTO` で `reports_<日時>.sqlite` を作り、この道具が作ったものを `backup_keep`（14 個）まで減らす（移行の前の写しなど、ほかのファイルは消さない）。さくらのレンタルサーバーでは定期実行に登録する |
| メンテナンス | 「メンテナンス中にする」（終わる日時（7 日以内）・一言（100 文字））と「メンテナンスを終える」（確認の表示のあと）。`app_state` の `maintenance`。記録 `admin maintenance:start:<日時>|end` |

**メンテナンス中**（`app/lib/maintenance.php`）

- 全員の画面の上に知らせを出す（管理者・補佐には「ほかの人は保存などの操作ができません」、ほかの人には「メンテナンス中です（〜まで）。この間は保存などの操作ができません。入力中の内容は、終わってから保存してください。」と一言）。
- 管理者・補佐以外の人の保存などの操作（ログインが要る画面の POST）は 503（`page_start()`）。画面では JavaScript が保存などのボタンを止め、下書きの自動保存も止める（入力は残る）。ログイン・ログアウトは止めない。
- 終わる日時を過ぎると自動で終わる。
- 予約した組織の改訂（G-14 §6.8）は、メンテナンス中は反映しない。

**組織の改訂の予約**（便利機能 G）: 「組織・ユーザー」のカードに次の予約の日、30 日以内に反映できなかった予約の数（目立つ札）を出す。
