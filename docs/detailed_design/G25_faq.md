# G-25 よくある質問（便利機能 J）

| 項目 | 内容 |

## 1. 目的

使い方でよく聞かれることと答えを、全員が見られるようにする。

## 2. 表示と操作

| 項目 | 内容 |
|---|---|
| 一覧 | 質問を並び順に出し、押すと答えが開く。管理者側には「直す」「↑」「↓」「消す」 |
| 載せる | 分野（§2.3）、質問（必須・200 文字）、答え（必須・2,000 文字・改行可）。500 件まで（`FAQ_MAX_COUNT`。2026-11-20 に 200 件から引き上げ） |
| すべての質問 | 「すべての質問（n 件）」の下に、分野ごとの見出し（件数）で分けて出す。「↑」「↓」は同じ分野の中で入れ替える |
| 要望・依頼から | 種類が「質問」で閉じた要望・依頼の詳細（管理者側）に「よくある質問に載せる」。もとの要望の番号だけを残し、質問と答えは管理者側が書き直す（出した人の文や名前は出さない） |
| 部下・確認者の操作 | 載せる・直す・消すは 403 |
| 記録 | `admin faq:<ID>:create|update|delete` |

テーブル `faq_entries`（DB 編）。各画面の「？ この画面の使い方」からも開ける（共通編）。そのときは画面の番号と開いていた画面を付けて開き、§2.2 で送る質問に入れる。

### 2.1 チャットで知りたいことを入れて探す（AI は使わない）

画面の上にチャットの枠（吹き出しの並びと、下に入力の欄「知りたいことを入れる」（200 文字まで）と「送る」）。その下に「すべての質問」。自動の答えは、よくある質問に載っている質問と答えの文だけ（文を作らない）。

| 場面 | チャットの表示（`app.js`。文言は G-17 で変えられる） |
|---|---|
| 開いたとき | 「こんにちは。知りたいことを入れてください。よくある質問から近い答えを探します。（例: …）」 |
| 入れた | 入れた文を右の吹き出し。`/faq.php?format=json&q=` に聞く（返すのは近い質問の番号・質問・答え） |
| 見つかった | いちばん近い質問と答えを左の吹き出し。ほかにもあれば「ほかに近い質問もあります。押すと答えを出します。」と質問のボタン（押すとその答え）と「この中にない」。続けて「解決した」「解決しない」のボタン。解決した → チャットを開いたときと同じ状態に戻す（最初の吹き出しと分野のボタンだけにし、入力欄を空にする。サーバーは会話を終え、次の発言は新しい会話） |
| 見つからない | 課長・確認者: 「近い質問は見つかりませんでした。言葉を変えて入れるか、質問として送ってください。」と「言葉を変えて入れる」「質問として送る」。ほかの人: 「…言葉を変えて入れてみてください。」と §2.2 の案内、「言葉を変えて入れる」 |
| 解決しない・この中にない・質問として送る | §2.2 の欄（課長・確認者）か案内（ほか）を吹き出しで出す |

JavaScript が無いときは、入れて「送る」で `?q=` の画面を開き直し、同じ吹き出し（入れた文、近い質問と答え、§2.2）をサーバーで出す。

| 手順 | 内容（`faq_search()`） |
|---|---|
| そろえる | 全角の英数字・記号を半角に、英字を小文字に、記号と空白を 1 つの空白にする（`faq_normalize_text()`。mbstring が無くても動く）。半角カナは全角カナに（`faq_halfwidth_kana_map()`）、日本語の文字の間の空白は詰める（「ログイン　できない」「パスワードを、忘れました」）。言い換えの表は、数字を除く前の文で見る（「404」「500」） |
| 言い換え | 入れた文に `FAQ_SEARCH_SYNONYMS` の左の言葉があれば、右の言葉でも探す（例: スマホ → スマートフォン、締切 → 締め日、修正 → 直す、エクセル → csv 出力）。表はコードで持つ（足すときは `notice.php`） |
| 言葉に分ける | 英数字はひと続きで 1 語（2 文字以上）。英数字の言葉は単語として当てる（前後が英数字でないところだけ。「ip」が「iphone」に、「then」が「authenticator」に当たらない。`faq_text_contains_term()`）。日本語は 2 文字ずつの並び。ただし、ひらがなで始まる並び（「の人」「を機」）と、助詞（は・が・を・に・の・で・と・も・へ・や）で終わる並び（「日は」「面が」）は、言葉の区切りをまたぐので使わない（「忘れ」「直せ」のような送り仮名の並びは使う）。漢字・カタカナ 1 文字だけのときはその 1 文字 |
| 近さ | 言葉ごとに、質問に当たれば 2 点、答えだけに当たれば 1 点。満点（言葉の数 × 2）に対する割合が 0.25 以上のものを、近い順に出す。同じ近さなら、質問の文の言葉のうち入れた文にもある割合が大きいほう（質問の文そのものを入れたら、その質問）、それも同じなら並び順 |

見つからないときは「近い質問は見つかりませんでした。言葉を変えて探すか、下から質問してください。」

### 2.2 見つからない質問を送る（自動で起票する）

| 人 | 表示 |
|---|---|
| 課長・確認者（`support_request_can_submit()`） | 説明と、入れた文を入れておいた質問の欄（2,000 文字まで。補足を書き足せる）と「質問として送る」。探す前から隠して置いておき、チャットで出す |
| 部下 | 「課長・確認者（課長代理・主任）に聞いてください。…」（送る欄は出さない。K-044・K-048） |
| 管理者・補佐（確認者でない） | 「システム管理者・補佐は質問を受ける側のため、ここからは送れません。…」 |

「質問として送る」は、画面を読み込み直さずに送る（JavaScript。`Accept: application/json`）。入力の誤り（空白だけ・続いている要望・依頼が多い など）は `{"ok": false, "reason": "invalid", "errors": [...]}` で返し、送る欄の上に出す（チャットのやり取りと入れた文は残る）。送れたら `{"ok": true, "redirect": <要望・依頼の画面>}` で、その画面へ移る（送信の番号は `rk_mark_done()` で完了にする）。つながらないときは、その旨を出して送り直せるようにする（送信の番号は変えない。届いていたときに二重に作らない）。JavaScript が無いときは、これまでどおり画面を作り直して誤りを出す（2026-11-18。他の端末で「入力の誤りを出すと、これまでのやり取りが消える」と指摘があった）。

送ると、要望・依頼（G-22）を 1 件出す（G-22 §6.1 と同じ処理・確かめ。続いているものが 30 件なら出せない）。

| 項目 | 値 |
|---|---|
| 種類・急ぎ | 質問・通常 |
| 件名 | 質問の最初の行（60 文字を超えれば 59 文字＋「…」。`faq_question_title()`） |
| 内容 | 質問の全文 |
| 関係する画面・開いていた画面 | 「この画面の使い方」から来たときの画面の番号と、開いていた画面（G-22 §4 の決まった項目だけ）。ほかは指定しない |

送ったら要望・依頼の詳細へ移り「質問をシステム管理者に送りました。返信があると、ホームに出ます」。空なら「質問を入れてください」。部下が送ると 403。記録は `admin support_request:<ID>:create`。管理者側は答えたあと、閉じた詳細の「よくある質問に載せる」で載せる（§2）。

### 2.3 分野と、曖昧な質問の聞き返し（AI は使わない）

`faq_entries.category`（DB 編）に分野を持つ（`FAQ_CATEGORY_LABELS`）。

| コード | 分野 |
|---|---|
| `about` | このシステムについて（概要・目的、システム管理者・補佐はだれか、開発者・問い合わせ先、役割、1 か月の流れ、ほしい機能がない、使える時間） |
| `login` | ログイン・パスワード・2 段階認証 |
| `report` | 報告の作成・提出 |
| `comment` | コメント・返信 |
| `review` | 報告の確認・チェック（確認者・課長） |
| `status` | 提出状況・横並び・検索・出力 |
| `survey` | 臨時の調査 |
| `account` | アカウント設定・画面の表示 |
| `request` | 要望・依頼・よくある質問 |
| `department` | 課の管理・項目（課長） |
| `admin` | システムの管理（管理者・補佐）。**システム管理者・補佐にだけ見せる**（`FAQ_STAFF_ONLY_CATEGORIES`・`faq_visible_entries()`。ほかの人には、チャットの答え・分野のボタン・すべての質問の一覧のどこにも出さない） |
| `device` | スマートフォン・PC・ブラウザー |
| （空） | そのほか |

- チャットの最初に、質問のある分野のボタン（「分野（件数）」）を出す。「この画面の使い方」から来たときは、その画面の分野（`FAQ_CATEGORY_BY_SCREEN`）を「開いていた画面の質問は「…」にあります。」と知らせ、ボタンを太くする。
- **曖昧な質問**: 言い換えの表（`FAQ_SEARCH_SYNONYMS`）にある言葉（概要・開発者・添付・余白など）が入っていれば曖昧としない（「このシステムは何するもの？」を聞き返さない）。そのうえで、入れた文から中身のない言い方（`FAQ_VAGUE_WORDS`。使い方・わからない・教えて・困った・どうすれば・できない・システム・画面 など）を除くと探す言葉が残らないとき（`faq_is_vague()`）は、答えを探さず「どのことについて知りたいですか？　分野を選ぶか、「パスワード」「提出」「コメント」のように、知りたいことの言葉を入れてください。」と分野のボタンを出す。例: 「使い方がわからない」「教えて」「困った」は聞き返す。「ログインできない」「報告の使い方」は「ログイン」「報告」が残るので探す。
- 分野を選ぶと「「（分野）」の質問です。近いものを選んでください。」と、その分野の質問のボタン（並び順）と「この中にない」を出す。選ぶと答えと「解決した」「解決しない」。「この中にない」は §2.2。
- 見つからないときにも「分野から選ぶ」を出す。
- 押した分野のボタンは押した見た目（枠）にする。最初の分野の並びは何度でも押せるが、押した見た目は**最後に押した 1 つだけ**に付け、前に押したボタンは押す前の見た目に戻す（チャットの中のすべての分野のボタンで 1 つだけ。`aria-current` も同じ）。
- JavaScript が無いときは、分野のボタンは `?category=` へのリンクで、開き直すと分野の質問を吹き出しの中に出す。

### 2.4 標準のよくある質問

`app/lib/faq_standard.php` の `FAQ_STANDARD_ENTRIES`（分野・質問・答え）に、（**答えにはシステムの内部の情報（コマンド・ファイルの場所・鍵やパスワードの置き場所など）を書かない**。検証で確かめる）操作マニュアルの全章と基本設計書の概要から想定される質問をまとめて持つ（160 件）。チャットの記録（§2.7）で答えられなかったシステムの質問は、ここに足していく。リポジトリで管理し、操作や画面を変えたときは操作マニュアルと一緒に直す。

- 管理者・補佐には「すべての質問」の下に「標準のよくある質問を取り込む（まだ載っていない n 件）」を出す（確認の表示のあと）。押すと、同じ質問の文が載っていないものだけを分野つきで足す（200 件まで）。すべて載っていれば「標準のよくある質問は、すべて載っています。」
- 取り込んだあとは、画面で直す・消すことができる。
- 標準の答え・分野が新しい版で変わったときは、取り込みで、管理者が画面で一度も直していない行（作った日時と直した日時が同じ）だけ答え・分野を新しくする（`faq_standard_updatable_rows()`。2026-11-18）。管理者が直した答えは変えない。ボタンは「（まだ載っていない n 件・答えの直し m 件）」で、どちらかが 1 件以上のときに出す。取り込んだ・新しくした行は、作った日時と直した日時を同じにしておく（次の版でも新しくできる）。
- 記録 `admin faq:import_standard;added=<足した件数>;updated=<新しくした件数>`。
- 検証: 標準の質問は、その質問の文で探すといちばん上に出ること（取り違えがないこと）を確かめる。

### 2.6 システムに関係のない質問・不適切な表現（AI は使わない）

判定の順（分野を選んだときは `faq_answer_chat()`、入れた文は `faq_classify_question()`（`app/lib/notice.php`）。自動入力検証（§3）も同じ関数を使う）: 分野を選んだ → 命・体の緊急の状態（§2.12） → 心の不調らしい文（§2.8） → 自分の退職（§2.10） → 要配慮個人情報に触れる文（§2.9） → 人への暴力を書いた文 → 不適切な表現 → 呼びかけだけの文 → 曖昧な質問 → 関係のない質問 → 近い質問を探す。

**日本語以外の言葉の文**（`faq_is_foreign_language()`）: 次の文は、断らずに標準のよくある質問「英語など、日本語以外で表示できるか（言語）」を答える（画面とチャットは日本語だけで、ほかの言葉で使いたいときは要望・依頼で伝えてもらう。日本語以外で聞かれたときだけ、答えの頭に「質問は日本語で入れてください。」と英語の同じ文を付ける。日本語で言語を聞いた人には付けない。ただし日本語で書かれていても、日本語が分からない・読めない・苦手と書かれたときは、英語の案内（日本語だけであること・課長や同僚に助けてもらうこと）を答えの頭に付ける。仮設定 K-060）。① ラテン文字だけで、言葉が 2 つ以上でよく使う英語の言葉（`FAQ_ENGLISH_COMMON_WORDS`。who・what・can・is・account・settings など）がある文か、言葉が 3 つ以上で「?」で終わる文（「Who is the system administrator?」「account settings」、フィジー語・ドイツ語などの問い）。② かなが無く、ハングル・デーヴァナーガリー・タイ文字・アラビア文字・キリル文字などがある文。③ かなが無く、中国語の言い回し（`FAQ_CHINESE_ONLY_WORDS`。可以・我的・嗎・顯示 など）がある文。判定の順は、用件なしの文のあと・会社の決まりの前。指示を引き出そうとする入力（英語の prompt・ignore previous なども含む）は今までどおり断る。「PDF」「excel csv」「Hello World!」のような短い英字と、漢字だけの日本語（「臨時調査」「目的」）は当たらない。台湾語・英語・外国語などの言語を聞く日本語の文も同じ答えに向ける（「英語に翻訳して」は翻訳の依頼なので断る）。

**無理な要求・皮肉の文**: 謝罪・誠意・納得できる・責任者・補償・特別扱い・例外的・私の要求・お客様は神様・頭を下げ・上座・同じ間違い など（`FAQ_COMPLAINT_WORDS`）があり、システムの言葉（`FAQ_COMPLAINT_SYSTEM_NOUNS`。報告・ログイン・パスワード・コメント・画面・認証・下書き・提出・調査・テーマ・出力・CSV・項目・案件・エラー）が無い文は、関係のない質問として断る（`faq_is_complaint()`。他の端末の確かめで、ことわざ・聖書・劇になぞらえた要求の文が「要望」「担当者」「お客様」「言語」などの言葉で、要望・依頼やシステム管理者の名前、黄色の注意、言語の答えに当たっていた）。

**休暇だけの文**: 「休暇」「特別休暇」「休み」などだけの文は、会社の決まりとして見つからない（課長・確認者への相談の案内）にする（忌引の答えに当てない）。

**前置き・結びのあいさつ**: 判定の前に、文の頭の前置き（すみません・すいません・恐れ入ります・失礼します・あの・あのー・えっと など。読点・空白などの区切りが続くときだけ。「あのボタン」の「あの」は外さない）と、文の終わりの結びのあいさつ（よろしくお願いします・よろしくお願いいたします など）を外す（`faq_strip_courtesy()`）。付けても知りたいことは変わらないため（「PDF。よろしくお願いします。」を断らない、「すみません、ワード」をパスワードに当てない）。外すと何も残らない文（「すみません」「よろしくお願いします」だけ）は外さずに判定する。記録には入れたままの文を残す。

**不適切な表現**: 不適切な言葉（`FAQ_ABUSIVE_WORDS`。バカ・死ね・無能・役立たず・ポンコツ・黙れ・クソ・ふざけるな など）が入っていれば（`faq_is_abusive()`）、システムの言葉があっても答えず、「不適切な表現が含まれているため、返答できません。」（G-17 で変えられる）。ふつうの文に紛れる言葉（「ばかり」の「ばか」、「カスタム」の「カス」、「ところすでに」の「ころす」など）は表に入れない。続いた回数は、関係のない質問と合わせて数える（下の「続いたとき」）。

**機能をやめたいの「辞めたい」**: 機能の言葉（`FAQ_FEATURE_OBJECT_WORDS`。2 段階認証・ログイン・パスワード・設定・テーマ・通知 など）と一緒の「辞めたい」（「2 段階認証を辞めたい」）は、心の不調・退職の言葉として扱わない（`faq_strip_feature_quitting()`）。仕事・会社を辞める話の言葉（`FAQ_JOB_QUITTING_WORDS`）があれば今までどおり。

**上司からのハラスメント**: 心の不調らしい文のうち、上の立場の人の言葉（`FAQ_SUPERIOR_WORDS`。上司・課長・部長・先輩 など）とハラスメントの言葉（`FAQ_HARASSMENT_WORDS`。パワハラ・セクハラ・怒鳴られ・嫌がらせ など）の両方がある文（`faq_is_harassment_by_superior()`）には、「上司に相談して」とは返さず、「つらい思いを書いてくれて、ありがとうございます。上司からのハラスメントは、その上司ではなく、ほかの管理職（別の課長・部長など）や、会社の相談窓口に相談してください。一人で抱え込まないでください。」と返す（命に関わる言葉もあれば「今すぐ危ないと感じるときは…」を続ける。G-17 で変えられる。2026-11-17 指示）。知らせは心の不調と同じ（システム管理者だけ）。

**人への暴力を書いた文**: 人への暴力の言葉（`FAQ_VIOLENCE_WORDS`。殴・蹴りたい・刺してやる・殺してやる・火をつけ・締め上げ・怒鳴ってしまった など。どなられた側の「怒鳴られ」は心の不調の心配な言葉で扱う。`faq_is_violent()`）が入っていれば、答えは出さず、カウンセリングを受けることをすすめる（「強い怒りや、人を傷つけたい気持ちを一人で抱えていませんか。カウンセラーや、会社の相談窓口・産業医など、話を聞いてもらえるところで、カウンセリングを受けることをおすすめします。…」。G-17 で変えられる）。断った回数には数えない（いつでも返事をする）。記録の結果は「不適切な表現」、知らせる理由は `violence`（人への暴力を書いた文）で、システム管理者と補佐のホーム・管理のトップ・記録の画面に知らせる（職場の安全のため。2026-11-17 指示）。補佐も「対応した」を押せる。「ハチに刺された」などは先に緊急として扱う。

**ひらがなだけの文**: ひらがなだけで、探す言葉が 1 つも取れない文（方言・話し言葉の「いってこうわい」「そうなんよ」など）は、断らずに分野を選んでもらう（関係のない話題の言葉があれば断る）。ひらがなの悪口（`FAQ_WHOLE_INPUT_ABUSIVE_WORDS`。ばか・あほ・きも など）は、文全体がその言葉のときだけ不適切な表現とする（「エラーばかり出る」に当たらないように）。

**会社の決まりの質問**: 勤務時間・手当など会社の決まりの言葉（`FAQ_COMPANY_POLICY_WORDS`）がある質問は、よくある質問では答えられないので「見つからない」として、課長・確認者への相談・質問として送る案内を出す（`faq_is_company_policy_question()`）。

**答えが違う、という言い方**: 「ちゃうちゃう」「違います」「そうじゃない」だけの文は、「チャットの答えが質問と合っていない（ちぐはぐ）」を答える（`FAQ_WHOLE_INPUT_SYNONYMS`）。方言のあいづち（じゃけん など）・答えが違う、には前の話題を補わない（`FAQ_CLARIFICATION_PHRASES`）。

**1 文字だけの入力**: 「は」「わ」のような 1 文字だけの入力は、打ち間違い・途中で送ったものとみなし、曖昧な質問として分野を選んでもらう（断らない。断った回数にも数えない）。

**返事を求めるだけの文**: 「はい？」「どういうこと？」「返答して」のように、中身のない言い方（`FAQ_VAGUE_WORDS`）だけでできた文は、言い換えの表に当たっても曖昧な質問として分野を選んでもらう（断らない）。

**用件がない文**: 「用件なし」「特にない」「なんでもない」「大丈夫です」「結構です」など（`FAQ_CLOSING_PHRASES`。記号と空白を除いた文がこれと同じときだけ。`faq_is_closing()`）には、聞き返さずに「わかりました。知りたいことがあるときは、いつでも入れてください。」と返す（G-17 で変えられる）。断らない。記録では「あいまい」。前の話題は持ち越さない。

**呼びかけだけの文**: 用件の無い「大変です」「大変」「たいへんです」など（`FAQ_OPENER_PHRASES`）と、「大変」で始まり、あとに用件の無い言い方（`FAQ_OPENER_TRAILING_WORDS`。「大変なのです」「大変でした」「大変困惑」「大変なことになった」）だけの文（`faq_is_opener()`）には、「どういったご用件でしょうか。」と返す（G-17 で変えられる）。断らず、断った回数にも数えない。記録では「あいまい」として残す。用件があれば（「大変です、ログインできません」）ふつうに答えを探す。

**関係のない質問**:


| 項目 | 内容 |
|---|---|
| 判定（`faq_is_unrelated()`） | 曖昧な質問でなく、システムの言葉（`FAQ_SYSTEM_WORDS`。エラー・表示・真っ白・固まる・動かない・保存・入力・ボタン・報告・画面・修正・削除・設定 など）が入っておらず、入れた文の言葉のうち、よくある質問の文（標準の質問と載っている質問）・分野の名前・システムの言葉に出てくる割合が 0.5 以下で、いちばん近い質問の近さも 0.5 以下のとき（`FAQ_UNRELATED_MAX_RATIO`）。言葉が 1 つも取れない文（「1+1は」「あなたは誰」）も関係のない質問とする |
| 関係のない話題の言葉 | 明らかにシステムと関係のない話題の言葉（`FAQ_OFFTOPIC_WORDS`。天気・ラーメン・料理・野球・株価・宝くじ・翻訳・Python・コードを書 など）が入り、システムの言葉が無ければ、関係のない質問とする。2 文字の並びがたまたま当たる（「ラーメン」が「コメント」に、「Python のコード」が「予備のコード」に）のを防ぐ |
| 関係のない話題の強い言葉 | `FAQ_OFFTOPIC_STRONG_WORDS`（Wi-Fi・プリンター・Teams・有給・人事・扶養・住所・年末調整・給与）は、システムの言葉（「パスワード」など）があっても関係のない質問とする（「社内の Wi-Fi のパスワード」） |
| 例 | 関係のない質問: 明日の天気は？／おすすめの映画を教えて／野球の結果／有給休暇の申請方法／経費精算したい。システムの質問: ログインできない／修正したい／画面が真っ白／動かない／スマホ変えた |
| 返事 | 「その質問には返答できません。」（G-17 で変えられる）。近い質問・送る欄（§2.2）は出さない |
| 続いたとき | 関係のない質問か不適切な表現が、合わせて 5 回続くと（`FAQ_UNRELATED_IGNORE_COUNT`）、5 回目から返事をしない（入れた文の吹き出しだけが出る）。数えるのはサーバーのセッション（`faq_count_unrelated()`。画面を開き直しても数え直さない。ログインし直すと 0）。システムの質問（曖昧な質問を含む）をするか、分野を選ぶと 0 に戻り、また返事をする |
| JavaScript が無いとき | `?q=` の画面でも同じに判定・数える（返事をしないときは、入れた文の吹き出しだけ） |
| JSON | `{"ok": true, "log_id": 12, "result": "unrelated", "vague": false, "unrelated": true, "abusive": false, "ignored": false, "matches": []}`（`result` は matched・no_match・vague・unrelated・abusive・category） |

### 2.7 チャットの記録（よくある質問の改善のため）

聞かれた質問と返した答えを、操作の記録（`access_logs`）とは別の表 `faq_chat_logs`（DB 編）に残す（`app/lib/faq_chat_log.php`）。

| 項目 | 内容 |
|---|---|
| 残すもの | 日時、聞いた人（`user_id`。不適切な表現への対応のため。K-051）と役割（部下・確認者・課長・管理者・補佐）、開いていた画面、質問の文（暗号化。`faq_chat:<ID>`）か選んだ分野、結果（答えた・見つからない・曖昧・関係のない質問・不適切な表現・分野を選んだ）、返事をしなかったか、出した質問の番号、反応（解決した・解決しない・質問として送った）と、どの答えへの反応か、送った要望・依頼の番号 |
| 残すとき | チャットで入れた・分野を選んだとき（JavaScript が無いときの `?q=`・`?category=` の画面も）。反応は「解決した」「解決しない」「この中にない」を押したとき（POST `action=chat_feedback`。その人のセッションで残した記録だけ。ほかは 400）と、「質問として送る」で要望・依頼を出したとき |
| 残す期間 | 1 年（新しく記録するときに、1 年より古いものを消す） |
| 表が無い DB | 画面を開いたときに無ければ作る（`faq_chat_log_ensure_table()`。`schema.php` にも載せる） |
| 操作の記録 | 質問の文は `access_logs` に残さない。記録の画面を見たことは `admin faq_chat_logs:view;days=<日数>` |

**よくある質問の記録の画面（`/admin/faq_logs.php`）**: システム管理者・補佐（メニューの見出し「管理」に「よくある質問の記録」。管理のトップにカード。7 日の答えられなかった質問の数、不適切な表現があれば目立つ札）。部下・確認者・課長は 403。

| 欄 | 内容 |
|---|---|
| 絞り込み | 期間（直近 7・30・90・365 日。既定 30 日）、結果（すべて／答えられなかったもの（見つからない・解決しない・送った）／各結果） |
| 集計 | 結果・返事をしない・反応ごとの件数（新しい 2,000 件まで） |
| 答えられなかった質問（多い順） | 同じ文をまとめて、回数・最後の日時と「よくある質問に載せる」（`/faq.php?draft_log=<記録の番号>`。質問の欄にその文、分野が分かれば分野を入れて、載せる欄を開く。管理者・補佐だけ） |

聞いた人の名前（表示名とログイン ID）は、システム管理者・補佐のどちらにも出す（K-051。補佐が個々の情報を見ない K-043 の例外）。

### 2.8 心の不調らしい文（AI は使わない。K-052）

| 項目 | 内容 |
|---|---|
| 判定（`faq_distress_level()`） | 命に関わる言葉（`FAQ_DISTRESS_URGENT_WORDS`。死にたい・消えたい・自殺・いなくなりたい・楽になりたい など）→ `urgent`。心配な言葉（`FAQ_DISTRESS_CONCERN_WORDS`。つらい・しんどい・疲れた・限界・眠れない・うつ病・怖い・助けて・パワハラ・いじめ・もう無理・辞めたい など）→ `concern`。ふつうの文に紛れる言葉（「写す」の「うつ」など）は入れない |
| 返事 | `urgent`: 「つらい気持ちを書いてくれて、ありがとうございます。一人で抱えずに、上司やシステム管理者に相談してください。今すぐ危ないと感じるときは、ためらわずに周りの人に助けを求めてください。」。`concern`: 「おつかれさまです。無理をせず、つらいときは一人で抱えずに、上司やシステム管理者に相談してください。」と、近い質問があればその答え（「助けて、ログインできない」など。心配な言葉を除いた残りの文に探す言葉が 2 つ以上あり、近さが 0.6 以上（`FAQ_DISTRESS_COMPANION_MIN_RATIO`）のときだけ出す（`faq_strip_distress_words()`・`faq_companion_matches()`。「仕事がつらい」の「仕事」1 語では出さない）。心配な言葉そのもので探すと、その言葉を書いた答えに当たるため。「会社を辞めたい」なども、退職の手続きは示さず、相談を促す言葉だけを返す（2026-11-16 指示））。どちらも G-17 で変えられる。知らせたことは返事に出さない（2026-11-16 指示）。返事をしない回数には数えない（数え直す） |
| 知らせ | ホーム（システム管理者だけ。補佐は対象外。補佐（開発担当。K-059）も対象外。K-054）に「よくある質問のチャットに、心の不調らしい文や退職に関わる質問があります（未対応 n 件。うち命に関わる言葉 n 件）。確かめて、対応してください」（目立つ札。記録の画面の欄へ）。管理のトップの「よくある質問の記録」のカードに「心の不調・退職に関わる質問（未対応） n 件」（目立つ札。システム管理者だけ）。メールは使わない |
| 記録の画面の欄 | 「心の不調・退職に関わる質問」（システム管理者だけ。補佐には欄を出さず、一覧・集計からもこの記録を除く。補佐の「対応した」は 403）: 期間にかかわらず未対応のものと、期間の中の対応済みのもの（未対応 → 命に関わる言葉 → 新しい順。200 件まで）。日時・聞いた人・段階・文・「対応した」（確認の表示のあと。対応した日時と人を残す。記録 `admin faq_chat_log:<ID>:distress_handled`）。すべて対応すると、ホームの知らせは消える |
| 本人への知らせ | 利用者に見える画面・返事・よくある質問・操作マニュアルの利用者の章には、管理者・補佐に知らせることを書かない（2026-11-16 指示） |
| 記録の列 | `faq_chat_logs.result = 'distress'`、`distress_level`（urgent・concern）、`handled_at`・`handled_by`。この列を足す前の表は、画面を開いたときに作り直して記録を写す（番号は変えない。暗号の文脈に使うため。`faq_chat_log_ensure_table()`） |

### 2.9 要配慮個人情報に触れる文（AI は使わない。K-053）

原則として、相手に寄り添う返事にする。

| 項目 | 内容 |
|---|---|
| 判定（`faq_is_sensitive()`） | 要配慮個人情報（病歴・心身の障がい・健康診断や治療・信条・人種・社会的身分・犯罪の経歴や被害など）と、それに近い個人的な事情（妊娠・出産・介護など）に触れる言葉（`FAQ_SENSITIVE_WORDS`。病気・入院・通院・手術・持病・診断・治療・がん治療・体調不良・感染・健康診断・妊娠・介護・障がい・宗教・信仰・人種・国籍・差別・性的指向・逮捕・前科・犯罪・警察・裁判 など）と、個人的な暮らしの不安（老後・将来が不安・生活が苦しい・借金・倒産・破産・リストラ・解雇）。「システム障害」の「障害」、「がんばる」の「がん」のように紛れる言葉は入れない |
| 返事 | 「大切なことを書いてくれて、ありがとうございます。体や家族のことなど、個人的な事情には、このチャットでは詳しくお答えできませんが、一人で抱えずに、上司や信頼できる人に相談してください。体の具合や病気・薬のことは、医療機関（医師）に相談してください。報告や締め日のことで困っているときは、課長に相談してください。」（G-17 で変えられる）。要配慮の言葉を除いた残りの文で、近さ 0.6 以上の質問があればその答えも出す（「入院するので報告が出せない」→ 報告を作れない・出せない）。返事をしない回数には数えない |
| 記録 | 文も記録する（暗号化。2026-11-16 指示）。ただし画面には出さない: よくある質問の記録の画面では、システム管理者・補佐とも「（要配慮の内容のため表示しません）」（`faq_chat_log_display_text()`）。答えられなかった質問・関係のない質問のまとめにも入れず、記録から「よくある質問に載せる」（`?draft_log=`）は 404。ローカル検証環境の書き出し（CSV）には文を入れる（開発担当が FAQ を直すため。本番には置かない）。前に文を記録しなかった記録は「（要配慮の内容のため、文は記録していません）」 |
| 知らせ | 管理者・補佐には知らせない。身の安全や職場での扱いに関わる被害（セクハラ・モラハラ・マタハラ・ストーカー・つきまとい・ドメスティック・暴力を受け・追い出し・干され・無視され・左遷・嫌がらせ・仕事を与えられない・恫喝・怒鳴られる・罵倒・暴言・脅される・威圧）は、心の不調らしい文（§2.8）の心配な言葉として知らせる |
| 記録の表 | 結果の種類が増えるたびに、古い表は画面を開いたときに作り直し、共通の列の記録を写す（`FAQ_CHAT_LOG_SCHEMA_MARK`） |

### 2.10 退職に関わる質問（K-054）

| 項目 | 内容 |
|---|---|
| 判定（`faq_is_retirement()`） | 退職・辞め・辞職・退社・離職（`FAQ_RETIREMENT_WORDS`） |
| 返事 | 自分の退職（部下・課員・担当・前任・後任・補佐・同僚・先輩・後輩など、ほかの人のことでない。`faq_is_about_subordinate()`）: 手続きは示さず「大切なことを書いてくれて、ありがとうございます。退職のことは、一人で抱えたり決めたりせず、まず上司（課長）に相談してください。気持ちや事情を話すことで、ほかの道が見つかることもあります。」（結果 `retirement`。G-17 で変えられる。2026-11-16 指示）。部下の退職（「部下が退職した。どうすればいい？」など）: 手続きの答え。「辞めたい」など気持ちの文は、心の不調らしい文（§2.8。相談を促すだけ） |
| 知らせ | システム管理者に知らせる（補佐は対象外。`faq_chat_logs.distress_level = 'retirement'`。心の不調らしい文と同じく、ホーム・管理のトップ・記録の画面の「心の不調・退職に関わる質問」の欄。「対応した」を押せる）。要配慮個人情報に触れる文（§2.9）は、退職に関わるものだけ知らせ（文は記録しない）、ほかは知らせない |

### 2.11 チャットの問い合わせの失敗（「通信エラー」）

| 項目 | 内容 |
|---|---|
| ログインが切れているとき | JSON を求める要求（`is_json_request()`。`?format=json` か Accept: application/json）は、ログインの画面に転送せず `{"ok": false, "reason": "login"}`（401）を返し、`app.log` に「WARN JSON の問い合わせで、ログインが切れていた: <パス>」を残す（パスだけ。質問の文は残さない）。チャットは「ログインの有効期限が切れました。画面を開き直して、もう一度ログインしてください。」 |
| エラーのとき | JSON を求める要求には、エラーの画面でなく `{"ok": false, "reason": "error", "status": <コード>}` を返す（`error_page()`）。500 は例外の処理が `app.log` に中身を残す。ほかは「WARN JSON の問い合わせのエラー <コード>: <パス>」 |
| 答えが読めなかったとき | 何が起きたかで文を分け（下）、「もう一度送る」を出す。POST `action=chat_client_error`（kind = not_json・not_ok・network・timeout）で `app.log` に「WARN よくある質問のチャットの問い合わせに失敗」を残す（サーバーに届かないときは残せない） |

| もう一度送る | 同じ質問（または同じ分野）を、入れ直さずにもう一度問い合わせる。記録は送るたびに 1 行できる |
| 数字の言葉 | 2 けた以上の数字（「10」「2026」など）は、配列のキーにすると整数に変わるので、探す言葉は文字列に戻す（`faq_search_terms()`）。戻さないと止まって「通信エラー」になっていた |

## 3. 検証の観点

**自動入力検証**（`tools/test/faq_input_check.php`。自動検証 `verify_all.py` の工程「よくある質問の自動入力検証」）: `tools/test/faq_input_cases.tsv` の入力を 3 つに分け、チャットと同じ判定（`faq_classify_question()`）にかける。判定に使うのは、標準のよくある質問をふつうの利用者に見える範囲にしたもの（DB・サーバーは使わない）。

| 区分 | 確かめること |
|---|---|
| 寄る（システムにはっきり寄る） | 答えること。いちばんの答えが決めた質問であること（言い換え・言い間違いを含む） |
| グレー（グレーゾーン） | 決めた範囲（答える・聞き返す・見つからない・断る）に入っていること。結果の内訳も出す |
| アウト（明確にアウト） | 関係のない質問・不適切な表現・緊急・心の不調・退職・要配慮として扱い、ふつうの答えを出さないこと。ID・パスワードを求める質問は管理者への知らせ |

### 2.15 解決しないとき（解決に近づける道筋。2026-11-17 指示）

「解決しない」を押したとき、そこで話を終えない。次の順で、解決に近づける。

| 段 | 内容 |
|---|---|
| 1. 関係がありそうな質問 | 「お役に立てず、すみません。関係がありそうな質問です。近いものはありますか？」と、関係がありそうな質問のボタン（最大 `FAQ_RELATED_MAX_COUNT` 件）と「この中にない」。答えた質問の文で近い質問を探し、足りなければ同じ分野の質問で補う（`faq_related_entries()`。`?format=json&related=<番号>&exclude=<この会話で出した番号>`。見せてよい質問だけ。記録には残さない）。選ぶと答えと「解決した」「解決しない」（解決しないなら、また 1. から。出した質問は除く） |
| 2. 詳しく聞き直す | 関係がありそうな質問が無い・「この中にない」を押したとき（最初の候補の「この中にない」も）: 「困っていることを、もう少し詳しく教えてください。「どの画面で」「何をしようとして」「どうなったか（出た文など）」を入れると、近い答えを探しやすくなります。」と、「詳しく入れ直す」（入れた文を入力欄に戻す）・「分野から選ぶ」・「質問として送る」（課長・確認者。ほかの人は「だれに聞けばよいか」で案内） |
