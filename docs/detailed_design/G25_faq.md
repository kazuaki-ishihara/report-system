# G-25 よくある質問（便利機能 J）

| 項目 | 内容 |
|---|---|
| URL | `/faq.php`（GET・POST）、`/admin/faq_logs.php`（GET。よくある質問の記録。§2.7）。`?q=<知りたいこと>` で探す（`&format=json` でチャットの答え）、`?category=<分野>` で分野の質問（`&format=json` も）、`?screen=<画面の番号>&from=<開いていた画面>`（「この画面の使い方」から来たとき）、`?edit=<ID>` で直す、`?request=<要望ID>` で要望・依頼の質問から載せる |
| ファイル | `app/pages/faq.php`、`app/views/faq.php`、`app/pages/admin_faq_logs.php`、`app/views/admin_faq_logs.php`、`app/lib/faq_chat_log.php`（チャットの記録）、`app/lib/faq_standard.php`（標準のよくある質問）、`app/lib/notice.php`（探す: `faq_search()`）、`app/lib/support_request.php`（送る: `support_request_validate()`・`support_request_create()`） |
| 利用者 | 見る・探す: 全員（メニューの見出し「アカウント」に「よくある質問」）。見つからない質問を送る: 課長・確認者（G-22 で出せる人）。書く・直す・消す・並べ替える: システム管理者・補佐 |
| 段階 | 3 |

---

## 1. 目的

使い方でよく聞かれることと答えを、全員が見られるようにする。

## 2. 表示と操作

| 項目 | 内容 |
|---|---|
| 一覧 | 質問を並び順に出し、押すと答えが開く。管理者側には「直す」「↑」「↓」「消す」 |
| 載せる | 分野（§2.3）、質問（必須・200 文字）、答え（必須・2,000 文字・改行可）。200 件まで |
| すべての質問 | 「すべての質問（n 件）」の下に、分野ごとの見出し（件数）で分けて出す。「↑」「↓」は同じ分野の中で入れ替える |
| 要望・依頼から | 種類が「質問」で閉じた要望・依頼の詳細（管理者側）に「よくある質問に載せる」。もとの要望の番号だけを残し、質問と答えは管理者側が書き直す（出した人の文や名前は出さない） |
| 部下・確認者の操作 | 載せる・直す・消すは 403 |
| 記録 | `admin faq:<ID>:create|update|delete` |

テーブル `faq_entries`（DB 編）。各画面の「？ この画面の使い方」からも開ける（共通編）。そのときは画面の番号と開いていた画面を付けて開き、§2.2 で送る質問に入れる。

### 2.1 チャットで知りたいことを入れて探す（AI は使わない）

画面の上にチャットの枠（吹き出しの並びと、下に入力の欄「知りたいことを入れる」（200 文字まで）と「送る」）。その下に「すべての質問」。自動の答えは、よくある質問に載っている質問と答えの文だけ（文を作らない）。

| 場面 | チャットの表示（`app.js`。文言は G-17 で変えられる） |
|---|---|
| 開いたとき | 「こんにちは。知りたいことを入れてください。よくある質問から近い答えを探します。（例: …）」 |
| 入れた | 入れた文を右の吹き出し。`/faq.php?format=json&q=` に聞く（返すのは近い質問の番号・質問・答え） |
| 見つかった | いちばん近い質問と答えを左の吹き出し。ほかにもあれば「ほかに近い質問もあります。押すと答えを出します。」と質問のボタン（押すとその答え）と「この中にない」。続けて「解決した」「解決しない」のボタン。解決した → 「よかったです。ほかにも知りたいことがあれば入れてください。」 |
| 見つからない | 課長・確認者: 「近い質問は見つかりませんでした。言葉を変えて入れるか、質問として送ってください。」と「言葉を変えて入れる」「質問として送る」。ほかの人: 「…言葉を変えて入れてみてください。」と §2.2 の案内、「言葉を変えて入れる」 |
| 解決しない・この中にない・質問として送る | §2.2 の欄（課長・確認者）か案内（ほか）を吹き出しで出す |

JavaScript が無いときは、入れて「送る」で `?q=` の画面を開き直し、同じ吹き出し（入れた文、近い質問と答え、§2.2）をサーバーで出す。

| 手順 | 内容（`faq_search()`） |
|---|---|
| そろえる | 全角の英数字・記号を半角に、英字を小文字に、記号と空白を 1 つの空白にする（`faq_normalize_text()`。mbstring が無くても動く） |
| 言い換え | 入れた文に `FAQ_SEARCH_SYNONYMS` の左の言葉があれば、右の言葉でも探す（例: スマホ → スマートフォン、締切 → 締め日、修正 → 直す、エクセル → csv 出力）。表はコードで持つ（足すときは `notice.php`） |
| 言葉に分ける | 英数字はひと続きで 1 語（2 文字以上）。英数字の言葉は単語として当てる（前後が英数字でないところだけ。「ip」が「iphone」に、「then」が「authenticator」に当たらない。`faq_text_contains_term()`）。日本語は 2 文字ずつの並び。ただし、ひらがなで始まる並び（「の人」「を機」）と、助詞（は・が・を・に・の・で・と・も・へ・や）で終わる並び（「日は」「面が」）は、言葉の区切りをまたぐので使わない（「忘れ」「直せ」のような送り仮名の並びは使う）。漢字・カタカナ 1 文字だけのときはその 1 文字 |
| 近さ | 言葉ごとに、質問に当たれば 2 点、答えだけに当たれば 1 点。満点（言葉の数 × 2）に対する割合が 0.25 以上のものを、近い順に出す。同じ近さなら、質問の文の言葉のうち入れた文にもある割合が大きいほう（質問の文そのものを入れたら、その質問）、それも同じなら並び順 |

見つからないときは「近い質問は見つかりませんでした。言葉を変えて探すか、下から質問してください。」

### 2.2 見つからない質問を送る（自動で起票する）

| 人 | 表示 |
|---|---|
| 課長・確認者（`support_request_can_submit()`） | 説明と、入れた文を入れておいた質問の欄（2,000 文字まで。補足を書き足せる）と「質問として送る」。探す前から隠して置いておき、チャットで出す |
| 部下 | 「課長・確認者（課長代理・リーダー）に聞いてください。…」（送る欄は出さない。K-044・K-048） |
| 管理者・補佐（確認者でない） | 「システム管理者・補佐は質問を受ける側のため、ここからは送れません。…」 |

送ると、要望・依頼（G-22）を 1 件出す（G-22 §6.1 と同じ処理・確かめ。続いているものが 30 件なら出せない）。

| 項目 | 値 |
|---|---|
| 種類・急ぎ | 質問・通常 |
| 件名 | 質問の最初の行（60 文字を超えれば 59 文字＋「…」。`faq_question_title()`） |
| 内容 | 質問の全文 |
| 関係する画面・開いていた画面 | 「この画面の使い方」から来たときの画面の番号と、開いていた画面（G-22 §4 の決まった項目だけ）。ほかは指定しない |

送ったら要望・依頼の詳細へ移り「質問をシステム管理者に送りました。返信があると、ホームに出ます」。空なら「質問を入れてください」。部下が送ると 403。記録は `admin support_request:<ID>:create`。管理者側は答えたあと、閉じた詳細の「よくある質問に載せる」で載せる（§2）。

### 2.3 分野と、曖昧な質問の聞き返し（AI は使わない）

`faq_entries.category`（DB 編）に分野を持つ（`FAQ_CATEGORY_LABELS`）。

| コード | 分野 |
|---|---|
| `about` | このシステムについて（概要・目的、システム管理者・補佐はだれか、開発者・問い合わせ先、役割、1 か月の流れ、ほしい機能がない、使える時間） |
| `login` | ログイン・パスワード・2 段階認証 |
| `report` | 報告の作成・提出 |
| `comment` | コメント・返信 |
| `review` | 報告の確認・チェック（確認者・課長） |
| `status` | 提出状況・横並び・検索・出力 |
| `survey` | 臨時の調査 |
| `account` | アカウント設定・画面の表示 |
| `request` | 要望・依頼・よくある質問 |
| `department` | 課の管理・項目（課長） |
| `admin` | システムの管理（管理者・補佐）。**システム管理者・補佐にだけ見せる**（`FAQ_STAFF_ONLY_CATEGORIES`・`faq_visible_entries()`。ほかの人には、チャットの答え・分野のボタン・すべての質問の一覧のどこにも出さない） |
| `device` | スマートフォン・PC・ブラウザー |
| （空） | そのほか |

- チャットの最初に、質問のある分野のボタン（「分野（件数）」）を出す。「この画面の使い方」から来たときは、その画面の分野（`FAQ_CATEGORY_BY_SCREEN`）を「開いていた画面の質問は「…」にあります。」と知らせ、ボタンを太くする。
- **曖昧な質問**: 言い換えの表（`FAQ_SEARCH_SYNONYMS`）にある言葉（概要・開発者・添付・余白など）が入っていれば曖昧としない（「このシステムは何するもの？」を聞き返さない）。そのうえで、入れた文から中身のない言い方（`FAQ_VAGUE_WORDS`。使い方・わからない・教えて・困った・どうすれば・できない・システム・画面 など）を除くと探す言葉が残らないとき（`faq_is_vague()`）は、答えを探さず「どのことについて知りたいですか？　分野を選ぶか、「パスワード」「提出」「コメント」のように、知りたいことの言葉を入れてください。」と分野のボタンを出す。例: 「使い方がわからない」「教えて」「困った」は聞き返す。「ログインできない」「報告の使い方」は「ログイン」「報告」が残るので探す。
- 分野を選ぶと「「（分野）」の質問です。近いものを選んでください。」と、その分野の質問のボタン（並び順）と「この中にない」を出す。選ぶと答えと「解決した」「解決しない」。「この中にない」は §2.2。
- 見つからないときにも「分野から選ぶ」を出す。
- 押した分野のボタンは押した見た目（枠）にする。最初の分野の並びは何度でも押せるが、押した見た目は**最後に押した 1 つだけ**に付け、前に押したボタンは押す前の見た目に戻す（チャットの中のすべての分野のボタンで 1 つだけ。`aria-current` も同じ）。
- JavaScript が無いときは、分野のボタンは `?category=` へのリンクで、開き直すと分野の質問を吹き出しの中に出す。

### 2.4 標準のよくある質問

`app/lib/faq_standard.php` の `FAQ_STANDARD_ENTRIES`（分野・質問・答え）に、（**答えにはシステムの内部の情報（コマンド・ファイルの場所・鍵やパスワードの置き場所など）を書かない**。検証で確かめる）操作マニュアルの全章と基本設計書の概要から想定される質問をまとめて持つ（149 件）。チャットの記録（§2.7）で答えられなかったシステムの質問は、ここに足していく。リポジトリで管理し、操作や画面を変えたときは操作マニュアルと一緒に直す。

- 管理者・補佐には「すべての質問」の下に「標準のよくある質問を取り込む（まだ載っていない n 件）」を出す（確認の表示のあと）。押すと、同じ質問の文が載っていないものだけを分野つきで足す（200 件まで）。すべて載っていれば「標準のよくある質問は、すべて載っています。」
- 取り込んだあとは、画面で直す・消すことができる（標準を直しても、取り込み済みの質問は変わらない）。
- 記録 `admin faq:import_standard;added=<件数>`。
- 検証: 標準の質問は、その質問の文で探すといちばん上に出ること（取り違えがないこと）を確かめる。

### 2.6 システムに関係のない質問・不適切な表現（AI は使わない）

判定の順（`faq_answer_chat()`）: 分野を選んだ → 命・体の緊急の状態（§2.12） → 心の不調らしい文（§2.8） → 自分の退職（§2.10） → 要配慮個人情報に触れる文（§2.9） → 不適切な表現 → 曖昧な質問 → 関係のない質問 → 近い質問を探す。

**不適切な表現**: 不適切な言葉（`FAQ_ABUSIVE_WORDS`。バカ・死ね・無能・役立たず・ポンコツ・黙れ・クソ・ふざけるな など）が入っていれば（`faq_is_abusive()`）、システムの言葉があっても答えず、「不適切な表現が含まれているため、返答できません。」（G-17 で変えられる）。ふつうの文に紛れる言葉（「ばかり」の「ばか」、「カスタム」の「カス」、「ところすでに」の「ころす」など）は表に入れない。続いた回数は、関係のない質問と合わせて数える（下の「続いたとき」）。

**関係のない質問**:


| 項目 | 内容 |
|---|---|
| 判定（`faq_is_unrelated()`） | 曖昧な質問でなく、システムの言葉（`FAQ_SYSTEM_WORDS`。エラー・表示・真っ白・固まる・動かない・保存・入力・ボタン・報告・画面・修正・削除・設定 など）が入っておらず、入れた文の言葉のうち、よくある質問の文（標準の質問と載っている質問）・分野の名前・システムの言葉に出てくる割合が 0.5 以下で、いちばん近い質問の近さも 0.5 以下のとき（`FAQ_UNRELATED_MAX_RATIO`）。言葉が 1 つも取れない文（「1+1は」「あなたは誰」）も関係のない質問とする |
| 例 | 関係のない質問: 明日の天気は？／おすすめの映画を教えて／野球の結果／有給休暇の申請方法／経費精算したい。システムの質問: ログインできない／修正したい／画面が真っ白／動かない／スマホ変えた |
| 返事 | 「その質問には返答できません。」（G-17 で変えられる）。近い質問・送る欄（§2.2）は出さない |
| 続いたとき | 関係のない質問か不適切な表現が、合わせて 5 回続くと（`FAQ_UNRELATED_IGNORE_COUNT`）、5 回目から返事をしない（入れた文の吹き出しだけが出る）。数えるのはサーバーのセッション（`faq_count_unrelated()`。画面を開き直しても数え直さない。ログインし直すと 0）。システムの質問（曖昧な質問を含む）をするか、分野を選ぶと 0 に戻り、また返事をする |
| JavaScript が無いとき | `?q=` の画面でも同じに判定・数える（返事をしないときは、入れた文の吹き出しだけ） |
| JSON | `{"ok": true, "log_id": 12, "result": "unrelated", "vague": false, "unrelated": true, "abusive": false, "ignored": false, "matches": []}`（`result` は matched・no_match・vague・unrelated・abusive・category） |

### 2.7 チャットの記録（よくある質問の改善のため）

聞かれた質問と返した答えを、操作の記録（`access_logs`）とは別の表 `faq_chat_logs`（DB 編）に残す（`app/lib/faq_chat_log.php`）。

| 項目 | 内容 |
|---|---|
| 残すもの | 日時、聞いた人（`user_id`。不適切な表現への対応のため。K-051）と役割（部下・確認者・課長・管理者・補佐）、開いていた画面、質問の文（暗号化。`faq_chat:<ID>`）か選んだ分野、結果（答えた・見つからない・曖昧・関係のない質問・不適切な表現・分野を選んだ）、返事をしなかったか、出した質問の番号、反応（解決した・解決しない・質問として送った）と、どの答えへの反応か、送った要望・依頼の番号 |
| 残すとき | チャットで入れた・分野を選んだとき（JavaScript が無いときの `?q=`・`?category=` の画面も）。反応は「解決した」「解決しない」「この中にない」を押したとき（POST `action=chat_feedback`。その人のセッションで残した記録だけ。ほかは 400）と、「質問として送る」で要望・依頼を出したとき |
| 残す期間 | 1 年（新しく記録するときに、1 年より古いものを消す） |
| 表が無い DB | 画面を開いたときに無ければ作る（`faq_chat_log_ensure_table()`。`schema.php` にも載せる） |
| 操作の記録 | 質問の文は `access_logs` に残さない。記録の画面を見たことは `admin faq_chat_logs:view;days=<日数>` |

**よくある質問の記録の画面（`/admin/faq_logs.php`）**: システム管理者・補佐（メニューの見出し「管理」に「よくある質問の記録」。管理のトップにカード。7 日の答えられなかった質問の数、不適切な表現があれば目立つ札）。部下・確認者・課長は 403。

| 欄 | 内容 |
|---|---|
| 絞り込み | 期間（直近 7・30・90・365 日。既定 30 日）、結果（すべて／答えられなかったもの（見つからない・解決しない・送った）／各結果） |
| 集計 | 結果・返事をしない・反応ごとの件数（新しい 2,000 件まで） |
| 答えられなかった質問（多い順） | 同じ文をまとめて、回数・最後の日時と「よくある質問に載せる」（`/faq.php?draft_log=<記録の番号>`。質問の欄にその文、分野が分かれば分野を入れて、載せる欄を開く。管理者・補佐だけ） |
| 「解決しない」が多い答え | よくある質問ごとの解決しない・解決したの数と「直す」 |
| 関係のない質問とした文（多い順） | システムの質問がここに出ていれば、システムの言葉の表に言葉が足りない |
| 不適切な表現 | 日時・聞いた人・文・返事（返答できない／返事をしない） |
| 新しい順 | 最大 300 件。日時・聞いた人・画面・質問か分野・結果・出した答え・反応（送った要望・依頼へのリンク） |

聞いた人の名前（表示名とログイン ID）は、システム管理者・補佐のどちらにも出す（K-051。補佐が個々の情報を見ない K-043 の例外）。

### 2.8 心の不調らしい文（AI は使わない。K-052）

| 項目 | 内容 |
|---|---|
| 判定（`faq_distress_level()`） | 命に関わる言葉（`FAQ_DISTRESS_URGENT_WORDS`。死にたい・消えたい・自殺・いなくなりたい・楽になりたい など）→ `urgent`。心配な言葉（`FAQ_DISTRESS_CONCERN_WORDS`。つらい・しんどい・疲れた・限界・眠れない・うつ病・怖い・助けて・パワハラ・いじめ・もう無理・辞めたい など）→ `concern`。ふつうの文に紛れる言葉（「写す」の「うつ」など）は入れない |

| 記録の画面の欄 | 「心の不調・退職に関わる質問」（システム管理者だけ。補佐には欄を出さず、一覧・集計からもこの記録を除く。補佐の「対応した」は 403）: 期間にかかわらず未対応のものと、期間の中の対応済みのもの（未対応 → 命に関わる言葉 → 新しい順。200 件まで）。日時・聞いた人・段階・文・「対応した」（確認の表示のあと。対応した日時と人を残す。記録 `admin faq_chat_log:<ID>:distress_handled`）。すべて対応すると、ホームの知らせは消える |
| 本人への知らせ | 利用者に見える画面・返事・よくある質問・操作マニュアルの利用者の章には、管理者・補佐に知らせることを書かない（2026-11-16 指示） |
| 記録の列 | `faq_chat_logs.result = 'distress'`、`distress_level`（urgent・concern）、`handled_at`・`handled_by`。この列を足す前の表は、画面を開いたときに作り直して記録を写す（番号は変えない。暗号の文脈に使うため。`faq_chat_log_ensure_table()`） |

### 2.11 チャットの問い合わせの失敗（「通信エラー」）

| 項目 | 内容 |
|---|---|
| ログインが切れているとき | JSON を求める要求（`is_json_request()`。`?format=json` か Accept: application/json）は、ログインの画面に転送せず `{"ok": false, "reason": "login"}`（401）を返し、`app.log` に「WARN JSON の問い合わせで、ログインが切れていた: <パス>」を残す（パスだけ。質問の文は残さない）。チャットは「ログインの有効期限が切れました。画面を開き直して、もう一度ログインしてください。」 |
| エラーのとき | JSON を求める要求には、エラーの画面でなく `{"ok": false, "reason": "error", "status": <コード>}` を返す（`error_page()`）。500 は例外の処理が `app.log` に中身を残す。ほかは「WARN JSON の問い合わせのエラー <コード>: <パス>」 |
| 答えが読めなかったとき | チャットは「通信エラー」と出し、POST `action=chat_client_error`（kind = not_json・not_ok・network）で `app.log` に「WARN よくある質問のチャットの問い合わせに失敗」を残す（サーバーに届かないときは残せない） |
| 数字の言葉 | 2 けた以上の数字（「10」「2026」など）は、配列のキーにすると整数に変わるので、探す言葉は文字列に戻す（`faq_search_terms()`）。戻さないと止まって「通信エラー」になっていた |

### 2.14 お悔やみの言葉

- 標準の答えには、お悔やみを決めて書かない（いなくなった・交代しただけで、亡くなったとは限らないため）。
- 質問に人が亡くなったことを表す言葉（`FAQ_DEATH_WORDS`: 亡くな・亡くし・急逝・他界・逝去・死去・永眠）があり、答えが見つかったときだけ、いちばんの答えの頭に「心よりお悔やみ申し上げます。」を添える（`faq_mentions_death()`。答えにもとから「お悔やみ」があれば重ねない）。

### 2.15 緊急の言葉の補い（他の端末での確かめによる）

- 緊急の言葉に、胸の強い痛み（すごく痛・胸が苦し・胸が重）、窒息（喉に詰ま・詰まらせ・顔色が真っ青・声も出せ）、誤飲（漂白剤・ハイター・灯油・タバコ・灰皿・電池・嘔吐・舐めて）、事故（巻き込まれ・挟まれ・下敷き・切断・転落）、亡くなっている状態（冷たくなっ・息をしていな・脈がな）を足した。「倒れそう」は緊急にしない（倒れた・倒れて・倒れ込 だけ）。
- 緊急の返事に、迷うときの相談先「#7119（救急安心センター。地域によってはつながらない）」「#8000（子ども医療電話相談）」を足した。
- 心の不調: 味の「辛い」（辛いラーメン など。`FAQ_DISTRESS_NOT_FEELING_PHRASES`）は除く。「死んだように（働く）」「精神的に」を心配な言葉に足した。
- システムの障害（サーバー・本番環境・停止・ダウン）とセキュリティの事故（不正アクセス・侵入・攻撃・漏えい）の質問に、「システムが止まった・障害が起きた」「不正アクセス・情報が漏れたおそれがある」の答えを出す。
- チャットの記録の書き出し（`export_faq_chat_log.php`）は、画面に出さない文（要配慮・緊急）を書き出さない（`faq_chat_log_display_text()`）。
