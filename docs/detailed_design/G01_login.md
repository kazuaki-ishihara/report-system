# G-01 ログイン

| 項目 | 内容 |
|---|---|
| URL | `/login.php`（GET: 手順 1 の画面、POST: `action=password`／`action=code`）、`/login.php?step=2`（GET: 手順 2 の画面）、`/logout.php`（POST） |
| 利用者 | 全員（未ログイン） |
| 主な端末 | スマートフォン |
| 段階 | 1 |
| 関連する機能 | F-01、F-02 |

---

## 1. 目的

ログイン ID・パスワードと、2 段階認証のコードで本人を確かめる。月に 1 回しか使わない人が、迷わずに入れるようにする。

## 2. 表示の条件と権限

- ログインしていない人が使う。ログインが済んだ段階（`full`）で開いたときはホームへ転送する。
- 2 段階認証の手順は、パスワードが正しかった人だけに見せる。手順 2 の状態（§6.1 の 8）がないのに `?step=2` を開いたときは、`/login.php` へ転送する。
- `action` が `password`・`code` 以外の POST は 400。

## 3. 画面の配置

**手順 1: ID とパスワード**

```text
┌──────────────────────────┐
│ ログイン                   │
├──────────────────────────┤
│ ログイン ID                │
│ [________________]        │
│ パスワード                 │
│ [________________] [表示] │
│                          │
│ [       ログイン       ]   │
│                          │
│ パスワードを忘れた場合      │
└──────────────────────────┘
```

**手順 2: 2 段階認証のコード**（記憶した端末では出ない）

```text
┌──────────────────────────┐
│ スマートフォンの認証アプリ…  │
│ 認証アプリの 6 桁のコード   │
│ [______]                  │
│ ☑ この端末を 90 日間記憶する │
│                          │
│ [        確認        ]    │
│                          │
│ 認証アプリが使えないときは、 │
│ 予備のコード（xxxx-xxxxxx） │
│ を上の欄に入れてください。   │
│ 最初からやり直す            │
└──────────────────────────┘
```

予備のコードは、6 桁のコードと同じ欄に入れる。「最初からやり直す」は手順 1 へ戻る。

## 4. 表示項目

| 項目 | 内容 |
|---|---|
| 説明 | 手順 2 に「スマートフォンの認証アプリ（Google Authenticator など）に表示される 6 桁の数字を入れてください。」 |
| 「この端末を記憶する」 | 既定はオン（月 1 回の利用で毎回コードを入れずに済むように）。日数は `remember_device_days` |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| ログイン ID | 必須。前後の空白を除き、小文字にそろえる。英小文字・数字・`.`・`_`・`-`、3〜32 文字、先頭は英数字（`^[a-z0-9][a-z0-9._-]{2,31}$`）。形が違う ID は、存在しない ID と同じ扱いにする（形についてのメッセージは出さない） |
| パスワード | 必須。ログインでは長さを確かめない（入力欄は 200 文字まで） |
| コード | 空白と `-` を除く。数字 6 桁なら TOTP、英数字 10 文字なら予備のコード（大文字・小文字は区別しない）。入力欄は 12 文字まで |

ID かパスワードが空のときは「ログイン ID とパスワードを入れてください」を出す。

## 6. 操作と処理

ログイン画面は `page_start(['auth' => 'none'])` で始め、POST なら CSRF を確かめる（共通編 §3）。画面を開くたびに 1 日 1 回の後片付けを呼ぶ（DB 編 §5）。送信の番号は使わない。

### 6.1 ログイン（手順 1）

1. `next` を受ける。自サイトのパスで、`/login.php` で始まらないものだけ使い、それ以外は `/index.php` にする。
2. `users` を `login_id` で探す。ないとき、無効（`is_active = 0`）のときは、ダミーのハッシュで `password_verify` を行う（時間をそろえる）。そのうえで、IP アドレスでロック中ならロックの文言を出し、そうでなければ IP アドレスの失敗を 1 増やして（`login_throttle`、`ip:<IP>`。上限と時間は利用者と同じ）、パスワード違いと同じ文言を出す。記録 `auth login:fail`（利用者なし）。
3. `locked_until` が今より後なら、ダミーのハッシュで時間をそろえ、ロックの文言を出す（パスワードは確かめない）。記録 `auth login:locked_attempt`。
4. `password_verify`。違えば `failed_count` を 1 増やし、`login_max_failures` に達したら `locked_until = 今 + login_lock_minutes`、`failed_count = 0`。記録 `auth login:fail`（ロックしたら `login:locked`）。
5. 正しくても、失敗の回数はここでは戻さない（パスワードだけ知る人がコードを総当たりできないように）。`password_needs_rehash` なら作り直して保存する。
6. 2 段階認証が未設定（`totp_enabled_at` が NULL）なら、セッションを段階 `setup` にしてログインさせ、`after_setup_next` に転送先を持つ。記録 `auth login:pw_ok_setup`。`/account.php?tab=totp`（G-16）へ転送する。
7. Cookie `mr_device` の端末の記憶があり、`remembered_devices` で有効（ハッシュが一致し、期限内、同じ利用者）なら、`last_used_at` を更新し、2 段階認証を済んだものとして §6.2 の 5 へ。
8. なければ `session_regenerate_id(true)` のあと、セッションに `pw_uid`・`pw_at`・`pw_next` を持ち、`/login.php?step=2` へ転送する（`pw_stage_minutes` = 5 分以内に手順 2 を終えなければやり直し）。

### 6.2 コードの確認（手順 2）

1. 手順 2 の状態が 5 分を過ぎたか、利用者が無効なら、状態を消し「時間が経ったため、最初からやり直してください」を出して手順 1 へ戻す。
2. 利用者がロック中なら、状態を消し、ロックの文言を出して手順 1 へ戻す。
3. TOTP（RFC 6238。HMAC-SHA1、30 秒、6 桁）を、前後 1 区間まで許して確かめる。最後に使った区間（`users.totp_last_step`）以前の区間は断る（同じコードの 2 回目を防ぐ）。一致したら `totp_last_step` を更新する。
4. 予備のコードのときは、未使用の `user_backup_codes` と `password_verify` で照合し、一致したら `used_at` を入れる。
5. 成功したら、`failed_count = 0`、`locked_until = NULL` にし、セッションを作り直して段階 `full` でログインさせる（利用者 ID・`session_version`・ログインの時刻・最終操作の時刻を持つ）。記録 `auth login:ok`。
6. 「この端末を記憶する」がオンなら、32 バイトの乱数（16 進）を Cookie `mr_device`（`HttpOnly`、`SameSite=Lax`、`Secure` は設定 `https` に従う、パスは `base_path`、90 日）に入れ、SHA-256 と端末の名前（User-Agent から「iPhone の Safari」など）・期限を `remembered_devices` に保存する。
7. `next`（自サイトのパスのみ）かホームへ転送する。仮のパスワードの間（`must_change_password = 1`）は、次の画面の共通処理が G-16 のパスワード変更へ転送する（共通編 §3）。
8. 失敗は手順 1 と同じ回数に数え、ロックの対象にする。記録 `auth login:2fa_fail`（ロックしたら `login:locked` を残し、手順 1 へ戻す）。

### 6.3 ログアウト

POST だけ（GET は 400）。記録 `auth logout` を残し、セッションを破棄して「ログアウトしました。」を出し、ログイン画面へ。端末の記憶は残す。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 未入力 | ログイン ID とパスワードを入れてください |
| ID かパスワードが違う | ログイン ID またはパスワードが違います |
| ロック中 | ログインに続けて失敗したため、しばらくログインできません。15 分ほど待ってからお試しください |
| コードが違う | コードが違います。認証アプリに表示されている最新の 6 桁を入れてください |
| 手順 2 の時間切れ | 時間が経ったため、最初からやり直してください |
| ログアウト | ログアウトしました。 |
| 自動ログアウト後 | 一定時間操作がなかったため、ログアウトしました。（最後の操作から 30 分、またはログインから 12 時間） |

ロック中の文言は、ID が存在しない場合も、失敗が続けば同じように出す（ID の有無を分からせない。存在しない ID の失敗は、IP アドレスごとの回数で数える）。

## 8. 記録

`auth` に `login:ok`、`login:fail`（存在しない ID は利用者なし）、`login:locked`、`login:locked_attempt`、`login:2fa_fail`、`login:pw_ok_setup`、`logout`。パスワードとコードは記録しない。

## 9. 検証の観点

- 存在しない ID と、パスワード違いで、表示・状態コードが同じ（応答の時間は自動の検証では測らない）。
- 10 回失敗でロックされる。ロック中は正しいパスワードでも入れない。15 分後に解除される。
- 手順 2 の途中ではホームを開けない。手順 1 を飛ばして手順 2 に POST しても入れない。5 分を過ぎた手順 2 は断られる。
- 同じ TOTP のコードを 2 回使えない。使用済みの予備のコードは使えない。
- 記憶した端末ではコードなしで入れる。その Cookie を別の利用者で使っても、2 段階認証を飛ばせない。期限切れの Cookie は無効。
- `next` に外のサイトの URL を入れても転送されない。
- CSRF のトークンがない POST は 403。
- ログイン前後でセッション ID が変わる。

自動の検証（`tools/test/smoke_auth.py`）でまだ試していないもの: ロックの解除、ロック中の正しいパスワード、同じ TOTP の 2 回目、5 分の時間切れ、別の利用者・期限切れの Cookie、セッション ID の変化、手順 1 を飛ばした POST。
