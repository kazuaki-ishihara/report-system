# G-01 ログイン

| 項目 | 内容 |
|---|---|
| URL | `/login.php`（GET: 画面、POST: ログイン）、`/logout.php`（POST） |
| 利用者 | 全員（未ログイン） |
| 主な端末 | スマートフォン |
| 段階 | 1 |
| 関連する機能 | F-01、F-02 |

---

## 1. 目的

ログイン ID・パスワードと、2 段階認証のコードで本人を確かめる。月に 1 回しか使わない人が、迷わずに入れるようにする。

## 2. 表示の条件と権限

- ログインしていない人だけが使う。ログイン済みで開いたときはホームへ転送する。
- 2 段階認証の手順は、パスワードが正しかった人だけに見せる。

## 3. 画面の配置

**手順 1: ID とパスワード**

```text
┌──────────────────────────┐
│ 月次報告                   │
├──────────────────────────┤
│ ログイン ID                │
│ [________________]        │
│ パスワード                 │
│ [________________] [表示] │
│                          │
│ [       ログイン       ]   │
│                          │
│ パスワードを忘れた場合 →    │
└──────────────────────────┘
```

**手順 2: 2 段階認証のコード**（記憶した端末では出ない）

```text
┌──────────────────────────┐
│ 認証アプリの 6 桁のコード   │
│ [______]                  │
│ □ この端末を 90 日間記憶する │
│                          │
│ [        確認        ]    │
│                          │
│ 予備のコードを使う →        │
└──────────────────────────┘
```

## 4. 表示項目

| 項目 | 内容 |
|---|---|
| 説明 | 手順 2 に「スマートフォンの認証アプリ（Google Authenticator など）に表示される 6 桁の数字を入れてください」 |
| 「この端末を記憶する」 | 既定はオン（月 1 回の利用で毎回コードを入れずに済むように） |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| ログイン ID | 必須。英数字・`-`・`_`・`.`、3〜32 文字。大文字・小文字は区別しない（小文字にそろえる） |
| パスワード | 必須。最大 72 バイト（`password_hash` の上限） |
| コード | 数字 6 桁（予備のコードのときは英数字 10 文字、`-` と空白は取り除く） |

## 6. 操作と処理

### 6.1 ログイン（手順 1）

1. CSRF の確認（ログイン画面にもトークンを入れる）。
2. `users` を `login_id` で探す。ないとき、無効（`is_active = 0`）のときも、パスワード違いと同じ処理・同じ表示にする（時間も同じになるよう、ダミーのハッシュで `password_verify` を行う）。
3. `locked_until` が今より後なら、ロック中の表示にする（パスワードは確かめない）。
4. `password_verify`。違えば `failed_count` を 1 増やし、`login_max_failures` に達したら `locked_until = 今 + login_lock_minutes`、`failed_count = 0`。記録 `auth login:fail`（ロックしたら `login:locked`）。
5. 正しければ `failed_count = 0`。`password_needs_rehash` なら作り直して保存する。
6. 2 段階認証が未設定（`totp_enabled_at` が NULL）なら、セッションを「パスワード確認済み・2 段階認証は未設定」にして G-16 の設定へ転送する。
7. Cookie の端末の記憶があり、`remembered_devices` で有効（ハッシュが一致し、期限内、同じ利用者）なら、2 段階認証を済んだものとして 8 へ。`last_used_at` を更新する。
8. なければ手順 2 を出す。セッションには「パスワード確認済み」と、その時刻だけを持つ（5 分以内に手順 2 を終えなければやり直し）。

### 6.2 コードの確認（手順 2）

1. CSRF の確認。セッションが「パスワード確認済み」で 5 分以内かを確かめる。
2. TOTP（RFC 6238。HMAC-SHA1、30 秒、6 桁）を、前後 1 区間まで許して確かめる。同じ区間のコードの 2 回目の使用は断る（最後に使った区間を記録する）。
3. 予備のコードのときは、未使用の `user_backup_codes` と `password_verify` で照合し、一致したら `used_at` を入れる。
4. 失敗は手順 1 と同じ回数に数え、ロックの対象にする。
5. 成功したら `session_regenerate_id(true)`。セッションに利用者 ID・`session_version`・ログインの時刻を持つ。
6. 「この端末を記憶する」がオンなら、32 バイトの乱数を Cookie（`Secure`、`HttpOnly`、`SameSite=Lax`、90 日）に入れ、SHA-256 を `remembered_devices` に保存する。
7. 記録 `auth login:ok`。`must_change_password = 1` なら G-16 のパスワード変更へ、そうでなければ `next`（自サイトのパスのみ）かホームへ転送する。
8. 1 日 1 回の後片付けを行う（DB 編 §5）。

### 6.3 ログアウト

POST（CSRF あり）。セッションを破棄し、ログイン画面へ。端末の記憶は残す。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| ID かパスワードが違う | ログイン ID またはパスワードが違います |
| ロック中 | ログインに続けて失敗したため、しばらくログインできません。15 分ほど待ってからお試しください |
| コードが違う | コードが違います。認証アプリに表示されている最新の 6 桁を入れてください |
| 手順 2 の時間切れ | 時間が経ったため、最初からやり直してください |
| 自動ログアウト後 | 一定時間操作がなかったため、ログアウトしました |

ロック中の文言は、ID が存在しない場合も、失敗が続けば同じように出す（ID の有無を分からせない。存在しない ID の失敗は、IP アドレスごとの回数で数える）。

## 8. 記録

`auth` に `login:ok`、`login:fail`、`login:locked`、`login:2fa_fail`、`logout`。パスワードとコードは記録しない。

## 9. 検証の観点

- 存在しない ID と、パスワード違いで、表示・応答の時間・状態コードが同じ。
- 10 回失敗でロックされ、15 分後に解除される。ロック中は正しいパスワードでも入れない。
- 手順 1 を飛ばして手順 2 に POST しても入れない。5 分を過ぎた手順 2 は断られる。
- 同じ TOTP のコードを 2 回使えない。使用済みの予備のコードは使えない。
- 記憶した端末の Cookie を別の利用者で使っても、2 段階認証を飛ばせない。期限切れの Cookie は無効。
- `next` に外のサイトの URL を入れても転送されない。
- ログイン前後でセッション ID が変わる。
