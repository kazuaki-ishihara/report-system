# G-03 ホーム

| 項目 | 内容 |
|---|---|
| URL | `/index.php`（GET） |
| 利用者 | 全員 |
| 主な端末 | スマートフォン |
| 段階 | 1（提出状況・臨時の調査の欄は 2） |
| 関連する機能 | F-05、F-07、F-12、F-13、F-14 |

---

## 1. 目的

月に 1 回しか来ない人が、**今やることがすぐ分かる**入り口にする。部下には「今月の報告」と「回答待ち」、確認者には「未チェック」と「回答あり」を出す。

## 2. 表示の条件と権限

- ログインしている全員。
- 出す欄は役割で変わる（共通編 §10.1）。複数の課の確認者なら、課ごとに欄を出す。確認者の欄は `department_reviewers` に入っている課だけに出す（管理者でも、入っていなければ出ない）。無効の課は出さない。

## 3. 画面の配置

```text
┌──────────────────────────┐
│ 月次報告      [≡ メニュー] │
├──────────────────────────┤
│ 山田 さん                  │
│ ■ あなたの役割と権限        │
│   [課長代理]               │
│   担当: A課（確認者）       │
│   ▶ できること             │ ← 押すと開く
│                          │
│ ■ 2026年11月の報告         │
│   状態: 未作成              │
│   締め日: 2026-12-05        │
│   [ 今月の報告を作る ]       │ ← いちばん大きいボタン
│   2026年10月の報告がまだです。作る │
│                          │
│ ■ 回答待ちのコメント 2件     │
│   ・作業フェーズ（佐藤さん）  │
│   ・報告全体（課長さん）      │
│                          │
│ ■ 臨時の調査 1件            │
│   ・AI の利用状況 期限 2026-11-20 │
│                          │
│ ■ A課 2026年11月（確認）    │
│   未チェック 5件 ／ 回答あり 1件 ／ 未提出 2人 │
│   [ 未チェックを順に見る ] [ 提出状況 ] │
└──────────────────────────┘
```

管理者には、課長がいない有効な課があれば、上に「課長がいない課があります（確認を完了にできません）: （課名）」と「組織・ユーザーで設定する」を出す（G-14 §6.7）。

所属の課がない人には、報告の欄（今月の報告を作るなど）を出さない。管理者には代わりに「管理」の欄を出し、メニューの「確認」「管理」の画面への入口を並べる。全課共通の調査の結果を見る人（部長以上・依頼元の担当。G-11 §10。K-067）には「見られるもの」の欄を出し、同じく入口（「調査の結果」）を並べる。どちらでもない人には「所属の課が設定されていません。管理者に連絡してください。」を出す。

## 4. 表示項目

### 4.1 全員

| 欄 | 内容 | 出し方 |
|---|---|---|
| 今月の報告 | 見出し「YYYY年M月の報告」。対象月（§4.3）の自分の報告の状態（未作成／下書き／提出済み／確認完了） | 未作成なら「今月の報告を作る」、下書きなら「続きを書く」（どちらも G-04）、それ以外は「報告を見る」（G-05） |
| 締め日 | 所属課の `close_day` による、対象月の**翌月**の締め日（`YYYY-MM-DD`。31 や月末を超える日は月末にする）。未設定なら出さない | 残り 3 日以内（過ぎた後を含む）は赤で出す |
| 前月の報告 | 前月の報告が未作成か下書きなら「YYYY年M月の報告がまだです。」と「作る」のリンク | 押すと前月の G-04 |
| 回答待ちのコメント | 自分の報告（対象月に限らない）への、`thread_status = 'open'` の最初のコメント | 件数と、「項目名（投稿者さん）」の一覧（最大 5 件）。項目がないコメントは「報告全体」。押すと G-05 の該当のコメント（`#comment-<ID>`）へ |
| 臨時の調査 | 自分が対象で、`status = 'open'`、削除されていない、未回答のもの | 題名と「期限 YYYY-MM-DD」。期限の順。押すと G-07 |
| 更新のお知らせ | 全員。出す期間の中のお知らせ（G-24） | 新しい順に 5 件まで。題名を押すと内容が開く |
| メンテナンス中 | 管理者・補佐。メンテナンス中のとき（G-21 §7） | 画面の上に知らせ（ほかの人はログインできず、ログインしている人は追い出される。ほかの人への知らせはログインの画面に出す） |
| 画面の使い方 | 全員 | 「？ この画面の使い方」（共通編） |
| 予備のコードの作り直し | 2 段階認証を設定していて、使える予備のコード（未使用）が 1 つもない人（管理者・補佐が初期化した（G-14）、使い切った） | 画面の上に赤で「予備のコードがありません。認証アプリが使えなくなったときに備えて、アカウント設定の「予備のコード」で作り直してください」。押すと G-16 の予備のコード |
| 要望・依頼の回答 | 課長・確認者が出した要望・依頼に、まだ開いていない管理者側の返信がある（G-22 §6.5） | 「要望・依頼にシステム管理者から回答があります（n 件）」。押すと G-22 の一覧 |
| 要望・依頼の受付 | 管理者・補佐。未受付・返信待ちがある（G-22 §6.5） | 「要望・依頼: 未受付 n 件、返信待ち n 件」。押すと G-22 の一覧 |

予備のコードの確認・復旧コード・再初期化・総入れ替えの知らせ（操作した人の名前と役割・理由。30 日。「心当たりがない」のボタン）、管理者と補佐（開発担当）への凍結・総入れ替えの知らせは、画面のいちばん上に出す（G-14 §6.11）。

### 4.2 確認者・課長（課ごと）

見出しは「（課名） YYYY年M月（確認）」。

| 欄 | 内容 |
|---|---|
| 未チェック | 対象月の、その課の提出済み・確認完了の報告のうち、自分が見られるもの（ラインごとの課では担当のラインの人の報告）で、自分がチェックしていない（または「更新あり」）もの。自分の報告、削除済み、移行データ（`is_legacy = 1`）は除く |
| 回答あり | その課の報告に自分が出した最初のコメントのうち、`thread_status = 'answered'` のもの（対象月に限らない） |
| 未提出 | その課の有効な所属者のうち、対象月に提出済み・確認完了の報告（移行データは数えない）がない人数（課長＝`is_final = 1` の欄だけ。確認者自身も数える）。数え方は G-08 と同じ |
| ボタン | 「未チェックを順に見る」→ G-08（`filter=unchecked&go=1`）を経由して、最初の未チェックの G-05 へ。未チェックが 0 件なら出さない。「提出状況」→ G-08 |

### 4.3 対象月の決め方

- 既定は**前月**（月次報告は前月の状況を月初に報告するため）。
- 課の `close_day` が設定されていて、今日がその日以前（月末を超える日は月末とする）なら、前月のまま。過ぎていれば当月。所属の課か `close_day` がなければ前月。
- 決め方は `report_target_period()`（`report.php`）にまとめる。設定の `report_period_rule` はまだ読んでいない（共通編 §12）。

### 4.4 あなたの役割と権限（K-072）

本人にだけ出す（ほかの人の役割は出さない）。作るのは `app/lib/role.php`。

| 欄 | 内容 |
|---|---|
| 札 | 役職（`users.role_title`。一般・主任・課長代理・課長・部長。専門職の人は専門職の名前と「専門職」。`display_role_title()`）、システムの役割（`system_role_label()`。G-16）、「人財管理者」（`is_hr_manager`）、「部長以上」（`is_executive`） |
| 担当 | 課ごとに「A課（課長）」「A課（確認者）」「A課（確認者・山田ライン）」。無効の課は「・無効の課」を付ける。なければ出さない |
| できること | 初めは畳んでおく（`<details>`）。自分の報告、課ごとの報告の範囲（課の全員／担当のライン）・コメント・チェック・課長の仕事、目標管理（目標管理のあるブランチだけ）、項目管理者、全課共通の調査、システムの管理 |

権限は役職からではなく、画面の制限に使う判定（`report_view_grants()`・`reviewer_does_check()`・`survey_can_manage_all_departments()`・`has_admin_authority()` など）から作る。目標管理の課長代理だけは、判定そのものが役職を使う（G-27）。

## 5. 入力項目と確認

なし。

## 6. 操作と処理

1. 自分の報告（対象月・前月）: `report_records` を `user_id` と `period` で 1 件ずつ探す（`is_legacy = 0 AND deleted_at IS NULL`）。
2. 回答待ち: `report_field_comments` で、自分の報告（削除済みを除く）の `parent_id IS NULL AND thread_status = 'open' AND deleted_at IS NULL`。
3. 臨時の調査: `adhoc_request_targets` で自分が対象、`adhoc_requests.status = 'open'`、`deleted_at IS NULL`、`adhoc_responses.submitted_at` が NULL。
4. 確認者: 自分が `department_reviewers` に入っている課ごとに、対象月の `report_records`（`status IN ('submitted','confirmed')`）と `report_reviews` を突き合わせる。
5. 本文は復号しない（件数と項目名だけを出す）。

## 7. メッセージ

| 状況 | 文言 |

## 9. 検証の観点

- 役割と権限が、役職・設定のとおりに本人にだけ出る（役職が主任でも課長を任されていれば課長の権限。ライン・無効の課・項目管理者・人財管理者・部長以上・管理者・補佐・開発担当。`smoke_deputy.py`・`smoke_surveys_all.py`）。
- 部下には確認者の欄が出ない。確認者には、自分が確認者の課の件数だけが出る。
- 自分の報告は「未チェック」に数えない。
- 「更新あり」の報告が未チェックに数えられる。
- 削除した報告・コメントが数えられない。
- 対象月が締め日の前後で正しく切り替わる。
- スマートフォンの幅で「今月の報告を作る」がはみ出さない。

自動の検証で試しているもの: 表示、回答待ち、臨時の調査、「今月の報告を作る」の表示、部下・確認者の欄（`smoke_screens.py`）、未チェックの数え方（自分の報告・チェック・更新あり。`smoke_edges.py`）、締め日の前後・月末・年の変わり目の対象月（日付を渡して `report_target_period()` を確かめる。`check_units.php`）。
