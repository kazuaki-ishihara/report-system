# G-16 アカウント設定

| 項目 | 内容 |
|---|---|
| URL | `/account.php?tab=<totp|devices|password>`（GET・POST） |
| 利用者 | 全員（自分のアカウント） |
| 主な端末 | スマートフォン |
| 段階 | 1 |
| 関連する機能 | F-01、F-02 |

---

## 1. 目的

2 段階認証の設定、予備のコード、記憶した端末、パスワードの変更を、本人が行う。初回のログインでは、ここで 2 段階認証を設定するまでほかの画面を使えない。

## 2. 表示の条件と権限

- ログインしている本人。
- 2 段階認証が未設定の人（G-01 §6.1 の 6）は、この画面の 2 段階認証の設定だけを使える。
- `must_change_password = 1` の人は、パスワードの変更だけを使える。

## 3. 画面の配置

**2 段階認証の設定（初回）**

```text
┌──────────────────────────┐
│ 2 段階認証の設定            │
├──────────────────────────┤
│ 1. スマートフォンに認証アプリ │
│   （Google Authenticator   │
│   など）を入れてください     │
│ 2. 下のボタンを押すと、認証  │
│   アプリに登録されます       │
│   [ 認証アプリに登録する ]   │ ← otpauth:// のリンク
│   うまくいかないときは、     │
│   次の文字を手で入れます     │
│   ABCD EFGH IJKL MNOP QRST │
│ 3. 認証アプリに出た 6 桁の   │
│   数字を入れてください       │
│   [______]                 │
│   [ 設定する ]              │
└──────────────────────────┘
```

**設定後: 予備のコード**

```text
予備のコード（1 回ずつ使えます）
  k3m9-x2p7q   7hd2-pq8wz   …（8 個）
機種変更などで認証アプリが使えないときに使います。
スクリーンショットではなく、紙に書くなどして保管してください。
[ 保管しました ]
```

**記憶した端末**

```text
記憶した端末
  iPhone の Safari   最後に使用 11/02   期限 2027/01/31  [解除]
  Windows の Chrome  最後に使用 10/30   期限 2027/01/28  [解除]
[ すべての端末からログアウト ]
```

## 4. 表示項目

| 欄 | 内容 |
|---|---|
| 2 段階認証 | 設定済み（日時）／未設定。設定済みなら「設定し直す」「予備のコードを作り直す」 |
| 予備のコード | 作った直後だけ表示する。残りの個数を出す |
| 記憶した端末 | `remembered_devices`（自分の、期限内）。今使っている端末に印 |
| パスワード | 最終変更日 |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 確認のコード | 数字 6 桁。§6.1 の仮の秘密の値で TOTP を確かめる |
| 今のパスワード | パスワードの変更・2 段階認証の設定し直しのときに必須（初回の設定と `must_change_password` のときを除く） |
| 新しいパスワード | 10 文字以上、72 バイト以下、ログイン ID と同じは不可、今のパスワードと同じは不可 |

## 6. 操作と処理

### 6.1 2 段階認証の設定

1. 画面を開いたとき、20 バイトの乱数で秘密の値を作り、**セッションに仮に持つ**（DB にはまだ入れない）。
2. `otpauth://totp/月次報告:<login_id>?secret=<Base32>&issuer=月次報告&digits=6&period=30` のリンクと、Base32 の文字（4 文字ごとに区切る）を出す。QR コードは使わない（外部の部品を使わないため。スマートフォンで設定するので、リンクを押せば認証アプリが開く）。
3. 入力された 6 桁を、仮の秘密の値で確かめる（前後 1 区間）。
4. 正しければ、1 つのトランザクションで `totp_secret_enc`（暗号化）、`totp_enabled_at`、予備のコードを作り直す（古いものは消す。新しい 8 個を `password_hash` で保存）、`session_version + 1`（ほかの端末をログアウトさせる）。セッションを作り直し、今の端末はログイン済みのままにする。
5. 予備のコードを 1 回だけ表示する。

### 6.2 予備のコードを作り直す

今のパスワードを確かめ、古いものを消して新しい 8 個を作り、1 回だけ表示する。

### 6.3 端末の解除・すべての端末からログアウト

- 解除: その `remembered_devices` を消す（自分のものだけ）。
- すべての端末から: 確認の表示のあと、自分の `remembered_devices` をすべて消し、`session_version + 1`。今の端末もログイン画面へ。

### 6.4 パスワードの変更

1. 今のパスワードを確かめる（`must_change_password` のときは不要）。
2. `password_hash`、`password_changed_at`、`must_change_password = 0`、`session_version + 1`。セッションを作り直し、今の端末はログイン済みのまま。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 設定した | 2 段階認証を設定しました。次からはログインのときに 6 桁のコードを入れます（この端末は記憶されています） |
| コードが違う | コードが違います。認証アプリに表示されている最新の 6 桁を入れてください。時計がずれていると合わないことがあります |
| パスワードを変えた | パスワードを変更しました。ほかの端末はログアウトしました |
| 未設定でほかの画面を開いた | 先に 2 段階認証を設定してください |

## 8. 記録

`auth totp:setup`、`auth totp:backup_regenerated`、`auth device:revoke`、`auth logout_all`、`auth password:change`。コード・秘密の値・パスワードは記録しない。

## 9. 検証の観点

- 2 段階認証が未設定の間は、ほかの画面の GET・POST がすべて G-16 に転送される。
- 仮の秘密の値が、確認の前に DB に入らない。
- 予備のコードが、作った直後以外に表示されない。DB にハッシュでしか入っていない。
- ほかの人の端末の記憶を解除できない。
- パスワードの変更・2 段階認証の設定で、ほかの端末のセッションが切れる。
