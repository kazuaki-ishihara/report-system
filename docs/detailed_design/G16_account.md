# G-16 アカウント設定

| 項目 | 内容 |
|---|---|
| URL | `/account.php?tab=<totp|codes|devices|password>`（GET・POST） |
| ファイル | `app/pages/account.php`、`app/views/account.php`、`app/lib/auth.php`・`totp.php` |
| 利用者 | 全員（自分のアカウント） |
| 主な端末 | スマートフォン |
| 段階 | 1 |
| 関連する機能 | F-01、F-02 |

POST の `action`: `totp_redo`（設定し直しの開始）、`totp_confirm`（確認のコード）、`codes_regen`（予備のコードの作り直し）、`device_revoke`（端末の解除）、`logout_all`、`password_change`。

---

## 1. 目的

2 段階認証の設定、予備のコード、記憶した端末、パスワードの変更を、本人が行う。初回のログインでは、ここで 2 段階認証を設定するまでほかの画面を使えない。

## 2. 表示の条件と権限

- ログインしている本人。`page_start()` に `setup` と `must_change` を許す指定をして開く（共通編 §3）。
- 2 段階認証が未設定の人（段階 `setup`。G-01 §6.1 の 6）は、`tab` に関係なく 2 段階認証の設定だけを出す。
- `must_change_password = 1` の人は、パスワードのタブだけ。ただし、2 段階認証の設定の直後の予備のコードの表示は先に見せる。
- 不明な `tab` は `totp` として扱う。
- 端末の解除（`device_revoke`）とすべての端末からのログアウト（`logout_all`）は、通常の状態（段階 `full` で `must_change_password = 0`）のときだけ受け付ける。それ以外は 403。
- タブの見出し（「2 段階認証」「予備のコード」「端末」「パスワード」）は、通常の状態（段階 `full` で `must_change_password = 0`）のときだけ出す。

### 4.5 画面のテーマ（タブ「表示」）

利用者が気分や好みで画面の色合いを選べるようにする。自分の画面だけが変わり、ほかの人には影響しない。

| 項目 | 内容 |
|---|---|
| テーマ | `auto`（自動。端末の明るさの設定に合わせて既定かダーク。既定値）、`light`（既定・明るい）、`dark`（ダーク）、`sakura`（さくら。淡い桜色、画面の名前の前に 🌸）、`wakaba`（若葉。落ち着いた緑、🌿）。一覧は `html.php` の `UI_THEMES` |
| 選び方 | 色の見本付きの選択肢から選び、「このテーマにする」（POST `action=theme_save`）。通常の状態（段階 `full`、仮のパスワードでない）だけ。知らない値は 400。「画面のテーマを「さくら」にしました」 |
| 保存 | `users.ui_theme`（DB 編） |
| 反映 | `layout.php` が `<html data-theme="…">` を付ける（`auto` と未ログインでは付けない）。CSS は色を変数（`--bg`・`--primary` など）で持ち、`[data-theme="…"]` ごとに上書きする。`auto` は `prefers-color-scheme: dark` のときダークの変数を使う |
| 守ること | 注意（客先名らしい言葉）・エラー・確認待ちなどの色の意味は、どのテーマでも変えない（ダークでは暗い背景で読める色に置き換える）。印刷では白地・黒字に戻す |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 確認のコード | 数字 6 桁。§6.1 の仮の秘密の値で TOTP を確かめる（前後 1 区間） |
| 今のパスワード | 2 段階認証の設定し直し・予備のコードの作り直し・パスワードの変更のときに必須（パスワードの変更は `must_change_password` のときを除く）。違うと「今のパスワードが違います」。失敗の回数に数え、ロックになれば `auth login:locked` を記録する |
| 新しいパスワード | `password_min_length`（10）文字以上、72 バイト以下、ログイン ID と同じは不可（小文字にそろえて比べる）、今のパスワードと同じは不可 |
| 新しいパスワード（確認） | 新しいパスワードと同じ |

## 6. 操作と処理

### 6.1 2 段階認証の設定

1. 設定し直しのときは、先に `totp_redo` で今のパスワードを確かめ、セッションに印を付ける（印がなく段階 `setup` でもない `totp_confirm` は 400）。
2. 画面を開いたとき、20 バイトの乱数で秘密の値を作り、**セッションに仮に持つ**（DB にはまだ入れない）。
3. `otpauth://totp/月次報告:<login_id>?secret=<Base32>&issuer=月次報告&digits=6&period=30` のリンクと、Base32 の文字（4 文字ごとに区切る）を出す。QR コードは使わない（外部の部品を使わないため。スマートフォンで設定するので、リンクを押せば認証アプリが開く）。
4. 入力された 6 桁を、仮の秘密の値で確かめる（前後 1 区間）。
5. 正しければ、1 つのトランザクションで `totp_secret_enc`（暗号化）、`totp_enabled_at`、`totp_last_step`、`session_version + 1`（ほかの端末をログアウトさせる）を保存し、予備のコードを作り直す（古いものは消す。新しい `backup_code_count`（8）個を `password_hash` で保存）。
6. セッションを作り直し（段階 `full`）、今の端末はログイン済みのままにする。チェックがあれば端末を記憶する。失敗の回数を 0 に戻す。
7. `?tab=codes` へ移り、予備のコードを 1 回だけ表示する。

### 6.2 予備のコードを作り直す

段階 `full` のときだけ（それ以外は 403）。確認の表示のあと、今のパスワードを確かめ、古いものを消して新しい 8 個を作り、1 回だけ表示する。

### 6.3 端末の解除・すべての端末からログアウト

- どちらも、通常の状態でなければ 403（§2）。
- 解除: その `remembered_devices` を消す（自分のものだけ）。確認の表示はない。
- すべての端末から: 確認の表示のあと、自分の `remembered_devices` をすべて消し、`session_version + 1`。今の端末もログアウトしてログイン画面へ。

### 6.4 パスワードの変更

1. 段階 `full` のときだけ（それ以外は 403）。今のパスワードを確かめる（`must_change_password` のときは不要）。
2. 1 つの UPDATE で `password_hash`、`password_changed_at`、`must_change_password = 0`、`failed_count = 0`、`locked_until = NULL`、`session_version + 1` を更新する。
3. セッションを作り直し、今の端末はログイン済みのまま。ホームへ移る。

2 段階認証が未設定のままほかの画面を開いたときは、メッセージを出さずに `/account.php?tab=totp` へ転送する（共通編 §3）。

## 8. 記録

`auth totp:setup`、`auth totp:backup_regenerated`、`auth device:revoke`、`auth logout_all`、`auth password:change`。今のパスワードを間違えてロックになったときは `auth login:locked`。コード・秘密の値・パスワードは記録しない。

## 9. 検証の観点

- 2 段階認証が未設定の間は、ほかの画面の GET・POST がすべて G-16 に転送される。
- 仮の秘密の値が、確認の前に DB に入らない。
- 予備のコードが、作った直後以外に表示されない。DB にハッシュでしか入っていない。
- ほかの人の端末の記憶を解除できない。
- パスワードの変更・2 段階認証の設定で、ほかの端末のセッションが切れる。

## パスワードを自動で作る・コピーする（APP-022）

- 新しいパスワードの欄の下に「自動で作る」「コピー」を出す（アカウント設定のパスワード・パスワードの再設定）。
- 「自動で作る」: ブラウザーの暗号用の乱数（`crypto.getRandomValues`）で、紛らわしい文字を除いた英数字と記号の 16 文字を作り、新しいパスワードと確認の欄に入れて表示に切り替える。「16 文字のパスワードを作りました。控えるときは「コピー」を押してください。」
- 「コピー」: 新しいパスワードの欄の文字をクリップボードに写す（「コピーしました」）。管理者のユーザーの編集の仮のパスワードにも「コピー」を出す。
- 「文の形（好きな言葉をつなげたもの）…」の案内は出さない（APP-045）。

## 4.6 自分の色（K-046）

テーマの一覧に「自分の色」を足し、土台・強調の色・背景の色を利用者が選べる。

| 項目 | 内容 |
|---|---|
| 選ぶもの | 土台（明るい／暗い）、強調の色（ボタン・見出し・リンク）、背景の色（色の部品 `<input type="color">`。`#rrggbb` の形だけ） |
| 変えない色 | 注意・エラー・状態の札・項目の札の色は、土台（既定・ダーク）の決まった色のまま（色の意味を人によって変えない） |
| 読みやすさ | 文字と背景の明るさの比が足りない組み合わせ（WCAG の式。背景と文字 4.5 未満、強調の色と面 3 未満、ボタンの文字と強調の色 4.5 未満）は、保存したうえで「保存しましたが、読みにくい組み合わせです。」と理由を出す（K-046 決定）。ボタンの文字は白か黒の読みやすい方を自動で選ぶ。色の形が違う（`#rrggbb` でない）ものは保存しない。選んでいる間も、見本の欄と「読みやすい組み合わせです」「…（保存はできますが、読みにくくなります）」を JavaScript ですぐ出す |
| 保存 | `users.ui_custom_colors`（JSON: `base`・`accent`・`background`）、`users.ui_theme = 'custom'`。ほかのテーマに戻しても選んだ色は残る |
| 画面への出し方 | html の `data-theme` は土台（`light`／`dark`）、`data-custom-colors="1"` を付け、`/css/user_theme.php?v=<版>` を `app.css` のあとに読む（`app/lib/user_theme.php` の `user_theme_css()`。強調の色・背景の色と、それを少し混ぜたボタン・行・枠の色を、色の変数に入れる）。CSP（`style-src 'self'`）のため、画面の中には色を書かない |
| 自分の色の CSS | ログインしている本人が「自分の色」を使っているときだけ色を返す。ほかの人・ログインしていない人には色を返さない |
| テーマの色見本 | 自分の色の色見本は、選んでいる色を JavaScript で出す（保存してあれば CSS でも出す） |

検証: `tools/test/smoke_theme.py`（`verify_all.py` の工程 theme）。
