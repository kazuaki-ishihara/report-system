## 1. 目的

総務の「交通費・通勤定期代精算書」（Excel の様式）を、各自が Web で作り、様式のとおりの xlsx で受け取れるようにする。月次報告とは別の機能で、承認の流れはない（受け取った xlsx を、これまでどおり提出する）。

- **受け付けるのは通勤定期だけ**。通勤実費・業務交通費・その他は別のシステムで受け付けるので、この画面では登録できない（種別は選べず「通勤定期」に決まっている。ほかの種別を送られても保存しない）。

## 2. 見られる人と記録

- 精算書を見る・直す・写す・消す・受け取るのは、作った本人だけ。確認者・課長・システム管理者・補佐も見られない（ほかの人の精算書の ID は 404）。
- 中身（上の欄・明細・仮払い）は、まとめて JSON にして暗号化し、`expense_sheets.data_enc` に入れる（付加データ `expense_sheets:<利用者 ID>`。ほかの人の行に写しても読めない）。
- 記録（`access_logs`）には残さない（本人だけのもので、管理者が見る記録に出さないため）。
- 管理者の削除データ・保管期限による削除の対象にしない（消すと元に戻せない）。

## 3. 画面

### 3.1 一覧（`/expenses/index.php`）

- 「＋ 新しく作る」、自分の精算書の一覧（新しい順に 100 件まで）: 提出日・精算方法・明細の行数・合計・最後に保存した日時。
- 行ごとに「開く」「Excel」（PC だけ）「写して新しく作る」。
- 上に「このシステムで受け付けるのは通勤定期だけです。通勤実費・業務交通費などは、別のシステムで申請してください。」を出す。

### 3.2 作る・直す（`/expenses/edit.php`）

```text
┌──────────────────────────────────────────┐
│ ← 通勤定期代の精算                              │
│ 精算書を作る                                    │
│ [このシステムで受け付けるのは通勤定期だけです…]      │
│ [精算書の Excel を受け取る（.xlsx）]（保存後・PC）    │
├ 精算書の上の欄 ───────────────────────────┤
│ 精算方法 (●振込 ○現金)  提出日 [2026-11-20]        │
│ 社員番号 [   ]  所属 [大阪▼]  部署 [   ]  氏名 [   ] │
├ 明細（26 行まで）─────────────────────────┤
│ # 月／日(から) 月／日(まで) 種別 業務・行先 交通手段   │
│   発～(経由)～着 片道往復 金額                     │
│ 1 [2026-11-01] [2027-04-30] 通勤定期 [  ] [私鉄▼]  │
├ 金額 ─────────────────────────────────────┤
│ 小計: 61,830 円  仮払い [    ]  合計: 61,830 円    │
│ [保存]                                         │
│ [この精算書を削除]（直すとき）                       │
└──────────────────────────────────────────┘
```

| 欄 | 決まり |
|---|---|
| 精算方法 | 振込・現金（必須。既定は前に作った精算書と同じ、無ければ振込） |
| 提出日 | 日付（必須。既定は今日） |
| 社員番号 | 20 文字まで（必須） |
| 所属 | 大阪・東京（様式の選択肢。必須） |
| 部署・氏名 | 40 文字まで（必須。既定は前に作った精算書、無ければ所属の課の名前・表示名） |
| 明細 | 1 行に 1 つの定期券。26 行まで（様式の 13 行 × 2 枚）。入力欄は書いた行のあとに空の行を足して出す（13 行に満たなければ 13 行）。空の行は捨てる |
| 月／日（から・まで） | 日付。「から」は必須。「まで」は空でもよいが、入れるなら「から」と同じかあとの日 |
| 種別 | 「通勤定期」に決まっている（入力欄はない）。ほかの値を送られたら「通勤定期のほか（通勤実費・業務交通費など）は、このシステムでは受け付けません。別のシステムで申請してください」 |
| 業務・行先 | 60 文字まで（空でもよい） |
| 交通手段 | ＪＲ・私鉄・地下鉄・バス・タクシー・その他（様式の選択肢。必須） |
| 発～(経由)～着 | 80 文字まで（必須） |
| 片道往復 | 片道・往復（必須） |
| 金額・仮払い | 0〜9,999,999 の円の数。全角の数字・カンマ・「円」は取り除いてから確かめる。仮払いは空でもよい |

- 小計（明細の金額の合計）と合計（小計 − 仮払い）は、入力のたびに画面で計算して出す（`public/js/app.js`）。保存のときはサーバーで計算する。
- 誤りがあれば保存せず、誤りの一覧と入れた値を出す。
- 「写して新しく作る」は、上の欄と明細を写し、提出日を今日、仮払いを空にする（定期券を毎回同じ区間で更新するため）。
- 削除は確認の表示のあと。元に戻せない。
- メンテナンス中は保存・削除を受け付けない（共通の決まり）。二重送信は送信の番号で防ぐ（`rk_begin()`）。

### 3.3 様式の xlsx を受け取る（`/expenses/download.php?id=<ID>`）

- 総務の様式（`app/templates/expense_sheet.xlsx`。`C:\ReportSystem\data\交通費通勤定期代精算書.xlsx` をそのまま入れたもの）の 1 枚目のシート「精算書(交通費通勤定期代)」に値を入れて渡す。罫線・並び・表示形式・入力規則（選択肢）・小計と合計の式・シートの保護・2 枚目のシート「記入例」は様式のまま。
- 値を入れるセル（`EXPENSE_TEMPLATE_PAGES`）:

| 欄 | No.1 | No.2（明細が 13 行を超えたとき） |
|---|---|---|
| 精算方法・提出日（年・月・日） | C3・F3・H3・J3 | C34・F34・H34・J34 |
| 社員番号・所属・部署・氏名 | C5・F5・I5・O5 | C36・F36・I36・O36 |
| 明細（月／日・月／日・種別・業務・行先・交通手段・発～着・片道往復・金額） | 8〜20 行の A・B・C・D・I・M・V・W | 39〜51 行 |
| 小計・仮払い・合計 | W21・W22・W23 | W52・W53・W54 |

- 日付は Excel の日付の数（様式の表示形式 m/d のまま）。社員番号は数字だけなら数、そうでなければ文字。文字は inlineStr で入れる（共有文字列の表は変えない）。
- 仮払いは No.1 に入れる。小計・合計の式は残し、計算した値も入れる。開いたときに計算し直す（`calcPr fullCalcOnLoad="1"`）。
- 支払日・印・受付の欄（3・2・1）は空のまま（総務が書く）。
- zip は自前で読み書きする（zip の拡張が無い環境のため。読みは格納と deflate、書きは格納だけ）。
- ファイル名は `<社員番号>_交通費通勤定期代精算書_<提出日>.xlsx`（社員番号のうち、ファイル名に使えない文字・空白は取り除く）。スマートフォンからは 403（「精算書のファイルは PC で受け取ってください。」。出力と同じく、スマートフォンにファイルを残さないため）。
- 様式が変わったら `app/templates/expense_sheet.xlsx` を差し替え、セルの位置が変わっていれば `EXPENSE_TEMPLATE_PAGES` を直す（様式に無いセルに入れようとすると例外にする）。

## 4. メニューと使い方

- メニューの見出し「精算」に「通勤定期代の精算」（全員）。
- 「？ この画面の使い方」: 一覧・作る画面に出す（`screen_help_text()` の `expense_list`・`expense_edit`）。

## 5. 検証の観点

自動検証の工程「通勤定期代の精算（本人だけ・通勤定期だけ・様式の xlsx）」（`tools/test/smoke_expenses.py`）。

- 通勤定期のほかの種別は保存しない。明細の無い精算書・入力の誤りは保存しない（入れた値は残る）
- 14 行の保存、小計・合計、全角の金額
- 確認者・課長・管理者・補佐・同じ課の人は、開く・写す・受け取る・消すが 404。一覧にも出ない
- DB の中身が暗号化されている。記録に残らない
- xlsx: 中のファイルの一覧が様式と同じ、記入例・書式・共有文字列が様式のまま、値の入るセル、2 枚目、式と値、シートの保護、計算し直す設定、zip の CRC
- スマートフォンでは受け取れない（入力はできる）。写す・消す
