# G-04 報告の作成・編集

| 項目 | 内容 |
|---|---|
| URL | `/reports/edit.php?period=YYYY-MM`（GET: 画面）、`/reports/save.php`（POST: 保存・提出・取り下げ・自動保存） |
| 利用者 | 本人（報告を作る人） |
| 主な端末 | スマートフォン |
| 段階 | 1（前月の引き継ぎ・変更なし・提出後の追記は 2） |
| 関連する機能 | F-05、F-10、F-11、F-23 |

---

## 1. 目的

様式（共通項目＋所属課の課別項目）に従って入力画面を組み立て、月次報告を作る・直す・提出する。**前月の内容が入った状態で開き、変わったところだけ直せばよい**ようにする。

## 2. 表示の条件と権限

| 状態 | 本人 | ほかの人 |
|---|---|---|
| 未作成 | 作成できる | 開けない |
| 下書き | 編集・提出・削除できる | 開けない（G-05 でも見えない） |
| 提出済み | 追記・修正できる（変更履歴が残る）。取り下げできる | 開けない（G-05 で見る） |
| 確認完了 | 開けない（G-05 で見る） | 開けない |

- 管理者は、本人に代わって編集できる（変更履歴に管理者の名前が残る）。
- 所属課が設定されていない人は「所属の課が設定されていません。管理者に連絡してください」と出して止める。
- 対象月は、当月と過去 3 か月まで（未来の月は不可）。

## 4. 表示項目

### 4.1 様式の組み立て

1. 対象の課 = 本人の所属課（報告が既にあれば、報告の `department_id`）。
2. 新しく作るときは、`report_fields` から `is_active = 1` かつ（`department_id IS NULL` または対象の課）の項目を、共通項目→課別項目、`sort_order` の順に並べる。作成の時点で `report_record_fields` に定義を写す（以後、この報告はこの定義で表示する）。
3. 既にある報告は、`report_record_fields` の定義で組み立てる（項目マスタをあとで変えても、この報告の見え方は変わらない）。
4. `field_scope = 'project'` の項目は案件ブロックの中に、`'report'` の項目は「報告全体」の欄に出す。
5. `settings_json.show_when`（例: 進捗が「遅延あり」のときだけ「進捗の補足」を出す）は、画面の JavaScript で表示を切り替える。隠れた欄の値は送らず、サーバーも空として扱う。

### 4.2 入力部品の出し方

| 種類 | 部品 |
|---|---|
| `project` | プルダウン（有効な `projects` のうち、所属課の案件と課の指定がない案件。表示は「コード 社内向けの呼び名」） |
| `single_text` | `<input type="text">` |
| `multi_text` | `<textarea>`（入力に合わせて高さが伸びる） |
| `date`・`month` | `<input type="date">`・`<input type="month">` |
| `number` | `<input type="number" inputmode="decimal">` |
| `select` | `<select>`（選択肢 5 個以下なら `radio` で出してもよい。設定で指定） |
| `radio` | ラジオボタン（縦に並べ、押しやすい大きさ） |
| `checkbox` | チェック 1 つ |
| `multi_check` | チェックボックス |
| `table` | 行ごとの入力。「行を追加」「この行を消す」 |

- 項目名の横に、必須の印と、機密区分の札（社外秘・限定）を出す。
- 説明文（`help_text`）を欄の下に、入力例（`placeholder`）を欄の中に出す。
- 自由記述の欄には「客先名・固有名詞・個人名を書かないでください」を常に出す。

### 4.3 前月からの引き継ぎ（段階 2）

新しく作るとき、同じ人の直前の月の報告（削除されていないもの）があれば、次を写す。

| 対象 | 写すもの |
|---|---|
| 案件ブロック | 前月の案件ブロックをすべて（`report_projects`）。ただし、無効になった案件は写さず、「前月の案件 P-0007 は終了したため外しました」と出す |
| 項目の値 | `carry_over = 1` の項目の値。前月の報告の定義と今の定義で、種類と選択肢が両立するものだけ（無効になった選択肢の値は写さない） |
| 自由記述 | `carry_over = 1` なら写す（復号して、新しい行用に暗号化し直す） |

`copied_from_id` に前月の報告の ID を入れる。

## 5. 入力項目と確認

- 項目ごとの確認は共通編 §9.2 に従う。設定は `report_record_fields.settings_json` を使う。
- 案件ブロック: 同じ案件を 2 つ入れられない。案件ブロックは最大 10 個。
- 必須の確認は、**提出のとき**と**提出済みの報告を保存するとき**だけ行う。下書きの保存と自動保存では行わない。
- 「先月から変更なし」がオンのときは、項目の入力を受け取らず、引き継いだ値のまま提出する（必須の確認は引き継いだ値に対して行い、足りなければ入力を開いて知らせる）。

## 6. 操作と処理

すべて `/reports/save.php` に POST する。`action` で分ける。共通: CSRF の確認 → 送信の番号の確認 → 権限と状態の確認 → 入力の確認 → 1 つのトランザクション → 転送。

### 6.1 画面を開く（GET）

1. `period` を確かめる。本人の `(user_id, period)` の報告を探す（削除されていないもの）。
2. なければ、まだ作らずに、§4.1・§4.3 で組み立てた入力画面を出す（最初の保存で作る）。
3. 確認完了なら G-05 へ転送する。

### 6.2 下書き保存（`action=draft`）・自動保存（`action=autosave`）

1. 報告がなければ作る（`status = 'draft'`）。`report_record_fields` に定義を写す。同時に 2 回作られないよう、一意の索引 `ux_report_user_period` で守り、重複したら既にあるほうを使う。
2. 案件ブロックを入れ替える（消えたブロックの値は消す）。
3. 値を保存する。自由記述と「限定」は暗号化。客先名らしい言葉があれば `has_warning = 1`。
4. 自動保存は、画面の JavaScript が**入力が変わったときだけ、60 秒ごと**に送る。応答は JSON（`{"ok":true,"saved_at":"10:42"}`）。下書きのときだけ行い、提出済みでは行わない（変更履歴が細かく増えるため）。

### 6.3 提出（`action=submit`）

1. 下書きの保存と同じ処理のあと、必須の確認を行う。足りなければ下書きとして保存したうえで、足りない欄を示して戻す。
2. 客先名らしい言葉の注意が残っている欄があり、確認の表示で「このまま提出」を選んでいなければ、欄を示して確認を出す（止めはしない）。
3. `status = 'submitted'`、`submitted_at`。`report_status_history` に記録。
4. 「先月から変更なし」のときは `unchanged = 1`。
5. G-05 へ転送し「提出しました」。

### 6.4 提出後の追記・修正（`action=save`、状態が提出済み）

1. 値を比べ、変わった値ごとに `report_value_history` に変更前・変更後を残す（暗号化の対象なら暗号化したまま）。
2. 1 つでも変われば `revision + 1`。チェック済みの確認者は「更新あり」になる（`report_reviews.checked_revision < revision`）。
3. 変わったものがなければ何もしない。
4. 再提出の操作はない（基本設計書 §4.1）。

### 6.5 取り下げ（`action=withdraw`、状態が提出済み）

確認の表示のあと、`status = 'draft'`。チェックはそのまま残す（再び提出したとき、変更がなければチェック済みのまま）。

### 6.6 下書きの削除（`action=delete`、状態が下書き）

確認の表示のあと、`deleted_at` を入れる。30 日間は管理者が戻せる（G-15）。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 下書き保存 | 下書きを保存しました |
| 自動保存 | 自動保存しました hh:mm（小さく出す） |
| 提出 | 提出しました |
| 提出済みの保存 | 保存しました。確認者に更新を知らせます |
| 必須の不足 | 入力が必要な項目があります（各欄の下に「入力してください」） |
| 客先名らしい言葉 | 客先名や個人名が含まれていませんか（欄の下）。提出の前: 「注意が出ている欄があります。このまま提出しますか？」 |
| 同じ案件 | 同じ案件が 2 つあります |
| 前月の案件が終了 | 前月の案件 P-0007 は終了したため外しました |
| 確認完了 | この報告は確認が完了しているため、変更できません |
| 通信が切れた | 共通編 §11.3 |

## 8. 記録

本人の操作は記録しない。管理者が代わりに編集したときは `admin report:<id>:edit_by_admin`。

## 9. 検証の観点

- ほかの人の報告の `period` を指定しても、自分の報告しか開けない（ほかの人の ID を POST しても断られる）。
- 同じ送信の番号で 2 回提出しても、提出は 1 回。2 つの端末から同時に新規作成しても、報告は 1 件。
- 下書きでは必須を確かめず、提出では確かめる。隠れた欄（`show_when`）は必須でも空でよい。
- 項目マスタを変えたあとも、既にある報告は作成時の定義で表示・保存される。
- 無効にした選択肢の値は、前月から引き継がれない。
- 提出後の修正で `revision` が上がり、チェック済みの確認者が「更新あり」になる。変更がなければ上がらない。
- DB に自由記述が平文で入っていない。
- 確認完了の報告に POST しても変わらない。
- 案件ブロック 0 件・10 件、自由記述の上限ちょうど・1 文字超えで動きが正しい。
