---

## 1. 目的

課の外からの依頼などを受けて、課長が臨時の調査を作り、課の人に答えてもらい、結果を見る。
システム管理者・補佐は、課をまたいで同じ質問の調査（全課共通）を作り、全課の集計と課ごとのまとめを見る（§10。K-066）。

## 2. 表示の条件と権限

- 課長は、自分の課の依頼だけ。全課共通の依頼（`department_id` が NULL）はシステム管理者・補佐だけ（`survey_can_manage()`。課長でも 403）。一覧・作成の画面は、どこかの課の課長かシステム管理者・補佐が開ける（`survey_can_use_manage_screens()`）。ほかの人は 403（管理者でも課長でなければ。回答は報告の中身と同じ扱い。管理者でも、確認者でない課の報告の中身は見られない（共通編 §10.2）。）。
- 対象の候補は、依頼の課の有効な利用者。サーバーは、依頼の課の有効な利用者だけを受け付ける（それ以外は 400）。
- 結果を開けるのはその課の課長だけ（`survey_can_manage()`）。`summary` の依頼でも、課長は個人の回答を見られる（依頼元に渡す出力が集計だけになる）。結果の画面では「限定」の質問もそのまま出す。
- 結果を開けるのは、公開した依頼（`status` が `open`・`closed`）だけ。下書き・ひな形（`is_template = 1`）は 404。一覧・編集の画面でも、下書き・ひな形には「結果」のリンクを出さない。
- 独自の質問を「限定」にできるのは、その課の課長。

- 状態の絞り込み: すべて・下書き・公開中・締め切り・ひな形。
- 操作: 下書きとひな形は「編集」、公開後は「設定」。下書き以外は「結果」も出す。締め切り・複製などは編集の画面で行う。

**作成・編集**

- 「回答する人の画面で見る」（見本）で、公開の前でも回答の画面を確かめられる（§6）。
- 公開後は質問の欄を出さず、「公開後は、題名・依頼元・目的・期限だけ変えられます。対象 n 人。」と出す。
- 「公開する」は下書き（ひな形を除く）、「締め切る」は公開中、「結果を見る」は下書き以外、「ひな形として保存」はひな形以外のときだけ出す。

## 4. 表示項目

### 4.1 一覧

- `adhoc_requests`（削除されていないもの、自分が課長の課）。システム管理者・補佐には全課共通の依頼も出す（課の列は「全課共通」）。課長でない管理者に、課の依頼は出さない。
- 並びは、ひな形を後ろにし、作成日時の新しい順。
- 回答は、下書きなら「—」、それ以外は「回答済み数（`adhoc_responses.submitted_at` の件数）/ 対象者数」。
- 一覧を開いたとき、期限（`due_at`）が今日より前の公開中の依頼を締め切る。

### 4.2 結果（`result.php`）

| 表示 | 内容 |
|---|---|
| 回答の状況 | 「回答 n/m」（m は対象者の数）と、対象者がいれば「（回答率 n%）」 |
| 集計 | 選択式（`select`・`radio`・`multi_check`・`checkbox`）の質問ごとに、選択肢ごとの件数と割合（回答者数に対する整数の %）と、割合の横棒のグラフ（`survey_tally()`・`survey_bar_svg()`。G-10 の印刷と同じ）。複数回答（`multi_check`）の質問は見出しに「（複数回答）」。表の上に「割合は回答者数に対する % です。複数回答の質問は、足すと 100% を超えます。」。「未回答」は、回答を出した人のうちその質問を空にした人の数（複数回答で 1 つも選ばなかった人も含む）。チェック（`checkbox`）は「はい」と「チェックなし」の 2 行にし、「未回答」の行は出さない（チェックしないことも答えのため） |
| 個人の回答 | 「個人の回答を表示」（`?detail=1`）を押したときだけ、全員分を復号して表で出す（記録に残る） |
| 未回答者 | 「未回答（n人）」として、回答を出していない対象者の名前を出す（催促の機能は作らない。基本設計書 §1.6） |
| 出力 | 「出力へ」で G-10 を `/export/index.php?type=survey&survey_id=<id>` で開く |

- 結果を開いたときも、期限切れの依頼を締め切る。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 課 | 新規のときだけ。自分が課長の課。それ以外は 403 |
| 題名 | 必須、1〜100 文字 |
| 依頼元・目的 | 0〜100 文字・0〜300 文字（目的は改行可） |
| 回答期限 | 入れたなら今日以降の日付（保存のときも）。公開するときは必須 |
| 結果の扱い | `summary`／`detail`。それ以外は 400 |
| 対象（`target_type`） | `all`／`users`。それ以外は 400。人数（0 人）の確認は公開のとき |
| 質問の数 | 公開のときに 1〜20 問。足すときには上限を見ない |
| 月次の項目 | 有効で、種類が `project`・`table` でなく、共通か依頼の課の項目。外れたら 400 |
| 独自の質問 | 種類は `single_text`・`multi_text`・`number`・`date`・`month`・`select`・`radio`・`checkbox`・`multi_check`（`table`・`project` は使えない）。質問 1〜100 文字、説明 0〜300 文字。選択式は選択肢を 1 行に 1 つ（各 1〜60 文字、1 つ以上）。選択肢のコードは `o1`、`o2`… を自動で振る。最大文字数などの設定は持たない |

## 6. 操作と処理

基本の内容（`save_meta`）と質問（足す・並べ替え・外す）は、別々の POST で 1 つずつ保存する。送信の番号の控えは `survey.<action>`。

| 操作 | 処理 |
|---|---|
| 保存（`save_meta`） | 新規は `status = 'draft'` で作る。`target_type = 'users'` なら、選んだ人を `adhoc_request_targets` に入れ替える（1 つのトランザクション）。公開後は題名・依頼元・目的・期限だけを更新する |
| 質問を足す・並べ替え・外す | 下書きのときだけ（公開後は 400「公開後は質問を変えられません。」）。並べ替えは隣と入れ替え、10, 20… で振り直す |
| 公開 | ひな形は 400「ひな形は公開できません。複製して使ってください。」。期限と質問の数を確かめる。`target_type = 'all'` なら、公開の時点の課の有効な利用者を `adhoc_request_targets` に入れ直す。対象が 0 人なら「対象者がいません」。`status = 'open'`、`opened_at` |
| 締め切り | 公開中のときだけ（それ以外は 400）。`status = 'closed'`、`closed_at`。期限を過ぎたものは、一覧・結果・回答（G-07）の画面を開いたときに自動で締め切る（`due_at` < 今日） |
| 複製 | 質問と設定を写して新しい下書きを作る。題名に「（複製）」を付け、対象は「課の全員」、期限は空 |
| ひな形として保存 | 今の依頼を写して、**新しい**ひな形（下書き、`is_template = 1`、対象は課の全員、期限なし）を作る。元の依頼はそのまま残る |
| 月次の項目へ移す | 独自の質問の横に、その課の課長のときだけリンクを出す（管理者でも課長でなければ出ない）。G-12 の作成画面（`/admin/field_edit.php?dept=<課>&from_q=<質問ID>`）に写して開く（保存は G-12 で行う） |
| 回答する人の画面で見る（見本） | 編集の画面の「操作」に出す（状態・ひな形に関係なく）。`/surveys/answer.php?id=<依頼>&preview=1` を GET で開く。調査を管理できる人（その課の課長）だけ。ほかの人は 404。G-07 と同じ画面を、空の回答で出す。上に「回答する人に見える画面の見本です。入力して確かめられますが、「回答する」は押せず、何も保存されません。」を出し、入力欄はフォームに入れない（Enter でも送られない）。「回答する」は押せない形で出す。何も保存しない（2026-11-18） |
| 削除 | 状態に関係なくできる。`deleted_at` を入れて一覧へ。30 日間は管理者が戻せる（G-15） |

全課共通の依頼の違いは §10。

月次の項目を質問にしたときは、項目マスタの定義（表示名・種類・機密区分・説明・設定・有効な選択肢）を `adhoc_request_fields` に写す。必須は写さず、常に任意にする。あとで項目マスタを変えても、この依頼は変わらない。

## 8. 記録

- 公開・締め切り・削除: `admin survey:<id>:open|close|delete`。複製・ひな形・保存は記録しない。
- 結果の個人の回答を開いた: `view survey:<id>:responses`。

## 9. 検証の観点

- 確認者・部下・別の課の課長は作れない・見られない。
- 公開後に質問を変える POST が断られる。
- 対象者を、自分の課の外の人にできない（課長）。
- 締め切り後は回答できない。期限を過ぎると自動で締め切られる。
- ひな形は公開できない。
- 全課共通: 管理者・補佐が作れる、課長は一覧に出ず開けない、文の質問・「限定」・月次の項目は 400、対象は課に所属する全員、結果に名前を出さない、回答が少ない課も内訳を出す、出力（`smoke_surveys_all.py`）。

## 10. 全課共通の調査（K-066。2026-11-24）

システム管理者・補佐・人財管理者が、すべての課に同じ質問で聞く調査。`adhoc_requests.department_id` を NULL にして表す（`survey_is_all_departments()`）。

| 項目 | 内容 |
|---|---|
| 作る | 作成の画面の「課」で「全課共通（すべての課の全員）」（`department_id=all`）を選ぶ。システム管理者・補佐・人財管理者だけ（`survey_can_manage_all_departments()`。ほかは 403）。DB の表を作り直す前（`migrate.php` の前）は選べない（`survey_all_departments_supported()`） |
| 対象・結果の扱い | 対象は「全員」、結果の扱いは「集計のみ」に固定する（送られた値は使わない）。公開の時点で、有効な課に所属する有効な利用者全員を `adhoc_request_targets` に入れる（`survey_all_departments_members()`。課の無い管理者・補佐は入らない） |
| 質問 | 選択式とチェックだけ（`SURVEY_ALL_DEPARTMENTS_TYPES`。だれも個人の回答を見ないので、集計できるものに限る）。「限定」は使えない（課長がいないため）。月次の項目は使えない。違反は 400 |
| 回答 | G-07 と同じ（対象者のホームに出る） |
| 結果（`result.php`） | 全課の回答の状況、課ごとの回答の状況（課・対象・回答・回答率・横棒）、質問ごとに全課の集計（件数・割合・横棒・未回答）と課ごとの内訳（課 × 選択肢の件数と割合）。個人の回答（`detail=1` も）・未回答者の名前は出さない。課は今の所属で数える（異動した人は今の課、所属がなくなった人は「所属なし」）。課ごとの内訳は、回答者の人数にかかわらず出す（数字を知るための機能のため。名前は出さない。2026-11-24 指示）。回答者が 0 人の課は「回答なし」 |
| 出力 | G-10 の画面ではなく、結果の画面から出す（POST `format=print|xlsx|csv`。PC からだけ）。見出しは G-10 §4.1 と同じ 4 行（2 行目は「臨時の調査（全課共通） <題名>（依頼元: …）」）。xlsx・CSV は「課・質問・選択肢・件数・割合」（全課の行のあとに課ごとの行。内訳を出さない課は 1 行だけ）と、空行のあとに「課・対象・回答・回答率」。印刷は結果の画面と同じ表。ファイル名 `survey_all_<ID>_<日時>`。記録 `export export:survey;id=<ID>;format=<形式>;scope=all_departments` |
| 課長との関係 | 課長は全課共通の調査を管理・閲覧できない（自分の課の分も見ない。仮）。ただし「結果を見られる人」に指定されれば、ほかの人と同じく結果を見られる |
| 結果を見る人（K-067。2026-11-24 指示） | 結果を見るのは依頼元と部長以上（管理者・補佐は作成と集計の代行）。見られるのは、管理者・補佐・人財管理者、「部長以上」の印の人（`users.is_executive`。すべての全課共通の調査。G-14）、調査ごとに指定した「結果を見られる人」（`adhoc_request_viewers`）。判定は `survey_can_view_all_departments_result()`。見られる範囲は管理者と同じ（全課の集計・課ごとのまとめ・出力。個人の回答と名前は出さない）。設定は開けない（403） |
| 人財管理者（K-071） | 「人財管理者」の印（`users.is_hr_manager`。G-14）の人は、すべての全課共通の調査を作成・公開・締め切り・複製・削除でき、結果（集計）を見て出力でき、「結果を見られる人」を指定できる（管理者と同じ）。課の調査・個人の回答・報告の中身・ほかの管理の画面は見られない。削除したものを戻すのは管理者 |
| 結果を見られる人の指定 | 全課共通の調査の編集の画面の「結果を見られる人」（`action=save_viewers`、`viewers[]`）。候補は有効な利用者全員（課の無い人を先に。`survey_viewer_candidates()`）。候補にない ID は 400。公開の後でも変えられる。複製・ひな形にも写す。記録 `admin survey:<id>:viewers;count=<人数>` |
| 調査の結果（一覧） | `/surveys/results.php`（`survey_results.php`）。管理者・補佐・人財管理者でなく、部長以上か、どれかの調査の「結果を見られる人」のときメニューに「調査の結果」を出す（`survey_has_result_viewing_menu()`）。公開した全課共通の調査のうち見られるもの（題名・依頼元・状態・期限・回答 n/m・「結果」）。見られるものがなく部長以上でもなければ 403。結果の画面の戻り先は、管理しない人には「← 調査の結果」 |
