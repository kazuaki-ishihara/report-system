# G-11 臨時の調査の管理

| 項目 | 内容 |
|---|---|
| URL | `/surveys/manage.php?state=`（GET: 一覧）、`/surveys/survey_edit.php`（GET: 新規）、`/surveys/survey_edit.php?id=`（GET: 編集。POST: 下の `action`）、`/surveys/result.php?id=`（GET: 回答の一覧・集計。`&detail=1` で個人の回答） |
| ファイル | `app/pages/survey_manage.php`・`survey_edit.php`・`survey_result.php`、同じ名前の `app/views/`、`app/lib/survey.php` |
| 利用者 | 課長 |
| 主な端末 | PC |
| 段階 | 2 |
| 関連する機能 | F-14 |

`survey_edit.php` の POST の `action`: `save_meta`（基本の内容の保存）、`add_source`（月次の項目を足す）、`add_custom`（独自の質問を足す）、`q_up`・`q_down`・`q_remove`（並べ替え・外す）、`publish`、`close`、`copy`、`save_template`、`delete`。

---

## 1. 目的

課の外からの依頼などを受けて、課長が臨時の調査を作り、課の人に答えてもらい、結果を見る。

## 2. 表示の条件と権限

- 課長は、自分の課の依頼だけ。ほかの人は 403（管理者でも課長でなければ。回答は報告の中身と同じ扱い。管理者でも、確認者でない課の報告の中身は見られない（共通編 §10.2）。）。
- 対象の候補は、依頼の課の有効な利用者。サーバーは、依頼の課の有効な利用者だけを受け付ける（それ以外は 400）。
- 結果を開けるのはその課の課長だけ（`survey_can_manage()`）。`summary` の依頼でも、課長は個人の回答を見られる（依頼元に渡す出力が集計だけになる）。結果の画面では「限定」の質問もそのまま出す。
- 結果を開けるのは、公開した依頼（`status` が `open`・`closed`）だけ。下書き・ひな形（`is_template = 1`）は 404。一覧・編集の画面でも、下書き・ひな形には「結果」のリンクを出さない。
- 独自の質問を「限定」にできるのは、その課の課長。

## 3. 画面の配置

**一覧**

```text
臨時の調査
[すべて ▼] [表示] [ ＋ 新しく作る ]
┌────────────────────┬────┬──────┬──────────┬──────┬──────────┐
│題名                 │課   │状態   │期限       │回答   │           │
├────────────────────┼────┼──────┼──────────┼──────┼──────────┤
│AI の利用状況          │A課  │公開中 │2026-11-20│6/10  │設定 結果   │
│ 依頼元: 経営企画      │    │      │          │      │           │
│来月の稼働予定         │A課  │締め切り│2026-10-31│10/10 │設定 結果   │
│新しい調査             │A課  │下書き │—         │—     │編集        │
│技術調査               │A課  │ひな形 │—         │—     │編集        │
└────────────────────┴────┴──────┴──────────┴──────┴──────────┘
```

- 状態の絞り込み: すべて・下書き・公開中・締め切り・ひな形。
- 操作: 下書きとひな形は「編集」、公開後は「設定」。下書き以外は「結果」も出す。締め切り・複製などは編集の画面で行う。

**作成・編集**

```text
← 臨時の調査
AI の利用状況 [下書き]
課       [A課 ▼]（新規のときだけ）
題名     [__________________]
依頼元   [__________]
目的     [____________________]（回答する人に表示します）
回答期限 [2026-11-20]
結果の扱い (●依頼元には集計のみを渡す  ○個人の回答も渡す)
対象     (●課の全員（公開の時点の所属者）  ○人を指定)
  ▸ 人を指定するとき  ☐ 山田 ☐ 鈴木 …
[ 作成して質問を足す ]（作成後は [ 保存 ]）

質問（2）
  1. 作業フェーズ  プルダウン・月次の項目         [↑][↓][外す]
  2. AI を使っていますか  ラジオ・必須             [↑][↓][外す] 月次の項目へ移す
月次報告の項目を使う  [作業フェーズ ▼] [足す]
この調査だけの質問を足す
  質問 [____]  答え方 [ラジオ ▼]  選択肢（1 行に 1 つ）[____]
  機密区分 [社外秘 ▼]  説明 [____]  [☐ 必須]  [足す]

[ 公開する ] [ 締め切る ] [ 結果を見る ] [ 複製 ] [ ひな形として保存 ] [ 削除 ]
```

- プレビューはない。
- 公開後は質問の欄を出さず、「公開後は、題名・依頼元・目的・期限だけ変えられます。対象 n 人。」と出す。
- 「公開する」は下書き（ひな形を除く）、「締め切る」は公開中、「結果を見る」は下書き以外、「ひな形として保存」はひな形以外のときだけ出す。

## 4. 表示項目

### 4.1 一覧

- `adhoc_requests`（削除されていないもの、自分が課長の課）。
- 並びは、ひな形を後ろにし、作成日時の新しい順。
- 回答は、下書きなら「—」、それ以外は「回答済み数（`adhoc_responses.submitted_at` の件数）/ 対象者数」。
- 一覧を開いたとき、期限（`due_at`）が今日より前の公開中の依頼を締め切る。

### 4.2 結果（`result.php`）

| 表示 | 内容 |
|---|---|
| 集計 | 選択式（`select`・`radio`・`multi_check`・`checkbox`）の質問ごとに、選択肢ごとの件数と割合（回答者数に対する整数の %）。「未回答」は、回答を出した人のうちその質問を空にした人の数 |
| 個人の回答 | 「個人の回答を表示」（`?detail=1`）を押したときだけ、全員分を復号して表で出す（記録に残る） |
| 未回答者 | 「未回答（n人）」として、回答を出していない対象者の名前を出す（催促の機能は作らない。基本設計書 §1.6） |
| 出力 | 「出力へ」で G-10 を `/export/index.php?type=survey&survey_id=<id>` で開く |

- 結果を開いたときも、期限切れの依頼を締め切る。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 課 | 新規のときだけ。自分が課長の課。それ以外は 403 |
| 題名 | 必須、1〜100 文字 |
| 依頼元・目的 | 0〜100 文字・0〜300 文字（目的は改行可） |
| 回答期限 | 入れたなら今日以降の日付（保存のときも）。公開するときは必須 |
| 結果の扱い | `summary`／`detail`。それ以外は 400 |
| 対象（`target_type`） | `all`／`users`。それ以外は 400。人数（0 人）の確認は公開のとき |
| 質問の数 | 公開のときに 1〜20 問。足すときには上限を見ない |
| 月次の項目 | 有効で、種類が `project`・`table` でなく、共通か依頼の課の項目。外れたら 400 |
| 独自の質問 | 種類は `single_text`・`multi_text`・`number`・`date`・`month`・`select`・`radio`・`checkbox`・`multi_check`（`table`・`project` は使えない）。質問 1〜100 文字、説明 0〜300 文字。選択式は選択肢を 1 行に 1 つ（各 1〜60 文字、1 つ以上）。選択肢のコードは `o1`、`o2`… を自動で振る。最大文字数などの設定は持たない |

## 6. 操作と処理

基本の内容（`save_meta`）と質問（足す・並べ替え・外す）は、別々の POST で 1 つずつ保存する。送信の番号の控えは `survey.<action>`。

| 操作 | 処理 |
|---|---|
| 保存（`save_meta`） | 新規は `status = 'draft'` で作る。`target_type = 'users'` なら、選んだ人を `adhoc_request_targets` に入れ替える（1 つのトランザクション）。公開後は題名・依頼元・目的・期限だけを更新する |
| 質問を足す・並べ替え・外す | 下書きのときだけ（公開後は 400「公開後は質問を変えられません。」）。並べ替えは隣と入れ替え、10, 20… で振り直す |
| 公開 | ひな形は 400「ひな形は公開できません。複製して使ってください。」。期限と質問の数を確かめる。`target_type = 'all'` なら、公開の時点の課の有効な利用者を `adhoc_request_targets` に入れ直す。対象が 0 人なら「対象者がいません」。`status = 'open'`、`opened_at` |
| 締め切り | 公開中のときだけ（それ以外は 400）。`status = 'closed'`、`closed_at`。期限を過ぎたものは、一覧・結果・回答（G-07）の画面を開いたときに自動で締め切る（`due_at` < 今日） |
| 複製 | 質問と設定を写して新しい下書きを作る。題名に「（複製）」を付け、対象は「課の全員」、期限は空 |
| ひな形として保存 | 今の依頼を写して、**新しい**ひな形（下書き、`is_template = 1`、対象は課の全員、期限なし）を作る。元の依頼はそのまま残る |
| 月次の項目へ移す | 独自の質問の横に、その課の課長のときだけリンクを出す（管理者でも課長でなければ出ない）。G-12 の作成画面（`/admin/field_edit.php?dept=<課>&from_q=<質問ID>`）に写して開く（保存は G-12 で行う） |
| 削除 | 状態に関係なくできる。`deleted_at` を入れて一覧へ。30 日間は管理者が戻せる（G-15） |

月次の項目を質問にしたときは、項目マスタの定義（表示名・種類・機密区分・説明・設定・有効な選択肢）を `adhoc_request_fields` に写す。必須は写さず、常に任意にする。あとで項目マスタを変えても、この依頼は変わらない。

| 状況 | 文言 |

| 公開 | 公開しました。対象者のホーム画面に表示されます |
| 公開の確認 | 公開すると質問は変えられません。公開しますか？ |
| 締め切りの確認・結果 | 締め切ります。よろしいですか？ ／ 締め切りました |
| 複製・ひな形 | 複製しました ／ ひな形として保存しました |
| 削除の確認・結果 | 削除します。よろしいですか？ ／ 削除しました（30 日間は管理者が戻せます） |
| 期限 | 回答期限は今日以降の日付にしてください ／ 回答期限（今日以降）を入れてから公開してください |
| 質問の数 | 質問は 1〜20 問にしてください |
| 選択肢がない | 選択肢を 1 行に 1 つずつ入れてください |
| 対象者がいない | 対象者がいません |
| 公開後の質問の変更 | 公開後は質問を変えられません。（400） |
| ひな形の公開 | ひな形は公開できません。複製して使ってください。（400） |

## 8. 記録

- 公開・締め切り・削除: `admin survey:<id>:open|close|delete`。複製・ひな形・保存は記録しない。
- 結果の個人の回答を開いた: `view survey:<id>:responses`。

## 9. 検証の観点

- 確認者・部下・別の課の課長は作れない・見られない。
- 公開後に質問を変える POST が断られる。
- 対象者を、自分の課の外の人にできない（課長）。
- 締め切り後は回答できない。期限を過ぎると自動で締め切られる。
- ひな形は公開できない。
