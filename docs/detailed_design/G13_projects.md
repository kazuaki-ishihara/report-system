# G-13 案件の管理

| 項目 | 内容 |
|---|---|
| URL | `/admin/projects.php`（GET: 一覧、POST: 追加・更新・終了） |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-09 |

---

## 1. 目的

報告で選ぶ案件コードと、客先が特定されない社内向けの呼び名を管理する。**客先名・案件名は入れない**（基本設計書 §11.1）。客先との対応表はシステムの外で管理する。

## 2. 表示の条件と権限

管理者だけ。課長・確認者・部下は 403。

## 3. 画面の配置

```text
案件の管理
※ 客先名・案件名は入力しないでください。客先との対応はシステムの外で管理します。
[ ＋ 案件を追加 ]   状態 [有効 ▼]  課 [すべて ▼]
┌────────┬──────────────────┬────┬──────┬────────┬──────────┐
│コード   │社内向けの呼び名      │課   │状態   │使用中   │操作       │
├────────┼──────────────────┼────┼──────┼────────┼──────────┤
│P-0012  │物流系・在庫管理更改   │A課  │有効   │3 人     │編集 終了  │
│P-0007  │（消去済み）          │A課  │終了   │—       │          │
└────────┴──────────────────┴────┴──────┴────────┴──────────┘
```

## 4. 表示項目

| 列 | 内容 |
|---|---|
| コード | `projects.code` |
| 社内向けの呼び名 | `alias`。終了後に消したものは「（消去済み）」 |
| 課 | 使う課（未指定なら全課で選べる） |
| 状態 | 有効／終了（終了日） |
| 使用中 | 最新の月の報告で、この案件を案件ブロックに入れている人数 |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| コード | 追加時に自動で振る（`P-` ＋ 4 桁の連番。最大の番号＋1。削除・終了したコードも再利用しない）。手で入れる場合は `^[A-Z0-9-]{3,20}$`、一意 |
| 社内向けの呼び名 | 0〜40 文字。客先名らしい言葉の注意を出す（共通編 §9.3）。止めはしない |
| 課 | 有効な課、または未指定 |

## 6. 操作と処理

| 操作 | 処理 |
|---|---|
| 追加 | コードを振って `projects` に保存 |
| 編集 | 呼び名・課を変える（コードは変えない） |
| 終了 | 確認の表示（「呼び名を消しますか？ 消してもコードと過去の報告は残ります」）のあと、`is_active = 0`、`ended_on`。「呼び名を消す」を選んだら `alias = ''` |
| 再開 | `is_active = 1`（呼び名は消えたまま。必要なら入れ直す） |

案件の物理削除はしない（過去の報告がコードで参照しているため）。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 追加 | 案件 P-0013 を追加しました |
| 終了 | 案件を終了にしました。次から作る報告では選べません |
| 客先名らしい言葉 | 客先名や案件名が含まれていませんか |

## 8. 記録

`admin project:<id>:create|update|end|reopen`。

## 9. 検証の観点

- 管理者以外は開けない・POST できない。
- コードが再利用されない（終了・最大の番号の扱い）。
- 終了した案件が、新しい報告の選択肢に出ない。過去の報告には「P-0007」と出る。
- テーブルに客先名の列がない（検証の道具で `projects` の列を確かめる）。
