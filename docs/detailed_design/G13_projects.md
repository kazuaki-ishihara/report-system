# G-13 案件の管理

| 項目 | 内容 |
|---|---|
| URL | `/admin/projects.php?state=<active|ended|all>`（GET: 一覧）、`/admin/projects.php?edit=<id>`（GET: その行を編集の形で出す）、`/admin/projects.php`（POST: `action` = `add`・`update`・`end`・`reopen`） |
| ファイル | `app/pages/admin_projects.php`、`app/views/admin_projects.php` |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-09 |

---

## 1. 目的

報告で選ぶ案件コードと、客先が特定されない社内向けの呼び名を管理する。**客先名・案件名は入れない**（基本設計書 §11.1）。客先との対応表はシステムの外で管理する。

## 2. 表示の条件と権限

管理者だけ。課長・確認者・部下は 403。

## 3. 画面の配置

```text
案件の管理
客先名・案件名は入力しないでください。客先との対応は、このシステムの外で管理します。
[社内向けの呼び名（例: 物流系・在庫管理更改）] [全課 ▼] [ ＋ 案件を追加（コードは自動） ]
[有効 ▼] [表示]
┌────────┬──────────────────┬────┬──────────────┬──────┬────────────────────┐
│コード   │社内向けの呼び名      │課   │状態           │使用中 │                     │
├────────┼──────────────────┼────┼──────────────┼──────┼────────────────────┤
│P-0012  │物流系・在庫管理更改   │A課  │有効           │3 人   │編集 ☑呼び名を消す [終了]│
│P-0007  │（なし）             │全課 │終了（2026-10-31）│—     │編集 [再開]           │
└────────┴──────────────────┴────┴──────────────┴──────┴────────────────────┘
```

- 上の欄は追加用のフォーム。呼び名と課（「全課」か各課）を入れて追加する。
- 絞り込みは状態（有効・終了・すべて。既定は有効）だけ。課の絞り込みはない。
- 「編集」を押すと、その行の呼び名と課の欄が入力の形になり、「保存」で送る。

## 4. 表示項目

| 列 | 内容 |
|---|---|
| コード | `projects.code`（コードの順に並べる） |
| 社内向けの呼び名 | `alias`。空なら「（なし）」 |
| 課 | 使う課。未指定なら「全課」 |
| 状態 | 「有効」か「終了（終了日）」 |
| 使用中 | 全体の最新の対象月（削除・移行データを除いた報告の最大の `period`）の報告（削除を除き、下書きを含む）で、この案件を入れている人数。0 人なら「—」 |

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| コード | 手では入れない。追加時に自動で振る: `P-` ＋ 4 桁。既存の `P-数字` の最大と、`app_state` の `project_seq` の大きいほう＋1。`project_seq` も更新する（終了したコードも再利用しない） |
| 社内向けの呼び名 | 0〜40 文字、制御文字なし。客先名らしい言葉の注意を出す（共通編 §9.3）。止めはしない |
| 課 | 空（全課）か、存在する課の ID（有効かどうかは見ない）。候補には有効な課だけを出す。違えば「課が正しくありません」 |
| `id`（更新・終了・再開） | 存在しなければ 404 |

## 6. 操作と処理

| 操作 | 処理 |
|---|---|
| 追加 | 1 つのトランザクションでコードを振って `projects` に保存（`is_active = 1`） |
| 編集 | 呼び名・課を変える（コードは変えない） |
| 終了 | 行の「☑ 呼び名を消す」（既定はチェックあり）と「終了」。確認の表示のあと、`is_active = 0`、`ended_on = 今日`。チェックがあれば `alias = ''` |
| 再開 | `is_active = 1`、`ended_on = NULL`（呼び名は消えたまま。必要なら入れ直す） |

- 追加・編集のあと、呼び名に客先名らしい言葉があれば、注意のメッセージを出す。
- 案件の物理削除はしない（過去の報告がコードで参照しているため）。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 追加 | 案件 P-0013 を追加しました |
| 編集 | 保存しました |
| 終了 | 案件を終了にしました。次から作る報告では選べません |
| 再開 | 案件を再開しました |
| 終了の確認 | 案件を終了にします。呼び名も消しますか？（消してもコードと過去の報告は残ります）チェックで選んでから押してください。 |
| 客先名らしい言葉 | 呼び名に客先名や案件名が含まれていませんか |
| 課の誤り | 課が正しくありません |

## 8. 記録

`admin project:<id>:create|update|end|reopen`。

## 9. 検証の観点

- 管理者以外は開けない・POST できない。
- コードが再利用されない（終了・最大の番号の扱い）。
- 終了した案件が、新しい報告の選択肢に出ない。過去の報告には「P-0007」と出る。
- テーブルに客先名の列がない（自動の検証にはまだない）。
