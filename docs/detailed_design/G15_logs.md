# G-15 記録の閲覧・削除データ

| 項目 | 内容 |
|---|---|
| URL | `/admin/logs.php`（GET: 記録）、`/admin/trash.php`（GET: 削除データ、POST: 戻す） |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1（記録）、2（削除データ） |
| 関連する機能 | F-19、F-21 |

---

## 1. 目的

- **記録**: 誰が・いつ・何を見たか、出力したか、管理の操作をしたかを調べる。漏えいが疑われるときに、影響の範囲を絞り込む（基本設計書 §11.5）。
- **削除データ**: 削除した報告・コメント・臨時の調査を、期間内なら戻す（基本設計書 §15.4）。

## 2. 表示の条件と権限

管理者だけ。

## 3. 画面の配置

**記録**

```text
記録   期間 [2026-11-01]〜[2026-11-30]  種類 [すべて ▼]  利用者 [____]  対象 [report:123]
[ 検索 ]   [ この条件で CSV に出力 ]
┌────────────────┬──────┬──────┬────────────────────────┬──────────┐
│日時             │利用者 │種類   │対象                      │IP アドレス│
├────────────────┼──────┼──────┼────────────────────────┼──────────┤
│2026-12-02 10:15│sato  │出力   │export:report;period=…    │203.0.113.5│
│2026-12-02 10:01│sato  │閲覧   │report:123                │203.0.113.5│
└────────────────┴──────┴──────┴────────────────────────┴──────────┘
```

**削除データ**

```text
削除データ（削除から 30 日で完全に消えます）
┌──────────────┬────────────────────────┬────────────┬──────┬──────┐
│種類           │内容                      │削除日時      │削除した人│操作   │
├──────────────┼────────────────────────┼────────────┼──────┼──────┤
│報告（下書き）  │山田 2026-11             │12/01 09:00 │山田   │[戻す] │
│コメント       │報告 #123 作業フェーズ      │11/30 18:00 │鈴木   │[戻す] │
│臨時の調査     │AI の利用状況             │11/29 12:00 │佐藤   │[戻す] │
└──────────────┴────────────────────────┴────────────┴──────┴──────┘
```

## 4. 表示項目

- 記録: `access_logs` を新しい順に 100 件ずつ。中身（報告の値・コメント）は記録にないので出ない。
- 削除データ: `deleted_at` があり、`trash_days` 以内のもの。内容は種類・持ち主・対象月・項目名だけを出す（本文は復号しない）。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 期間 | 日付。開始 ≦ 終了、最大 1 年 |
| 種類 | `view`／`export`／`admin`／`auth`／すべて |
| 利用者 | ログイン ID（前方一致） |
| 対象 | 文字列（前方一致。例 `report:123`） |

## 6. 操作と処理

### 6.1 記録の検索・出力

- 条件で `access_logs` を検索する（索引 `created_at`・`target`）。
- 「この報告を見た人」を調べるときは、対象に `report:<id>` を入れる。
- CSV 出力は G-10 と同じ形式（社外秘の見出し、数式の注入対策）。出力したことも記録する。

### 6.2 戻す

| 種類 | 戻せる条件 | 処理 |
|---|---|---|
| 報告 | 同じ人・同じ月の報告が新しく作られていない（一意の索引に当たらない） | `deleted_at = NULL` |
| コメント | 報告が削除されていない | `deleted_at = NULL`（本文は暗号化のまま残っている） |
| 臨時の調査 | — | `deleted_at = NULL`（状態は削除前のまま） |

戻せないときは理由を出す。戻したら記録 `admin restore:<種類>:<id>`。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 戻した | 戻しました |
| 戻せない（同じ月の報告がある） | 同じ人・同じ月の報告が新しく作られているため、戻せません |
| 記録が多い | 該当が 10,000 件を超えています。条件を絞ってください |

## 8. 記録

記録の CSV 出力 `export logs;...`。戻す `admin restore:...`。記録の画面を開いたことは記録しない。

## 9. 検証の観点

- 管理者以外は開けない。
- 記録に、報告の値・コメント・パスワードが含まれていない（検証の道具で `access_logs` の `target` を確かめる）。
- 30 日を過ぎた削除データが表示されず、後片付けで物理削除されている。
- 同じ月の報告が作り直されたあとは、古いほうを戻せない。
