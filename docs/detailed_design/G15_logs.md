# G-15 記録の閲覧・削除データ

| 項目 | 内容 |
|---|---|
| URL | `/admin/logs.php?from=&to=&kind=&who=&target=&page=`（GET: 記録。`&csv=1` で CSV 出力）、`/admin/trash.php`（GET: 削除データ。POST: `action` = `restore_report`・`restore_comment`・`restore_survey`） |
| ファイル | `app/pages/admin_logs.php`・`admin_trash.php`、同じ名前の `app/views/` |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1（記録）、2（削除データ） |
| 関連する機能 | F-19、F-21 |

---

## 1. 目的

- **記録**: 誰が・いつ・何を見たか、出力したか、管理の操作をしたかを調べる。漏えいが疑われるときに、影響の範囲を絞り込む（基本設計書 §11.5）。
- **削除データ**: 削除した報告・コメント・臨時の調査を、期間内なら戻す（基本設計書 §15.4）。

## 2. 表示の条件と権限

管理者とシステム管理者補佐。ほかの人は 403。削除データはメニューに出さず、記録の画面のタブから開く（共通編 §11.5）。

- 補佐は、記録のうちログイン（`auth`）と管理の操作（`admin`）だけを見られる（一覧・CSV とも）。種類に閲覧・出力を指定すると 403。
- 補佐は、削除データの種類ごとの件数だけを見られ、戻せない（戻す操作は 403）。
- 補佐としての管理の操作・出力の記録には「補佐」の札を出す（CSV では利用者の後ろに「（補佐）」）。
- 種類に「ログインの失敗」（`kind=auth_fail`。`login:` で始まり `login:ok` でない記録: パスワード・2 段階認証の誤り、ロック、ロック中の試行）を選べる。ログインの失敗の行は赤く出す。無い ID での失敗は、入れた ID も記録する（`login:fail;id=<ID>`。ID の形に合わないものは、パスワードを誤って入れた恐れがあるので `login:fail;id=(形が違う)`）。管理のトップに直近 24 時間の失敗の数を出す（K-041）。

## 3. 画面の配置

**記録**

```text
[記録] [削除データ]
記録
期間 [2026-11-05]〜[2026-11-12]  種類 [すべて ▼]  利用者 [____]  対象 [report:123]
[ 検索 ]   [ この条件で CSV に出力 ]
「この報告を見た人」は、対象に report:報告の番号 を入れて調べます。記録には報告の中身は入っていません。
該当 235 件
┌────────────────┬──────┬──────┬────────────────────────┬──────────┐
│日時             │利用者 │種類   │対象                      │IP アドレス│
├────────────────┼──────┼──────┼────────────────────────┼──────────┤
│2026-12-02 10:15│sato  │出力   │export:report;period=…    │203.0.113.5│
│2026-12-02 10:01│sato  │閲覧   │report:123                │203.0.113.5│
└────────────────┴──────┴──────┴────────────────────────┴──────────┘
[ 次の 100 件 ]
```

- 種類の表示は「閲覧」「出力」「管理」「ログイン」。

**削除データ**

```text
[記録] [削除データ]
削除データ（削除から 30 日で完全に消えます）
┌──────────────┬──────────────────────────────┬───────────────────┬──────┐
│種類           │内容                            │削除日時             │操作   │
├──────────────┼──────────────────────────────┼───────────────────┼──────┤
│報告（下書き）  │山田 2026年11月                  │2026-12-01 09:00:00│[戻す] │
│コメント       │報告 #123 作業フェーズ（鈴木）     │2026-11-30 18:00:00│[戻す] │
│臨時の調査     │AI の利用状況（佐藤）             │2026-11-29 12:00:00│[戻す] │
└──────────────┴──────────────────────────────┴───────────────────┴──────┘
```

- 削除した人の列はない（内容の括弧の中は、コメントした人・調査を作った人）。
- 0 件なら「削除データはありません。」。

## 4. 表示項目

- 記録: `access_logs` を新しい順に 100 件ずつ。該当の件数も出す。中身（報告の値・コメント）は記録にないので出ない。
- 削除データ: `deleted_at` があり、`trash_days` 以内のもの。本文は復号しない。
  - 報告: 種類「報告（状態）」、内容「表示名 YYYY年M月」。
  - コメント: 内容「報告 #<id> <項目名 または 報告全体>（コメントした人）」。本文が空（`comment_enc = ''`）のものは出さない。
  - 臨時の調査: 内容「題名（作った人）」。
  - 削除日時は DB の値（`YYYY-MM-DD HH:MM:SS`）をそのまま出す。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 期間（`from`・`to`） | 日付（`YYYY-MM-DD`）。形が違えば 400。開始 ≦ 終了、最大 366 日。開始が終了より後なら 400「期間の開始は、終了と同じ日かそれより前にしてください。」、366 日を超えたら 400「期間は 1 年以内にしてください。」。既定は 7 日前から今日まで |
| 種類（`kind`） | `view`／`export`／`admin`／`auth`／空（すべて）。それ以外は 400 |
| 利用者（`who`） | ログイン ID（前方一致） |
| 対象（`target`） | 文字列（前方一致。例 `report:123`） |
| `id`（戻す） | 削除済みのものがなければ 404 |

## 6. 操作と処理

### 6.1 記録の検索・出力

- 条件で `access_logs` を検索する（索引 `created_at`・`target`）。
- 「この報告を見た人」を調べるときは、対象に `report:<id>` を入れる。
- CSV 出力（`&csv=1`、GET）:
  - スマートフォンの `User-Agent` では 403「出力は PC から行ってください。」。
  - 該当が 10,000 件を超えると 400「該当が 10,000 件を超えています。条件を絞ってください。」。
  - G-10 と同じ形式（UTF-8 BOM、CRLF、社外秘の見出し 3 行、数式の注入対策）。見出しは「社外秘」「記録 <開始>〜<終了>」「出力者: <ログイン ID>  出力日時: …」。列は「日時・利用者・種類・対象・IP アドレス」。
  - ファイル名は `logs_<YYYYMMDD-HHMM>.csv`。出力したことも記録する。

### 6.2 戻す

| 種類 | 戻せる条件 | 処理 |
|---|---|---|
| 報告 | 同じ人・同じ月の報告が新しく作られていない。移行データの報告は確かめない（旧システムの日付ごとの報告を移したため、同じ人・同じ月に複数あってよい。一意の索引も移行データを対象にしない） | `deleted_at = NULL` |
| コメント | 報告が削除されていない、かつ本文が残っている | `deleted_at = NULL`（本文は暗号化のまま残っている） |
| 臨時の調査 | — | `deleted_at = NULL`（状態は削除前のまま） |

- 戻す POST でも、削除から `trash_days` 以内かを確かめる（一覧と同じ期限）。過ぎていれば戻さずに「削除から 30 日を過ぎているため、戻せません」を出して削除データの画面へ戻す（日数は `trash_days`）。
- 戻せないときは理由を出して削除データの画面へ戻す。戻したら記録 `admin restore:<report|comment|survey>:<id>`。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 戻した | 戻しました |
| 戻せない（同じ月の報告がある） | 同じ人・同じ月の報告が新しく作られているため、戻せません |
| 戻せない（コメント） | 報告が削除されているか、本文が残っていないため、戻せません |
| 戻せない（期限切れ） | 削除から 30 日を過ぎているため、戻せません（日数は `trash_days`） |
| 期間（開始が終了より後） | 期間の開始は、終了と同じ日かそれより前にしてください。（400） |
| 期間（長すぎる） | 期間は 1 年以内にしてください。（400） |
| 記録が多い（CSV のとき） | 該当が 10,000 件を超えています。条件を絞ってください。（400） |
| 削除データが 0 件 | 削除データはありません。 |

## 8. 記録

記録の CSV 出力 `export export:logs;from=<開始>;to=<終了>`。戻す `admin restore:<report|comment|survey>:<id>`。記録の画面を開いたことは記録しない。

## 9. 検証の観点

- 管理者以外は開けない。
- 記録に、報告の値・コメント・パスワードが含まれていない（検証の道具で `access_logs` の `target` を確かめる）。
- 30 日を過ぎた削除データが表示されず、後片付けで削除されている（報告と臨時の調査は物理削除。コメントは本文を空にし、返信がないものは物理削除、返信があるものは行を残す。DB 編 §5）。
- 同じ月の報告が作り直されたあとは、古いほうを戻せない。
