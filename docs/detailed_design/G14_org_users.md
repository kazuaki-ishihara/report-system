# G-14 組織・ユーザーの管理

| 項目 | 内容 |
|---|---|
| URL | `/admin/org.php?tab=<departments|users|words>`（GET）、`/admin/user_edit.php?id=`（GET・POST）、`/admin/org.php`（POST: 課・確認者・言葉の一覧） |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-03、F-02（管理者による初期化） |

---

## 1. 目的

課、ユーザー、所属、確認者と課長、課別項目の管理者、客先名らしい言葉の一覧を管理する。2 段階認証の初期化やロックの解除など、利用者が自分でできないことを管理者が行う。

## 2. 表示の条件と権限

管理者だけ。

## 3. 画面の配置

```text
[ ＋ 課を追加 ]

├────┼──────┼──────────────────────────┼────────┼──────┤

│     │       │リーダー 田中, 中村            │        │[編集] │
└────┴──────┴──────────────────────────┴────────┴──────┘
```

**タブ: ユーザー**

```text
[ ＋ ユーザーを追加 ]  課 [すべて ▼]  状態 [有効 ▼]  検索 [____]
┌─────────┬──────┬────┬──────┬────────┬──────┬────────┐
```

**ユーザーの編集**


## 4. 表示項目

| 欄 | 内容 |
|---|---|
| 役割 | その人が確認者・課長・項目管理者になっている課 |
| 2 段階認証 | 設定済み（日時）／未設定 |
| ロック | `locked_until` が今より後ならロック中 |
| 最終ログイン | `access_logs` の `login:ok` の最新 |

パスワード、2 段階認証の秘密の値、予備のコードは、どの画面にも出さない。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 課の名前 | 必須、1〜40 文字、一意。課名には人名を入れないことを推奨（「A課」のような名前） |
| 締め日 | 1〜31（31 は月末）または未設定 |
| 確認者 | その課の有効な利用者、または管理者が指定した人。課長は 1 課に 1 人 |
| ログイン ID | `^[a-z0-9][a-z0-9._-]{2,31}$`、一意。**メールアドレスは不可**（`@` を含めない） |
| 表示名 | 1〜20 文字 |
| 注意の言葉 | 1〜20 文字、一意。**実際の客先名は入れない**ことを画面に表示する |

## 6. 操作と処理

| 操作 | 処理 |
|---|---|
| 課の追加・編集 | `departments` |
| 課の無効化 | 所属する有効な利用者がいれば不可（「所属している人がいます」） |
| 確認者の設定 | `department_reviewers` を入れ替える。課長（`is_final`）は 1 人。確認者から外すと、その人のチェックの記録は残る |
| 項目管理者の設定 | `department_admins` |
| ユーザーの追加 | 仮のパスワード（12 文字の乱数）を作り、`must_change_password = 1`。仮のパスワードは**この画面に 1 回だけ**出す（本人に口頭などで伝える）。2 段階認証は本人が初回ログイン時に設定する |
| 所属の変更 | `department_id` を変える。既にある報告の課（`report_records.department_id`）は変えない |
| 無効化 | `is_active = 0`、`session_version + 1`、端末の記憶を消す。報告は残る。確認者に設定されていれば、先に外すよう求める |
| 仮のパスワードを発行 | 新しい仮のパスワード、`must_change_password = 1`、`session_version + 1` |
| 2 段階認証を初期化 | 確認の表示のあと、`totp_secret_enc = NULL`、`totp_enabled_at = NULL`、予備のコードと端末の記憶を消す、`session_version + 1`。次のログインで設定し直す |
| ロックを解除 | `locked_until = NULL`、`failed_count = 0` |
| すべての端末からログアウト | `session_version + 1`、端末の記憶を消す |
| 管理者の付け外し | 自分自身の管理者は外せない。管理者が 1 人もいなくなる変更は不可 |

**権限が意図せず広がる変更を防ぐ**（基本設計書 §15.4）

- 確認者の追加・課長の変更は、確認の表示で「この人は A課の全員の報告を見られるようになります」と出す。
- 管理者を付けるときも同様に確認を出す。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 仮のパスワード | 仮のパスワード: xxxxxxxxxxxx（この画面を閉じると二度と表示されません。本人に伝えてください） |
| 初期化 | 2 段階認証を初期化しました。次のログインで設定し直します |
| ログイン ID にメールアドレス | ログイン ID にメールアドレスは使えません |
| 最後の管理者 | 管理者が 1 人もいなくなるため、変更できません |

## 8. 記録

`admin department:<id>:...`、`admin reviewer:<課>:<user>:add|remove|final`、`admin user:<id>:create|update|deactivate|temp_password|reset_2fa|unlock|logout_all|admin_on|admin_off`、`admin word:<id>:add|delete`。仮のパスワードは記録しない。

## 9. 検証の観点

- 管理者以外は開けない・POST できない。
- 課長が 1 課に 2 人にならない（DB の一意の索引でも止まる）。
- 最後の管理者を外せない。自分の管理者を外せない。
- 無効にした人がログインできない。無効化・初期化・全端末ログアウトで、その人の既存のセッションが切れる。
- ログイン ID に `@` を含められない。
- 仮のパスワードが記録・ログに残らない。
