# G-14 組織・ユーザーの管理

| 項目 | 内容 |
|---|---|
| URL | `/admin/org.php?tab=<departments|users|words>`（GET）、`/admin/org.php?tab=departments&edit=<id>`（課の編集）・`&new=1`（課の追加）、`/admin/org.php`（POST: `action` = `dept_save`・`roles_save`・`word_add`・`word_delete`）、`/admin/user_edit.php`（GET・POST: 追加）、`/admin/user_edit.php?id=`（GET・POST: 編集。`action` = `save`・`temp_password`・`reset_2fa`・`unlock`・`logout_all`） |
| ファイル | `app/pages/admin_org.php`・`admin_user_edit.php`、同じ名前の `app/views/`、`app/lib/admin.php` |
| 利用者 | 管理者 |
| 主な端末 | PC |
| 段階 | 1 |
| 関連する機能 | F-03、F-02（管理者による初期化） |

---

## 1. 目的

課、ユーザー、所属、確認者と課長、課別項目の管理者、客先名らしい言葉の一覧を管理する。2 段階認証の初期化やロックの解除など、利用者が自分でできないことを管理者が行う。

## 2. 表示の条件と権限

管理者だけ。ほかの人は 403。

## 3. 画面の配置

**タブ: 課**

```text
組織・ユーザー
[課] [ユーザー] [注意の言葉]
[ ＋ 課を追加 ]
┌────┬──────┬──────────────────────────┬──────┬────┐
│課   │締め日 │確認者                       │状態   │     │
├────┼──────┼──────────────────────────┼──────┼────┤
│A課  │月末   │[課長 佐藤] [鈴木] [高橋] [田中]│有効   │編集 │
│B課  │25日   │[課長 中村]                   │有効   │編集 │
└────┴──────┴──────────────────────────┴──────┴────┘
```

- 締め日は「n日」「月末」（31）「—」（未設定）。
- 確認者は名前の札で並べ、課長だけ頭に「課長 」を付ける（課長が先、そのあと `sort_order`）。代理・リーダーの区別はない。項目管理者の列はない。

**課の編集（`&edit=<id>`）**

```text
A課 の編集
課の名前 [A課]  締め日 [31]  並び順 [10]  ☑ 有効   [ 保存 ]

確認者と項目管理者
確認者はこの課の全員の報告を見られます（「限定」の項目は課長だけ）。
┌──────────────┬────┬──────────────────┬────────┐
│名前           │所属 │役割                │項目管理者│
├──────────────┼────┼──────────────────┼────────┤
│佐藤 sato      │A課  │[課長（最終確認者） ▼]│☐       │
│鈴木 suzuki    │A課  │[確認者 ▼]          │☑       │
│中村 nakamura  │B課  │[— ▼]              │☐       │
└──────────────┴────┴──────────────────┴────────┘
[ 確認者を保存 ]
```

- 候補は有効な利用者全員（その課の人が先、そのあと表示名の順）。
- 課の追加（`&new=1`）は、課の名前・締め日・並び順を入れて「追加する」。

**タブ: ユーザー**

```text
[課: すべて ▼] [有効 ▼] [ID・名前で検索] [絞り込む] [ ＋ ユーザーを追加 ]
┌─────────┬────────────┬────┬──────────────┬────────┬──────┬────┐
│ログイン ID │表示名       │課   │役割           │2 段階認証│ロック │     │
├─────────┼────────────┼────┼──────────────┼────────┼──────┼────┤
│yamada    │山田         │A課  │               │設定済み  │      │編集 │
│sato      │佐藤 [管理者]│A課  │A課（課長）     │未設定    │ロック中│編集 │
└─────────┴────────────┴────┴──────────────┴────────┴──────┴────┘
```

- 絞り込み: 課、状態（有効・無効・すべて。既定は有効）、ログイン ID・表示名の部分一致。
- 並びは課の並び順、表示名の順。無効の人は薄く出す。

**ユーザーの編集**

```text
ユーザーの編集
← ユーザーの一覧
ログイン ID  yamada（追加のときだけ入力）
表示名      [山田]
役職（表示のみ。権限には使いません） [一般 ▼]
所属の課    [A課 ▼]
☐ 管理者
☑ 有効（外すとログインできなくなります。報告は残ります）（編集のときだけ）
[ 保存 ]（追加のときは [ 追加して仮のパスワードを発行 ]）

状態
  2 段階認証       設定済み（2026-11-01 09:00:00）
  ロック           なし
  最終ログイン      2026-11-12 08:55:10
  パスワードの変更  仮のパスワード（未変更）
操作
[ 仮のパスワードを発行 ] [ 2 段階認証を初期化 ] [ ロックを解除 ] [ すべての端末からログアウト ]
```

**タブ: 注意の言葉**

- 説明「自由記述にこれらの言葉が入ると、「客先名や個人名が含まれていませんか」と注意を出します。」と、注意「実際の客先名は入れないでください（この一覧が漏れても客先が分からないように）。」を出す。
- 言葉の入力欄と「追加」。一覧の各行に削除のボタン。

## 4. 表示項目

| 欄 | 内容 |
|---|---|
| 役割（一覧） | その人が確認者・課長になっている課（「A課（課長）」「A課（確認者）」）。項目管理者は出さない。管理者には表示名の横に「管理者」の札 |
| 2 段階認証 | 一覧は「設定済み／未設定」。編集の画面は設定日時も出す |
| ロック | `locked_until` が今より後ならロック中（編集の画面は期限も出す） |
| 最終ログイン | 編集の画面だけ。`access_logs` の `login:ok` の最新 |
| パスワードの変更 | 編集の画面だけ。`must_change_password = 1` なら「仮のパスワード（未変更）」、それ以外は `password_changed_at` |

パスワード、2 段階認証の秘密の値、予備のコードは、どの画面にも出さない（仮のパスワードは発行の直後に 1 回だけ出す）。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| 課の名前 | 必須、1〜40 文字、一意（「同じ名前の課があります」）。課名には人名を入れないことを推奨（「A課」のような名前） |
| 締め日 | 1〜31（31 は月末）または空欄（なし）。違えば「締め日は 1〜31（31 は月末）にしてください」 |
| 並び順 | 数字。数字でなければ 0 |
| 確認者 | 有効な利用者なら、どの課の人でも選べる。課長は 1 課に 1 人（「課長（最終確認者）は 1 人にしてください」） |
| 項目管理者 | 利用者の ID の形だけを確かめる |
| ログイン ID | 追加のときだけ。前後の空白を除き小文字にしてから確かめる。`@` を含むと「ログイン ID にメールアドレスは使えません」。`^[a-z0-9][a-z0-9._-]{2,31}$` でなければ「ログイン ID は英小文字・数字・. _ - の 3〜32 文字にしてください」。`login_id`・`username` のどちらかと同じなら「同じログイン ID があります」。あとから変えられない |
| 表示名 | 1〜20 文字 |
| 役職 | 一般・主任・課長代理・課長・部長（表示のみ。権限には使わない） |
| 所属の課 | 空（なし）か、有効な課 |
| 注意の言葉 | 1〜20 文字、一意（「同じ言葉があります」）。**実際の客先名は入れない**ことを画面に表示する |

## 6. 操作と処理

| 操作 | 処理 |
|---|---|
| 課の追加 | `departments` に有効で作る |
| 課の編集 | 名前・締め日・並び順・有効を更新。所属する有効な利用者がいれば無効にできない（「所属している人がいるため、無効にできません」） |
| 確認者と項目管理者の保存 | その課の `department_reviewers` と `department_admins` を、1 つのトランザクションで全部入れ替える。課長（`is_final = 1`）の `sort_order` は 0、ほかは 10, 20…。確認者から外しても、その人のチェックの記録は残る |
| ユーザーの追加 | 仮のパスワード（12 文字。紛らわしい文字を除いた英数字）を作り、`username = login_id`、`must_change_password = 1` で保存。仮のパスワードはセッションに一度だけ持ち、編集の画面に**1 回だけ**出す（本人に口頭などで伝える）。2 段階認証は本人が初回ログイン時に設定する |
| 所属の変更 | `department_id` を変える。既にある報告の課（`report_records.department_id`）は変えない |
| 無効化 | 自分自身は無効にできない。確認者に設定されていれば断る（先に外すよう求める）。`is_active = 0`、端末の記憶を消し、`session_version + 1`。報告は残る |
| 仮のパスワードを発行 | 新しい仮のパスワード、`must_change_password = 1`、`failed_count = 0`、`locked_until = NULL`、`session_version + 1`。端末の記憶は消さない。成功のメッセージは出さず、仮のパスワードを出す |
| 2 段階認証を初期化 | 確認の表示のあと、1 つのトランザクションで `totp_secret_enc`・`totp_enabled_at`・`totp_last_step` を NULL、予備のコードと端末の記憶を消し、`session_version + 1`。次のログインで設定し直す |
| ロックを解除 | `locked_until = NULL`、`failed_count = 0` |
| すべての端末からログアウト | 確認の表示のあと、端末の記憶を消し、`session_version + 1` |
| 管理者の付け外し | 自分自身の管理者は外せない。管理者が 1 人もいなくなる変更（外す・無効にする）は不可 |

**権限が意図せず広がる変更を防ぐ**（基本設計書 §15.4）

- 確認者の保存のたびに、確認の表示「確認者に設定した人は、この課の全員の報告を見られるようになります。保存しますか？」を出す。
- 管理者のチェックを新しく付けたときだけ、「管理者はすべての課の報告と管理画面を使えるようになります」と確認を出す（`data-confirm-on`）。

| 最後の管理者 | 管理者が 1 人もいなくなるため、変更できません |
| 確認者の無効化 | 確認者に設定されているため、無効にできません。先に課の確認者から外してください |

## 8. 記録

- 課: `admin department:<id>:create|update`。確認者と項目管理者の保存は、まとめて 1 件の `admin department:<課ID>:roles`。
- ユーザー: `admin user:<id>:create|update|deactivate|temp_password|reset_2fa|unlock|logout_all|admin_on|admin_off`。管理者の付け外しでは、`admin_on|admin_off` のあとに `update`（無効にしたときは `deactivate`）も残す。
- 注意の言葉: `admin word:<id>:add|delete`。
- 仮のパスワードは記録しない。

## 9. 検証の観点

- 管理者以外は開けない・POST できない。
- 課長が 1 課に 2 人にならない（DB の一意の索引でも止まる）。
- 最後の管理者を外せない。自分の管理者を外せない。
- 無効にした人がログインできない。無効化・初期化・全端末ログアウトで、その人の既存のセッションが切れる。
- ログイン ID に `@` を含められない。
- 仮のパスワードが記録・ログに残らない。
