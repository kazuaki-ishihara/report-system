# G-09 横並び表示・状況のまとめ

| 項目 | 内容 |
|---|---|
| URL | `/status/compare.php?period=YYYY-MM&dept=<課ID>&view=<表示>&diff=<0|1>`（GET）、`/status/compare.php?cell=<報告ID>:<案件ブロックID>:<項目ID>`（GET、JSON） |
| ファイル | `app/pages/status_compare.php`、`app/views/status_compare.php`、`app/lib/export.php`（`compare_dataset()`・`compare_summary()`） |
| 利用者 | 確認者、課長、管理者 |
| 主な端末 | PC |
| 段階 | 3 |
| 関連する機能 | F-16、F-17 |

---

## 1. 目的

課の報告を横に並べて比べる。選択式の値を使って、**終了が近い案件、人員の動きがある現場、遅延・問題がある現場**をまとめて見る。課長が課の外への報告を作る材料にする。

## 2. 表示の条件と権限

- G-08 と同じ（自分が確認者の課、管理者は全課）。確認者の課が 1 つもない人は 403。
- 「限定」の項目は、その課の課長と管理者にだけ列を出す。確認者には列ごと出さない。
- 提出済み・確認完了の報告のうち、削除されていないもの、移行データ（`is_legacy = 1`）でないものを対象にする。

## 3. 画面の配置

**横並び（`view=table`）**

```text
← 提出状況
横並び・まとめ
[2026-11] [A課 ▼] [横並び ▼] [☑ 前月との差分] [表示] [出力へ]
┌────┬──────────┬────────┬──────┬────────┬────────┐
│氏名 │案件       │フェーズ │進捗   │継続見込み│担当内容 │ …
├────┼──────────┼────────┼──────┼────────┼────────┤
│山田 │P-0012    │製造・単体│遅延あり *│当分継続 │[開く]   │
│山田 │P-0020    │運用・保守│問題なし │終了の話あり *│[開く] │
│鈴木 │P-0031 新規│…       │…     │…       │        │
```

- 「出力へ」（G-10）は、スマートフォンの `User-Agent` では出さない。
- 氏名は G-05 へのリンク。

## 4. 表示項目

### 4.1 横並び

- 行は「人 × 案件ブロック」。案件ブロックがない報告は、案件を「—」として 1 行にする。報告全体の項目は、その人の最初の行に出す。
- 並びは表示名の順。
- 列は、課の**今の様式**の有効な項目から作る。種類 `project` は除く（案件の列は別にある）。
  - 自由記述でない項目: `show_in_list = 1` のものだけ。
  - 自由記述（`single_text`・`multi_text`・`table`）: `show_in_list` に関係なくすべて列にし、値があるセルにだけ「開く」ボタンを出す。
  - 「限定」の項目: 課長・管理者のときだけ列にする。
- 選択肢の表示名は、報告の作成時の定義で出す。
- 前月との差分（`diff=1`。既定は表示する）:
  - 前月の同じ表示名・同じ案件コードの行と、保存値（選択肢のコード）で比べる。
  - 違うセルは色を付け、「 *」を足す。
  - 前月にその行がなければ、案件の欄に「新規」の札を出す。
- 自由記述は一覧では復号しない。「開く」を押したときだけ、その 1 つを復号して出す（§6）。

### 4.2 まとめ

| 欄 | 条件（初期の様式の項目のコードで判定） |
|---|---|
| 終了が近い案件 | `continuation = 'ending'`、または `end_month` が対象月から 3 か月先までの間（対象月 ≦ `end_month` ≦ 対象月＋3 か月） |
| 人員の動きがある現場 | `staffing IN ('increase', 'decrease')` |
| 遅延・問題がある現場 | `progress IN ('delayed', 'other')` |
| 集計 | 一覧の列にある `select`・`radio` の項目ごとに、選択肢の件数（1 件以上のものだけ）。`multi_check` は数えない |

- 各欄は「案件 氏名（報告へのリンク） 項目名: 値 …」を並べる。値を出すのは、一覧の列のうち `select`・`radio`・`month`・`date` で値があるもの。0 件の欄は「なし」と出す。
- 判定に使う項目と値は、既定をコード（`summary_rules()`）に持つ。設定ファイルに `summary_rules` を書けば上書きできる（画面からは変えない）。

## 5. 入力項目と確認

| 項目 | 確認 |
|---|---|
| `period` | 形が違えば 400。省略時は見ている人の報告の対象月（`report_target_period()`） |
| `dept` | 整数でなければ 400。見られない課は 403。省略時は見られる課の最初の課 |
| `view` | `summary` 以外は `table` として扱う |
| `diff` | `1` なら差分を出す。省略時は `1` |
| `cell` | `<報告ID>:<案件ブロックID>:<項目ID>`（報告全体の項目は案件ブロックID を 0）。形が違えば 400 |

## 6. 操作と処理

1. 権限の確認。
2. 対象の報告と、列にする項目の値を取得する。暗号化されている値（「限定」の選択式など）は、見られる人のときだけ復号する。自由記述は一覧では復号せず、値があるかだけを調べる。
3. 差分を出すときは、前月の同じ条件のデータを取得し、表示名＋案件コードで比べる。
4. まとめは、一覧のデータ（選択式・年月の値）だけで判定・集計する（自由記述を復号しない）。
5. 自由記述のセルを開いたとき（`?cell=...`、GET、JSON）:
   - 報告が見られない、下書き、作成時の定義にない項目、「限定」で見られない項目なら、404 と `{"ok":false}`。
   - 正しければ、その 1 つだけを復号して `{"ok":true,"text":…}` を返す。記録 `view report:<id>`。
   - 画面では、ボタンの横に本文を出してボタンを隠す。失敗のときは「表示できません」、通信できないときは「通信エラー」と出す。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 対象なし | 提出済みの報告がありません。 |
| まとめの欄が 0 件 | なし |

## 8. 記録

- 画面を開いたとき `view compare:period=…;dept=…`。
- 自由記述のセルを開いたとき `view report:<id>`。

## 9. 検証の観点

- 確認者に「限定」の列が出ない（HTML・JSON の中にも含まれない）。確認者が「限定」のセルを開くと 404。
- 一覧の HTML に自由記述の本文が含まれない。セルを開くと本文が返る。
- 既定は横並び。案件と表示名が出る。
- まとめの件数が、選択式の値の件数と一致する。
- 列は今の様式で決まる（無効にした項目は過去の月でも出ない）。選択肢の表示名は報告の作成時の定義で出すので、選択肢を無効にしても値の表示は崩れない。
- 下書きの報告が出ない。案件ブロック 0 件の人、前月の報告がない人で崩れない（自動の検証にはまだない）。
