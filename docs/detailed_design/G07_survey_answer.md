# G-07 臨時の調査への回答

| 項目 | 内容 |
|---|---|
| URL | `/surveys/answer.php?id=<依頼ID>`（GET: 画面、POST: 回答） |
| 利用者 | 依頼の対象者 |
| 主な端末 | スマートフォン |
| 段階 | 2 |
| 関連する機能 | F-14 |

---

## 1. 目的

課長が作った臨時の調査に答える。**誰が・何のために聞いているか**を見せ、月次報告と同じ質問は最新の値を入れておき、1 分程度で答え終わるようにする。

## 2. 表示の条件と権限

- `adhoc_request_targets` に自分が入っている依頼だけ。それ以外は 404。
- `status = 'open'` の間だけ回答・修正できる。`closed` のあとは、自分の回答を見るだけ。
- 下書きの依頼（`draft`）は対象者にも見せない。

## 3. 画面の配置

```text
┌──────────────────────────┐
│ ← 臨時の調査               │
├──────────────────────────┤
│ AI の利用状況               │
│ 依頼元: 経営企画             │
│ 目的: 社内研修の計画のため    │
│ 回答期限: 11月20日           │
│ 結果の扱い: 集計のみを依頼元  │
│ に渡します（個人の回答は渡し  │
│ ません）                    │
│                          │
│ 1. AI を使ったことがありますか│
│   ◉ ある  ○ ない            │
│ 2. 業務で使っていますか       │
│   ○ 毎日 ◉ ときどき ○ 使わない│
│ 3. 作業フェーズ（月次と同じ）  │
│   [製造・単体 ▼]  ← 最新の月次報告の値│
│                          │
├──────────────────────────┤
│ [       回答する        ]   │
└──────────────────────────┘
```

## 4. 表示項目

| 項目 | 内容 |
|---|---|
| 題名・依頼元・目的・期限 | `adhoc_requests` |
| 結果の扱い | `result_visibility` が `summary` なら「集計のみを依頼元に渡します」、`detail` なら「回答は課長が確認し、必要な範囲で依頼元に渡します」 |
| 質問 | `adhoc_request_fields` を `sort_order` 順に。入力部品は G-04 と同じ |
| 最新の月次報告の値 | `source_field_id` がある質問は、自分の最新の提出済み報告の値を初期値に入れる（案件ブロックの項目なら最初の案件の値） |
| 回答済み | 回答済みなら「回答済み（hh:mm）。期限までは直せます」 |

## 5. 入力項目と確認

- 質問ごとの確認は共通編 §9.2。必須は回答のときに確かめる。
- 自由記述と「限定」の質問は暗号化。客先名らしい言葉は注意（止めない）。

## 6. 操作と処理

1. CSRF → 送信の番号 → 対象者か・`open` か・期限内か（期限を過ぎたら回答できない）。
2. `adhoc_responses` を作る（あれば更新）。`submitted_at`。
3. `adhoc_response_values` を入れ替える。
4. ホームへ転送し「回答しました」。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 回答 | 回答しました |
| 期限切れ | この調査は締め切られました |
| 必須の不足 | 入力が必要な質問があります |

## 8. 記録

なし（本人の回答のため）。

## 9. 検証の観点

- 対象外の人、下書きの依頼は 404。締め切り後は回答できない。
- 同じ送信の番号で 2 回送っても回答は 1 件。
- 月次報告の値が初期値に入る。ほかの人の値は入らない。
- 自由記述が暗号化されている。
