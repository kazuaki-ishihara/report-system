# G-07 臨時の調査への回答

| 項目 | 内容 |
|---|---|
| URL | `/surveys/answer.php?id=<依頼ID>`（GET: 画面、POST: 回答） |
| 利用者 | 依頼の対象者 |
| 主な端末 | スマートフォン |
| 段階 | 2 |
| 関連する機能 | F-14 |

---

## 1. 目的

課長が作った臨時の調査に答える。**誰が・何のために聞いているか**を見せ、月次報告と同じ質問は最新の値を入れておき、1 分程度で答え終わるようにする。

## 2. 表示の条件と権限

- `adhoc_request_targets` に自分が入っている依頼だけ。対象外、下書き（`draft`）、ひな形（`is_template = 1`）、削除済みの依頼は 404。
- 画面を開くたびに、期限（`due_at`）が今日より前の公開中の依頼を自動で `closed` にする（期限の日までは回答できる）。
- `status = 'open'` の間だけ回答・修正できる。`closed` のあとは、自分の回答を入れた欄を出すだけで、「回答する」ボタンは出さない。

## 3. 画面の配置

```text
┌──────────────────────────┐
│ ← ホーム                   │
│ AI の利用状況               │
├──────────────────────────┤
│ 依頼元     経営企画          │
│ 回答期限   2026-11-20       │
│ 結果の扱い 集計のみを依頼元に │
│ 渡します（個人の回答は渡し    │
│ ません）                    │
│ 目的: 社内研修の計画のため    │
│                          │
│ 1. AI を使ったことがありますか│
│   ◉ ある  ○ ない            │
│ 2. 業務で使っていますか       │
│   ○ 毎日 ◉ ときどき ○ 使わない│
│ 3. 作業フェーズ              │
│   [製造・単体 ▼]  ← 最新の月次報告の値│
│                          │
├──────────────────────────┤
│ [       回答する        ]   │
└──────────────────────────┘
```

## 4. 表示項目

| 項目 | 内容 |
|---|---|
| 題名・依頼元・期限 | `adhoc_requests`。依頼元・期限は空なら出さない。期限は保存した値をそのまま出す |
| 結果の扱い | `result_visibility` が `summary` なら「集計のみを依頼元に渡します（個人の回答は渡しません）」、`detail` なら「回答は課長が確認し、必要な範囲で依頼元に渡します」 |
| 目的 | 一覧の下に「目的: …」。空なら出さない |
| 質問 | `adhoc_request_fields` を `sort_order` 順に、番号（「1. 」）を付けて出す。入力部品は G-04 と同じ。使える種類は 1 行・複数行・数値・日付・年月・プルダウン・ラジオ・チェック 1 つ・チェックボックス（表と案件はない） |
| 最新の月次報告の値 | まだ回答していないときだけ、`source_field_id` がある質問に、自分の最新の報告（提出済み・確認完了のうち `period` がいちばん新しいもの。移行データ・削除済みは除く）の値を初期値に入れる。「報告全体」の値を先に見て、なければ最初の案件ブロックの値 |
| 回答済み | 「回答済み（YYYY-MM-DD HH:MM:SS）。期限までは直せます。」（後半は公開中のときだけ） |
| 締め切り後 | 「この調査は締め切られました。」 |

## 5. 入力項目と確認

- 質問ごとの確認は共通編 §9.2。必須は回答のときに確かめる。
- 入力の誤り（必須に限らない）は、保存せずに画面へ戻し、上に「入力が必要な質問があります。」を出す。
- 自由記述と「限定」の質問は暗号化（付加データは `arv:<回答ID>:<質問ID>`）。客先名らしい言葉は注意（止めない。自由記述の欄の `has_warning` に入れる）。

## 6. 操作と処理

1. CSRF（共通編 §3）→ 対象者か（404）→ 送信の番号（控えは `survey.answer`）→ `open` か（締め切り後は 400「この調査は締め切られました。」）。
2. 1 つのトランザクションで、`adhoc_responses` を作る（あれば更新）。`submitted_at`。
3. `adhoc_response_values` を入れ替える。空の回答は行を作らない。
4. ホームへ転送し「回答しました」。

## 7. メッセージ

| 状況 | 文言 |
|---|---|
| 回答 | 回答しました |
| 期限切れ | この調査は締め切られました。 |
| 入力の誤り | 入力が必要な質問があります。 |

## 8. 記録

なし（本人の回答のため）。

## 9. 検証の観点

- 対象外の人、下書きの依頼は 404。締め切り後は回答できない。
- 同じ送信の番号で 2 回送っても回答は 1 件。
- 依頼元・結果の扱いが出る。
- 月次報告の値が初期値に入る。ほかの人の値は入らない。
- 自由記述が暗号化されている。

自動の検証でまだ試していないもの: 下書きの依頼の 404、締め切り後、二重送信、暗号化。
