月次報告システム 本番の配置と公開範囲
（さくらのレンタルサーバー。www の外には置けないため、すべて ~/www/report-system/ に置く）

■ 置き方
反映用の一式を、次の道具で作って上げる。手で選んで上げない。

  python tools/deploy/build_package.py

できた tools/deploy/output/<日時>_<コミット>/report-system/ の中身を、
サーバーの ~/www/report-system/ にそのまま上書きで上げる（手順は同じ場所の 反映手順.txt）。
一式は、リポジトリの public/ の中身（41 ファイル）と app/（108 ファイル）だけでできている。
コミットした内容から作るので、作業中の変更は入らない。

すでにアカウントを配って使っているサイト（デモ用の report-system_onion など）には、差分だけを上げる。
DB・暗号の鍵・アカウントはそのまま残る。上げてある版のコミットを --base に指定する。

  python tools/deploy/build_diff_package.py --base <上げてある版> --site <サーバーのフォルダー名>

できた tools/deploy/output/diff_<日時>_<base>_<ref>/ に、追加・変更したファイルだけの <site>/ と、
差分公開範囲.txt（上げるもの・消すもの・触らないもの・migrate.php の要否）と 反映手順.txt ができる。

■ Web から見える範囲
見えるのは、上の画面の入り口（.php）と css/・js/ だけ。

許すものだけを書く形にしている（.htaccess の mod_rewrite）:
  - 置かれているファイルのうち、拡張子が .php・.css・.js（小文字）のものだけを送る。
    それ以外のファイルは、置かれていても 403（拒否）にする。大文字の .PHP なども 403。
  - フォルダー（index.php への切り替え）と、無いもの（404）はそのまま。
  - .well-known/ はサーバーが置くもの（証明書の更新など）なので除く。

見えないもの（.htaccess で拒否する）:
  - 上の 3 つの拡張子のほかのファイルすべて（DB・鍵・控え・圧縮ファイル・事務の文書・拡張子のないファイルなど）
  - app/ の中すべて（app/.htaccess と ~/www/report-system/.htaccess の二重）
  - 置かれていても 404 にするフォルダー:
      app  docs  tools  public  __pycache__  node_modules  vendor
      data  keys  backup(s)  log(s)  config  lib  include(s)  src  db  database  storage  tmp  private
  - 名前が「.」で始まるファイル・フォルダー（.git など）
  - _boot.php

二重の守り（mod_rewrite が効かないときも拒否する拡張子。大文字・小文字を区別しない）:
  sqlite sqlite3 sqlite-wal sqlite-shm sqlite-journal db db-journal db3 key pem crt cer p12 pfx ppk
  inc phps phtml php3〜php8 old save tmp swo conf cfg toml xls xlsx doc docx pdf
  bak backup log md sql json ini sh py pyc pyo txt csv tsv yml yaml xml dist example orig swp lock env
  圧縮ファイル（形式を問わない）: zip tar gz tgz 7z br zst zstd deflate zz bz2 tbz tbz2 xz txz lzma lz lz4 rar z
  （事前に圧縮した .css.br・.js.gz なども配信しない）、名前が ~ で終わるもの（エディターの控え）

反映のあとに確かめること（.htaccess を変えたとき。手元の検証は .htaccess を読まないため、サーバーで確かめる）:
  1. ログインの画面・ホーム・css/app.css・js/app.js が開く。フォルダーだけの URL（/report-system/）でログインの画面になる。
  2. health.php が開く（200）。
  3. 試しのファイルを ~/www/report-system/ に置いて開き、どれも 403 になることを確かめてから消す:
       check.txt  check.css.br  check.PHP  check  check.php~  check.xlsx
     （中身は空でよい。確かめたら必ず消す）

■ 本番に置かないもの
  - docs/、tools/（設計書と開発の道具）
  - app/config/config.local.php と config.local.example.php（ローカル検証専用）
  - 旧システム（レポート管理システム）の public/・data/ など
  - この 公開範囲.txt と 反映手順.txt

■ 上げたあとの確認
  python tools/deploy/check_prod.py https://toyama-mai.sakura.ne.jp/report-system
  画面を見るだけの確認（ログイン・データの変更はしない）。全件 OK になること。
  .htaccess を変えたときも必ず流す（www の中に app/ を置くので、.htaccess の誤りがそのまま漏えいになる）。

■ 初めて置くとき（DB と鍵がまだ無いとき）
サーバーでコマンドを実行して作る（Web からは作れない）。
  php app/bin/migrate.php                                         DB と暗号化の鍵を作る
  php app/bin/create_user.php --login=<ID> --name=<名前> --admin  最初の管理者を作る（仮パスワードを 1 回だけ表示）
開発用の DB・鍵・アカウント（dev_seed.php で作ったもの）は本番に持ち込まない。

詳しくは docs/system_architecture.md の「2. サーバーの中の配置」。
