月次報告システム 本番更新の操作指示書（課長向け）
作成: 2026-11-16　対象: さくらのレンタルサーバー https://toyama-mai.sakura.ne.jp/report-system/
使う一式: 20261116_112507_bff12bc（開発担当から受け取るフォルダー）

すでに公開済みの本番を、新しい版に入れ替える手順です（2 回目以降の更新）。
この順に進めてください。各手順の □ に印を付けながら進め、終わったら「7. 開発担当への連絡」の内容を返してください。
わからないところ、書いてあるとおりにならないところがあれば、そこで止めて開発担当に連絡してください。
所要時間の目安: 20〜30 分（そのうち、利用者が保存できない時間は 10 分ほど）

0. 【大事】やってはいけないこと
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  - ~/www/report-system/ の中身を「すべて消す」こと（初回の公開のときの手順 2 は、今回は行いません）
      app/data（DB）と app/keys（暗号の鍵）が消え、これまでの報告が読めなくなります
  - app/data・app/keys・app/logs・app/backups を消す・上書きすること
  - 初期設定のコマンド（migrate.php・seed_template.php・create_user.php）をもう一度実行すること
      今回は DB の作りに変更がないので、不要です
  - 開発用の DB・鍵・config.local.php をサーバーに置くこと


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 今回の版で変わること（利用者への案内用）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  直したもの
  - メニューを開いたとき、管理者・課長などで一番下の「ログアウト」が見切れていた
  - 組織・ユーザーで、課の並び順に範囲外の値（999999 を超える・負の数）を入れると、エラーにならず 0 で保存されていた
  - メッセージ（文言の変更）で変えても、アカウント設定の色の注意文など、一部の文言が画面で変わらなかった
  - 臨時の調査の「この調査は締め切られました。」の知らせが、メッセージで変えても変わらなかった
  変わったもの・増えたもの
  - 2 段階認証の設定画面に、スマートフォンに認証アプリを入れる案内と、使える認証アプリの一覧を出す
    （PC で開いたときは、スマートフォンで設定するよう案内する）
  - 管理者が仮のパスワードを発行した画面に、本人への伝え方の案内を出す
  - ログインに失敗したとき、存在しない ID でも、入れた ID を記録に残す
  - 画面のテーマに「夜桜1」「夜桜2」「若葉2」「見分けやすい色（カラーユニバーサルデザイン）」を追加。「若葉」の見た目を改善
    （アカウント設定 →「表示」で選ぶ。見分けやすい色は、色が見分けにくい人向けの配色と印）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 事前の準備
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 開発担当から一式（フォルダー 20261116_112507_bff12bc）を受け取る。中身は次の 3 つ
     report-system/       ← これを上げる
     report-system.zip    ← 上と同じもの（サーバーで zip を展開できるときに使う）
     反映手順.txt         ← 上げない
□ ファイルを上げる道具で「.」で始まるファイル（.htaccess）が見えるようにする
   - FileZilla の場合: メニュー「サーバー」→「隠しファイルを強制表示」
   - コントロールパネルのファイルマネージャーの場合: 隠しファイルを表示する設定を有効にする
□ 利用者に、作業の日時を知らせておく（作業中の 10 分ほどは保存できない）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. DB のバックアップを取る
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 管理者でログインし、メニュー →「管理のトップ」の「最後のバックアップ」を見る
□ SSH でつなぎ、次を 1 行ずつ実行して、いまの DB のバックアップを作る
     cd ~/www/report-system
     php app/bin/backup.php
□ 管理のトップを開き直し、「最後のバックアップ」の日時が今の時刻になったことを確かめる
   ※ SSH が使えないときは、ここで止めて開発担当に連絡する


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. メンテナンス中にして、入れ替える
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 管理のトップの「メンテナンス」で、終わる日時（今から 1 時間後で十分）と一言（例: 新しい版に入れ替えています）を入れ、
   「メンテナンス中にする」を押す
   （管理者・補佐以外の人は、終わるまで保存などの操作ができなくなる。終わる日時を過ぎると自動で終わる）
□ 一式の report-system フォルダーの「中身」を、サーバーの ~/www/report-system/ に上書きで上げる
   - 「同じ名前のファイルがあります」と聞かれたら「上書き」を選ぶ
   - ~/www/report-system/report-system/ にならないよう注意（~/www/report-system/login.php が新しくなれば正しい）
□ 次の 2 つのファイルがサーバーにあることを、必ず目で確かめる
     ~/www/report-system/.htaccess
     ~/www/report-system/app/.htaccess
   ※ この 2 つが無いと、設定や DB が Web から見えてしまいます
□ 次のものが残っていないことを確かめる。あれば消す
     ~/www/report-system/docs/　tools/　public/　data/（app/data ではない、直下の data）
     ~/www/report-system/app/config/config.local.php
   ※ app/data・app/keys・app/logs・app/backups は消さない

5. 動きを確かめて、メンテナンスを終える
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
ブラウザーで本番を開き直す（Ctrl + F5 で読み直す。古い画面が残っていることがあるため）。

□ ログインできる（パスワードと 2 段階認証）
□ メニューを開き、一番下の「ログアウト」まで見える（スクロールして届く）
□ アカウント設定 →「表示」に「夜桜1」「夜桜2」「若葉2」「見分けやすい色（カラーユニバーサルデザイン）」が並んでいる
□ ホーム・提出状況・報告の詳細が、エラーなく開ける
□ 管理のトップの「メンテナンスを終える」を押す
□ 管理者以外の人（課長代理など）で、保存ができることを確かめる（できれば）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. 報告のあった不具合が直ったかを確かめる
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
メッセージ（文言の変更）の不具合を報告した人に、次を確かめてもらってください。

□ メッセージの画面で「背景の色と文字の色が近く、読みにくくなります」を変えて保存する
□ アカウント設定 →「表示」の「自分の色」の欄で、「明るい土台（白い面・黒い文字）」を選び、「背景の色」を黒に近い濃い色にする
   （保存しなくてよい。色を選んだその場で、欄の下に注意文が出る）
□ 注意文が、変えた文言になっていることを確かめる
□ 確かめ終わったら、メッセージの画面で「既定に戻す」を押す（必要なら）

7. 開発担当への連絡
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
終わったら、次を開発担当に伝えてください。開発担当が外から確認します（画面を見るだけで、データは変えません）。

  - 手順 2〜6 のうち、終わったもの・できなかったもの
  - 上げた一式のフォルダー名（20261116_112507_bff12bc）
  - 3. のバックアップの日時
  - 手順の途中で出たエラーの表示（あれば、そのまま写す）
  - 6. の結果（報告者が確かめられたか）

※ ログイン ID・パスワード・予備のコード・暗号化の鍵は、開発担当にも送らないでください。

開発担当の確認:
  python tools/deploy/check_prod.py https://toyama-mai.sakura.ne.jp/report-system
  → 全件 OK で更新完了
