使う一式: 20261116_170100_a8315dc（開発担当から受け取るフォルダー）

すでに公開済みの本番を、新しい版に入れ替える手順です（2 回目以降の更新）。
この順に進めてください。各手順の □ に印を付けながら進め、終わったら「8. 開発担当への連絡」の内容を返してください。

0. 【大事】やってはいけないこと
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  - ~/www/report-system/ の中身を「すべて消す」こと（初回の公開のときの手順 2 は、今回は行いません）
      app/data（DB）と app/keys（暗号の鍵）が消え、これまでの報告が読めなくなります
  - app/data・app/keys・app/logs・app/backups を消す・上書きすること
  - 初期設定のコマンド（migrate.php・seed_template.php・create_user.php）をもう一度実行すること
      今回は DB に表と列が増えますが、画面を開いたときに自動で足されるので、コマンドは不要です
  - 開発用の DB・鍵・config.local.php をサーバーに置くこと

1. 今回の版で変わること（利用者への案内用）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  【増えたもの】よくある質問のチャット
  - 「よくある質問」の画面で、チャットのように質問できる（AI は使っていません。用意した答えから探します）
  - 何を聞けばよいか分からないときは、分野のボタンから選べる。答えが無いときは、そのまま要望・依頼（質問）に出せる
  - システムに関係のない質問・不適切な表現には答えない
  - 体調の急変・事故など、命や体に関わる文には、119 番と相談先を案内する
  - 心の不調・退職・個人的な事情に触れる文には、寄り添う返事をし、上司・管理者への相談を勧める
  【増えたもの】管理者・補佐向け
  - 管理のトップに「よくある質問の記録」。だれが何を聞き、どう答えたかを見て、答えを直すのに使う
  - 次のときに、ホームと管理のトップに知らせが出る
      ・心の不調らしい文・退職に関わる質問（システム管理者だけ）
      ・ほかの人の ID・パスワードを求める質問（システム管理者と補佐）
      ・存在しない ID でログインしようとした記録（システム管理者と補佐）
  - 要配慮の個人情報・命に関わる文は、記録はするが、管理者にも画面には出さない
  【直したもの・変わったもの】
  - 通信が切れた・ログインの期限が切れたとき、チャットに分かる言葉で知らせる
  - 「課代」の表記を「課長代理」にそろえた
  （午前の版を反映していない場合は、午前の版の直しも入ります: メニューの「ログアウト」の見切れ、
    2 段階認証の設定の案内、画面のテーマの追加（夜桜1・夜桜2・若葉2・見分けやすい色）、メッセージの文言の不具合など）

□ 開発担当から一式（フォルダー 20261116_170100_a8315dc）を受け取る。中身は次の 3 つ
     report-system/       ← これを上げる
     report-system.zip    ← 上と同じもの（サーバーで zip を展開できるときに使う）

   ※ SSH が使えないときは、ここで止めて開発担当に連絡する
   ※ 今回は DB に表と列が増えるので、バックアップは必ず取ってください

4. メンテナンス中にして、入れ替える
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
□ 管理のトップの「メンテナンス」で、終わる日時（今から 1 時間後で十分）と一言（例: 新しい版に入れ替えています）を入れ、
   「メンテナンス中にする」を押す
   （管理者・補佐以外の人は、終わるまで保存などの操作ができなくなる。終わる日時を過ぎると自動で終わる）
□ 一式の report-system フォルダーの「中身」を、サーバーの ~/www/report-system/ に上書きで上げる
   - 「同じ名前のファイルがあります」と聞かれたら「上書き」を選ぶ
   - ~/www/report-system/report-system/ にならないよう注意（~/www/report-system/login.php が新しくなれば正しい）
□ 次の 2 つのファイルがサーバーにあることを、必ず目で確かめる
     ~/www/report-system/.htaccess
     ~/www/report-system/app/.htaccess
   ※ この 2 つが無いと、設定や DB が Web から見えてしまいます
□ 次のものが残っていないことを確かめる。あれば消す
     ~/www/report-system/docs/　tools/　public/　data/（app/data ではない、直下の data）
     ~/www/report-system/app/config/config.local.php
   ※ app/data・app/keys・app/logs・app/backups は消さない

   （用意した 148 件の質問と答えが入ります。すでに同じ質問があれば、重ねて入れません）
□ チャットの欄に「パスワードを忘れた」と入れて送り、答えが出ることを確かめる
□ 分野のボタン（例: ログイン）を押し、質問の一覧が出ることを確かめる
□ 管理のトップの「よくある質問の記録」を開き、いま聞いた質問が記録されていることを確かめる
□ 管理のトップの「メンテナンスを終える」を押す

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  - 画面が真っ白・「500」などのエラーになる
      → メンテナンス中のまま、開発担当に連絡する（エラーの表示と、上げたファイルの一覧を伝える）
      → 3. のバックアップがあるので、データは戻せます。自分で DB を消したり置き換えたりはしないでください
  - 画面の見た目が古いまま・チャットが動かない
      → Ctrl + F5 で読み直す。それでも古いときは、js/app.js と css/app.css が上書きされたか確かめる
  - 「標準のよくある質問を取り込む」のボタンが無い
      → 管理者か補佐でログインしているか確かめる（課長・課長代理などには出ません）
      → すでに全件取り込んであるときは、ボタンは出ません（「すべての質問」の件数が 148 件以上なら取り込み済み）
  - 上げたあと .htaccess が見当たらない
      → 隠しファイルを表示する設定を確かめ、一式の report-system/.htaccess と report-system/app/.htaccess を上げ直す
  - メンテナンスを終え忘れた
      → 終わる日時を過ぎると自動で終わる。急ぐときは管理のトップで「メンテナンスを終える」を押す
